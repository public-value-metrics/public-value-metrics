# திறந்த தரவின் மதிப்பு

திறந்த தரவின் மதிப்பு என்பது, அரசு மற்றும் பொதுத் தரவுக்கு விலை இல்லாதபோது அது எவ்வளவு மதிப்புடையது என மதிப்பிடும் சிக்கல்: அது விற்கப்படுவதில்லை, எனவே வருவாய் வரி எதுவும் இல்லை; ஆயினும் அதை வெளியிடுவது (வானிலைப் பதிவுகள், போக்குவரத்து நேரசூசிகள், அஞ்சல் குறியீட்டு எல்லைகள், நிறுவனப் பதிவேடுகள்) கீழ்நிலையில் பொருளாதார மற்றும் சமூகச் செயல்பாட்டை உருவாக்குவது நிரூபிக்கத்தக்கது. இதை நன்றாக மதிப்பிடுவது முக்கியம்; ஏனெனில் "வெளியிடுவது இலவசம்" என்பதும் "அது மதிப்பற்றது" என்பதும் இரண்டுமே தவறு, ஒரு API-யையோ தரவுத்தொகுப்பையோ திறக்கலாமா என்று தீர்மானிக்கும் மென்பொருள் பொறியாளருக்கு இரண்டையும்விடச் சிறந்த வாதம் தேவை.

## ஏன் இது முக்கியம்

மிக அதிகமாக மேற்கோள் காட்டப்படும் மேலிருந்து-கீழ் மதிப்பீடு McKinsey Global Institute-இன் 2013 அறிக்கையான "Open data: Unlocking innovation and performance with liquid information" என்பதிலிருந்து வருகிறது; கல்வி, போக்குவரத்து, நுகர்வோர் பொருட்கள், மின்சாரம், எண்ணெய் மற்றும் எரிவாயு, சுகாதாரம், நுகர்வோர் நிதி ஆகிய ஏழு துறைகளில் திறந்த தரவின் ஆண்டுச் சாத்தியமான மதிப்பை உலகளவில் ஆண்டுக்கு $3 டிரில்லியன் முதல் $5 டிரில்லியன் வரை என அது மதிப்பிட்டது; அதிகரித்த வெளிப்படைத்தன்மை, வழங்கலையும் தேவையையும் மிகத் திறமையாகப் பொருத்துதல், தரவின் மீது கட்டமைக்கப்படும் புதிய பொருட்களையும் சேவைகளையும் சாத்தியமாக்குதல் ஆகிய வழிமுறைகள் மூலம் இது நிகழும் என்றது. அந்த எண் ஒரு காட்சி மதிப்பீடு, அளவிடப்பட்ட விளைவு அல்ல; அரசாங்கம் நேரடியாகப் பெறக்கூடிய வருவாய் போலத் தவறாக மேற்கோள் காட்டப்படுவது வழக்கம்; உண்மையில் மதிப்பின் பெரும்பகுதி தரவைப் பயன்படுத்தும் மூன்றாம் தரப்பினருக்கு — வணிகங்கள், ஆய்வாளர்கள், குடிமக்கள் — சேர்கிறது; விற்பதற்குப் பதிலாகத் திறப்பதன் நோக்கமே அதுதான். 2012-இல் Sir Tim Berners-Lee மற்றும் Sir Nigel Shadbolt இணைந்து நிறுவிய ஐக்கிய இராச்சியத்தின் Open Data Institute, அதன்பின் துறைவாரியாக, தரவுத்தொகுப்புவாரியாக மிகவும் நுணுக்கமான கீழிருந்து-மேல் வழக்காய்வுகளின் தொகுப்பை உருவாக்கியுள்ளது; இவை மதிப்பு உருவாக்கத்தின் வழிமுறையைக் காட்டுவதால், McKinsey தலைப்பு எண்ணைவிட உண்மையான வணிக வழக்குக்கு மிகவும் பயனுள்ளவை.

## கணிதம்

திறந்த தரவுக்கு சந்தை விலை இல்லாததால், மதிப்பீட்டு முறைகள் அதற்கு மாற்றாகின்றன; மூன்று அணுகுமுறைகள் மீண்டும் மீண்டும் வருகின்றன, எதுவும் தனியாகப் போதுமானதல்ல:

```
1. Cost-avoided / replacement-cost method:
   value ≈ what users would have paid to produce or licence the
   equivalent data themselves — a lower bound, ignores value created
   by uses the original producer never anticipated

2. Market-analogue / downstream-activity method:
   value ≈ revenue or savings generated by businesses/services built
   on the data (e.g. satnav apps built on open mapping and traffic
   data) — captures real economic activity but is hard to attribute
   cleanly to the data release itself (see additionality-and-deadweight)

3. Contingent/stated-preference method:
   value ≈ what users say they would pay, or the time they say it
   saves them — see stated-preference-valuation for the general
   method and its biases

None of these produces a figure as clean as a market price; credible
open data business cases triangulate across two or more, and are
explicit about which mechanism is doing the work.
```

## செயல்முறை எடுத்துக்காட்டு

**எடுத்துக்காட்டுக்கான தேசிய வரைபடம்/முகவரித் தரவு வெளியீடு** (ODI பாணி வழக்காய்வுகளின் வழிமுறைப்படி; எண்கள் இத்தகைய ஆய்வுகள் பொதுவாகக் காணும் அளவைக் குறிக்கும் எடுத்துக்காட்டுகள்):

```
Cost-avoided estimate:
  Businesses that would otherwise licence equivalent address-matching
  data commercially, at an estimated average licence cost of £4,000/
  year, across an estimated 15,000 SMEs now using the free open dataset
  = 15,000 × £4,000 = £60,000,000/year in avoided licensing cost alone

Downstream-activity estimate (more speculative, needs a counterfactual):
  New delivery-routing and logistics products built on the open data
  that would not exist, or would be materially worse, without it —
  requires a comparison against the counterfactual of the data staying
  closed or commercially licensed (counterfactual-analysis), because
  some of that activity would happen anyway on paid data at a higher
  price, which is deadweight in the "value created by opening it" sense

A defensible business case reports the cost-avoided figure as the
solid lower bound, and treats the downstream-activity figure as an
upper-bound scenario, not a fact.
```

## மென்பொருள் பொறியியல் தொடர்பு

பொறியாளர்களுக்கு, நடைமுறையில் திறந்த தரவு மதிப்புக் கேள்வி பொதுவாக தேசிய தலைப்பு எண்களைவிடக் குறுகியது: இந்த குறிப்பிட்ட API-யையோ தரவுத்தொகுப்பையோ (கூட்டாளர் ஒப்பந்தத்துக்குப் பின்னால் வைத்திருப்பதற்குப் பதிலாக) திறப்பது, அதைப் பொது இடைமுகமாக ஆவணப்படுத்தி, பதிப்புப்படுத்தி, ஆதரிப்பதற்கான தொடர் செலவை நியாயப்படுத்தும் அளவுக்கு மறுபயன்பாட்டை அதிகரிக்குமா? அந்தப் பராமரிப்புச் செலவு உண்மையானது; அது [தளமாக அரசாங்கம்](../தளமாக-அரசு/) என்பதன் ஒருமுறை உருவாக்கி அடிக்கடி மறுபயன்படுத்தும் பொருளாதாரத்துக்கு இணையானது — இரு தலைப்புகளும் நெருங்கிய உறவினர்கள்; ஒன்று பகிரப்பட்ட நிரல் மற்றும் உள்கட்டமைப்பைப் பற்றியது, மற்றொன்று பகிரப்பட்ட தரவைப் பற்றியது. எந்தவொரு திறந்த தரவு மதிப்புக் கூற்றும் வணிக வழக்கில் சேர்வதற்கு முன் [additionality-and-deadweight](../கூடுதல்-பங்களிப்பும்-இறந்தசுமையும்/) என்பதற்கு எதிராகச் சரிபார்க்கப்பட வேண்டும்: வணிக உரிமம் பெற்ற தரவிலேயே எப்படியும் நடந்திருக்கக்கூடிய செயல்பாடு, *திறந்ததால்* உருவான மதிப்பு அல்ல.

## பொதுவான தவறுகள்

- **McKinsey-யின் $3–5 டிரில்லியன் எண்ணை ஐக்கிய இராச்சியத்துக்கே உரியதாக அல்லது இந்தத் தரவுத்தொகுப்பின் பங்காக மேற்கோள் காட்டுதல்**: இது 2013-இலிருந்து உலகளாவிய, ஏழு துறை காட்சி மதிப்பீடு — அதை ஒரு தனி தேசியத் தரவுத்தொகுப்புக்கான துல்லியமான பெருக்கியாகப் பயன்படுத்துவது அந்த எண் என்ன என்பதைத் தவறாகச் சித்தரிக்கிறது.
- **மாற்று நிலை இல்லாமை**: திறந்த தரவின் மீது கட்டப்பட்ட அனைத்துக் கீழ்நிலைப் பொருளாதாரச் செயல்பாட்டுக்கும் உரிமை கோருவது; அதில் எவ்வளவு, கட்டணத் தரவிலோ உரிமம் பெற்ற தரவிலோ அதிக விலையில் எப்படியும் நடந்திருக்கும் என்று கேட்காமல் (பார்க்க [additionality-and-deadweight](../கூடுதல்-பங்களிப்பும்-இறந்தசுமையும்/) மற்றும் [counterfactual-analysis](../மாற்றுநிலைப்-பகுப்பாய்வு/)).
- **உற்பத்திச் செலவையும் உருவான மதிப்பையும் குழப்புதல்**: சேகரிக்கச் செலவான தரவுத்தொகுப்பு வெளியிடுவதற்கு தானாக மதிப்புடையது அல்ல, மலிவானது தானாகக் குறைந்த மதிப்புடையதும் அல்ல — மதிப்பு கீழ்நிலைப் பயன்பாட்டைப் பின்பற்றுகிறது, மேல்நிலைச் செலவை அல்ல.
- **"திறந்த" நிலையின் தொடர் பராமரிப்புச் செலவைப் புறக்கணித்தல்**: ஒருமுறை CSV பிரித்தெடுப்பை வெளியிடுவது, ஆவணப்படுத்தப்பட்ட, பதிப்புப்படுத்தப்பட்ட, ஆதரிக்கப்படும் திறந்த API-யை இயக்குவதற்கு இணையான பொறுப்பு அல்ல — அறிமுக அறிவிப்புக்குப் பிறகு பிந்தையதற்கு நிதி குறைவாக ஒதுக்குவது ஒரு பொதுவான தோல்வி முறை.
