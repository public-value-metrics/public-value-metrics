# ថ្លៃចំណាយក្នុងមួយលទ្ធផល

ថ្លៃចំណាយក្នុងមួយលទ្ធផល (cost per outcome) គឺជាការចំណាយកម្មវិធីសរុបចែកនឹងចំនួនមនុស្សដែលសម្រេចបានការផ្លាស់ប្តូរមានអត្ថន័យដែលបានកំណត់ក្នុងស្ថានភាពរបស់ពួកគេ មិនមែនចំនួនអ្នកដែលគ្រាន់តែទទួលបានសេវាទេ។ វាជារង្វាស់ប្រសិទ្ធភាពមុតស្រួចបំផុតដែលម្ចាស់មូលនិធិ ឬក្រុមអនុវត្តអាចប្រើ ព្រោះវាបង្ខំសំណួរមុនដែលអង្គការសប្បុរសធម៌ភាគច្រើនគេចវាង៖ តើអ្វីជាអ្វីដែលរាប់ជាជោគជ័យយ៉ាងជាក់លាក់?

## ហេតុអ្វីបានជាសំខាន់

ធនាគារអាហារអាចរាយការណ៍លេខពីរខុសគ្នាខ្លាំងពីគណនីឆ្នាំដូចគ្នា។ ថ្លៃចំណាយក្នុងមួយកញ្ចប់អាហារដែលបានចែកអាចជា £15។ ថ្លៃចំណាយក្នុងមួយគ្រួសារដែលបន្តសម្រេចសន្តិសុខស្បៀង ដែលលែងត្រូវការជំនួយអាហារបន្ទាន់ ផ្ទៀងផ្ទាត់នៅចំណុចតាមដាន អាចជា £340។ ទាំងពីរពិត។ មានតែមួយប៉ុណ្ណោះដែលប្រាប់ម្ចាស់មូលនិធិថាប្រាក់កំពុងដំណើរការ។ គម្លាតរវាងពួកវាគឺជាគម្លាតរវាងផលិតកម្ម និងលទ្ធផល៖ កញ្ចប់ដែលបានប្រគល់គឺជាផលិតកម្ម គ្រួសារដែលលែងស្ថិតក្នុងវិបត្តិគឺជាលទ្ធផល។ សូមមើល [លទ្ធផល ធៀបនឹងផលិតកម្ម](../លទ្ធផល-ធៀបនឹង-ទិន្នផល/)។

វិស័យទីបីរបស់ចក្រភពអង់គ្លេសបានចំណាយពីរទសវត្សកសាងហេដ្ឋារចនាសម្ព័ន្ធដើម្បីបង្ខំភាពខុសគ្នានេះ។ "four pillar approach" របស់ New Philanthropy Capital ចំពោះប្រសិទ្ធភាពអង្គការសប្បុរសធម៌ សុំយ៉ាងច្បាស់ឱ្យអង្គការបញ្ជាក់លទ្ធផលរបស់ខ្លួនមុនផលិតកម្ម ហើយ Inspiring Impact ដែលជាកិច្ចសហការវាស់ផលប៉ះពាល់ដែលគាំទ្រដោយម្ចាស់មូលនិធិរបស់ចក្រភពអង់គ្លេស បោះពុម្ព Outcomes Matrix ដែលពាក្យសុំជំនួយឧបត្ថម្ភជាច្រើនឥឡូវតម្រូវឱ្យអង្គការសប្បុរសធម៌បំពេញ។ កម្មវិធីស្រាវជ្រាវ "State of Hunger" ប្រចាំឆ្នាំរបស់ Trussell Trust ដែលដំណើរការជាមួយ Heriot-Watt University មានយ៉ាងជាក់លាក់ ព្រោះការរាប់កញ្ចប់តែមួយមិនប្រាប់អ្វីអំពីថាតើមនុស្សគេចផុតពីភាពអសន្តិសុខស្បៀងឬអត់។

ថ្លៃចំណាយក្នុងមួយលទ្ធផលមានន័យតែនៅពេលអ្នកបានកំណត់ counterfactual៖ លទ្ធផលដែលសម្រេចបាន «ដដែល» មិនមែនជាលទ្ធផលដែលកម្មវិធីបានទិញទេ។ សូមមើល [ការវិភាគ counterfactual](../ការវិភាគ-counterfactual/) និង [ការជំនួស និងការសន្មតមូលហេតុ](../ការបំលាស់ទី-និងការសន្មតផល/)។

## គណិតវិទ្យា

```
Cost per outcome = Total programme cost / Number of beneficiaries achieving the defined outcome

where:
  Total programme cost   = direct delivery cost + fair share of overhead
  Defined outcome        = a pre-specified, measurable state change
                            (e.g. "food secure at 6-month follow-up",
                            not "received a food parcel")
```

ប្រៀបធៀបជាមួយ [មូលដ្ឋានទិន្នន័យថ្លៃចំណាយឯកតា](../មូលដ្ឋានទិន្នន័យថ្លៃចំណាយឯកតា/) (ឧទាហរណ៍ លក្ខខណ្ឌយោងថ្លៃចំណាយឯកតាតាមវិស័យជាក់លាក់) ដើម្បីវិនិច្ឆ័យថាតើថ្លៃចំណាយក្នុងមួយលទ្ធផលណាមួយល្អ មធ្យម ឬអន់ ធៀបនឹងអន្តរាគមន៍ដែលអាចប្រៀបធៀបបាន។

## ឧទាហរណ៍គណនា

**ធនាគារអាហារ មួយឆ្នាំ**៖

- ថ្លៃចំណាយកម្មវិធីសរុប៖ £450,000
- កញ្ចប់ដែលបានចែក៖ 30,000
- ថ្លៃចំណាយក្នុងមួយកញ្ចប់ (រង្វាស់ផលិតកម្ម)៖ £450,000 / 30,000 = **£15**

អង្គការសប្បុរសធម៌ក៏ធ្វើការស្ទង់មតិតាមដានប្រាំមួយខែជាមួយគំរូគ្រួសារ ដោយរកឃើញថា 35% នៃគ្រួសារដែលទទួលបានបីកញ្ចប់ ឬច្រើនជាងនេះរាយការណ៍ថាលែងត្រូវការជំនួយអាហារបន្ទាន់ ហើយទទួលបានពិន្ទុលើសកម្រិតសន្តិសុខស្បៀងលើម៉ូឌុលស្ទង់មតិសន្តិសុខស្បៀងស្តង់ដារ។ ក្នុងចំណោមគ្រួសារ 1,800 ដែលទទួលបានបីកញ្ចប់ឬច្រើនជាងនេះក្នុងឆ្នាំនោះ 630 សម្រេចលទ្ធផលនោះ។

```
Cost per outcome = £450,000 / 630 = £714 per household achieving food security
```

តួលេខ £714 នោះគឺជាតួលេខដែលម្ចាស់មូលនិធិប្រៀបធៀបអង្គការសប្បុរសធម៌នេះជាមួយគម្រោងសាកល្បងផ្ទេរសាច់ប្រាក់ ឬសេវាប្រឹក្សាបំណុលគួរប្រើ មិនមែន £15 ទេ។ ប្រសិនបើកម្មវិធីផ្ទេរសាច់ប្រាក់ដែលអាចប្រៀបធៀបបាននៅក្នុងតំបន់ដូចគ្នាសម្រេចសន្តិសុខស្បៀងក្នុងតម្លៃ £500 ក្នុងមួយគ្រួសារ ធនាគារអាហារមិនមែនជាផ្លូវមានប្រសិទ្ធភាពជាងយ៉ាងច្បាស់ទៅរកលទ្ធផលដូចគ្នាទេ ទោះបីថ្លៃចំណាយក្នុងមួយកញ្ចប់មើលទៅថោកក៏ដោយ។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

ប្រព័ន្ធគ្រប់គ្រងករណីភាគច្រើនត្រូវបានសាងសង់ដើម្បីកត់ត្រាផលិតកម្ម ព្រោះផលិតកម្មគឺជាអ្វីដែលកើតឡើងក្នុងប្រតិបត្តិការ (កញ្ចប់ត្រូវបានប្រគល់ ទម្រង់ត្រូវបានដាក់ស្នើ)។ លទ្ធផលជាធម្មតាកើតឡើងក្រោយ ច្រើនតែនៅក្រៅបង្អួចចាប់យកធម្មតារបស់ប្រព័ន្ធ ហើយតម្រូវឱ្យមានការសម្រេចចិត្តរចនាដោយចេតនា៖ កសាងយន្តការតាមដាន (ការជំរុញការស្ទង់មតិ ដំណើរការទាក់ទងឡើងវិញ លំហាត់តភ្ជាប់ទិន្នន័យ) ជាមុខងារថ្នាក់ទីមួយ មិនមែនបន្ថែមក្រោយសម្រាប់របាយការណ៍ប្រចាំឆ្នាំទេ។ វិស្វករដែលកសាងវេទិកាគ្រប់គ្រងជំនួយឧបត្ថម្ភ ឬគ្រប់គ្រងករណីសម្រាប់វិស័យនេះ គួរចាត់ទុក «តើអ្វីជាព្រឹត្តិការណ៍លទ្ធផល និងយើងសង្កេតវាយ៉ាងដូចម្តេច» ជាសំណួរតម្រូវការដែលសួរមុនម៉ូដែលទិន្នន័យត្រូវបានកំណត់ ព្រោះវាពិបាកជាងឆ្ងាយក្នុងការបន្ថែមវាលលទ្ធផលក្រោយ ជាងបន្ថែមបញ្ជរផលិតកម្ម។ សូមមើល [លទ្ធផល ធៀបនឹងផលិតកម្ម](../លទ្ធផល-ធៀបនឹង-ទិន្នផល/) និង [គំរូតក្កវិជ្ជា](../គំរូតក្កវិជ្ជានៃកម្មវិធី/) សម្រាប់របៀបរៀបចំការសន្ទនាតម្រូវការនោះ និង [ថ្លៃចំណាយក្នុងមួយអ្នកទទួលផល](../ថ្លៃចំណាយក្នុងមួយអ្នកទទួលផល/) សម្រាប់រង្វាស់លឿន និងឆៅជាងដែលក្រុមប្រើនៅពេលការតាមដានលទ្ធផលមិនទាន់ត្រូវបានសាងសង់។

## កំហុសដែលតែងកើតមាន

- **ការរាយការណ៍ផលិតកម្មដែលតុបតែងជាលទ្ធផល។** «មនុស្សដែលបានទៅដល់» មិនមែន «មនុស្សដែលបានជួយ» ទេ។ ប្រសិនបើរង្វាស់អាចផលិតបានដោយកំណត់ហេតុប្រព័ន្ធដោយគ្មានការទាក់ទងតាមដាន វាស្ទើរតែប្រាកដជាផលិតកម្ម។
- **ការលេងល្បិចភាគបែង។** ការបង្រួមចំនួនប្រជាជនលទ្ធផលទៅ «អ្នកដែលបានបំពេញកម្មវិធី» ទម្លាក់អ្នកដែលបោះបង់ដោយស្ងាត់ស្ងៀម ដែលច្រើនតែជាករណីលំបាកបំផុត ហើយបំផ្លើសអត្រាច្បាស់ជាក់ស្តែង។ ត្រូវកំណត់ភាគបែងជាអ្នកទាំងអស់ដែលបានចាប់ផ្តើម មិនមែនអ្នកទាំងអស់ដែលបានបញ្ចប់។
- **គ្មាន counterfactual។** ការរាប់នរណាម្នាក់ដែលសម្រេចលទ្ធផល រួមទាំងអ្នកដែលនឹងសម្រេចដដែល បំផ្លើសអ្វីដែលកម្មវិធីបានទិញ។ សូមមើល [ការវិភាគ counterfactual](../ការវិភាគ-counterfactual/)។
- **ការប្រៀបធៀបឆ្លងនិយមន័យលទ្ធផលដែលមិនឆបគ្នា។** «សន្តិសុខស្បៀង» ដែលវាស់ដោយម៉ូឌុលស្ទង់មតិដែលបានផ្ទៀងផ្ទាត់ មិនអាចប្រៀបធៀបជាមួយ «សន្តិសុខស្បៀង» ដែលរាយការណ៍ដោយខ្លួនឯងក្នុងទម្រង់ការពេញចិត្តទេ ដូច្នេះតារាងចំណាត់ថ្នាក់ថ្លៃចំណាយក្នុងមួយលទ្ធផលស្មោះត្រង់តែនៅពេលនិយមន័យលទ្ធផលត្រូវគ្នា។
