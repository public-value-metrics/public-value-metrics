# រង្វាស់លំហូរក្នុងការចែកចាយរបស់រដ្ឋាភិបាល

រង្វាស់លំហូរ — ច្បាប់របស់ Little ដែនកំណត់ការងារកំពុងដំណើរការ (WIP) និងប្រសិទ្ធភាពលំហូរ — ពណ៌នាពីល្បឿនដែលការងារផ្លាស់ទីកាត់ប្រព័ន្ធដែលមានសមត្ថភាពកំណត់។ ក្តារ sprint គឺជាប្រព័ន្ធមួយបែបនេះ។ ជួរទាមទារអត្ថប្រយោជន៍ ចុះបញ្ជីពាក្យសុំអនុញ្ញាតសាងសង់ ឬការងារករណីទិដ្ឋាការដែលជាប់គាំង គឺជាគណិតវិទ្យាដូចគ្នាបេះបិទ ដែលស្លៀកឯកសណ្ឋានផ្សេង។

## ហេតុអ្វីបានជាសំខាន់

បន្ទុកករណីរបស់រដ្ឋាភិបាលគឺជាប្រព័ន្ធជួរ ហើយប្រព័ន្ធជួរគោរពតាមច្បាប់ជួរ ទោះមាននរណាវាស់ឬអត់ក៏ដោយ។ រយៈពេលសម្រេចតាមច្បាប់ធ្វើឱ្យរឿងនេះច្បាស់៖ ក្រោមរបបផែនការទីក្រុង និងជនបទ ពាក្យសុំអនុញ្ញាតសាងសង់តូចៗភាគច្រើនមានគោលដៅសម្រេចតាមច្បាប់ 8 សប្តាហ៍ ហើយពាក្យសុំធំៗ 13 សប្តាហ៍ — ការប្តេជ្ញាចិត្តរយៈពេលវដ្តដែលបញ្ចូលដោយផ្ទាល់ក្នុងច្បាប់។ ការងារពាក្យសុំសិទ្ធិសន្តិភាពដែលជាប់គាំងរបស់ Home Office ដែលត្រូវបានពិនិត្យឡើងវិញជាច្រើនដងដោយ National Audit Office និង Home Affairs Select Committee គឺជាករណីដែលមានឯកសារច្បាស់នៃប្រព័ន្ធសាធារណៈដែលការងារកំពុងដំណើរការ (WIP) កើនលឿនជាងកម្រិតឆ្លងកាត់ក្នុងរយៈពេលយូរ ដែលនាំឱ្យរយៈពេលវដ្តលើសឆ្ងាយពីការរំពឹងទុកតាមច្បាប់ ឬសេវាណាមួយ។ រង្វាស់លំហូរផ្តល់ដល់វិស្វករ និងអ្នកគ្រប់គ្រងការងារករណីនូវវាក្យសព្ទបរិមាណរួមមួយ សម្រាប់របៀបបរាជ័យនេះ ជាជាងទុកវាជា "បញ្ហាការងារជាប់គាំង" ជាគុណភាព។

## គណិតវិទ្យា

```
Little's Law:  WIP = Throughput × Cycle Time
           →   Cycle Time = WIP / Throughput

Flow efficiency = active (touch) time / total cycle time   (Vacanti)

WIP limit effect: for fixed throughput, halving WIP roughly halves
average cycle time (Little's Law rearranged) — the lever available
without adding headcount.
```

សូមមើល [រង្វាស់ DORA សម្រាប់តម្លៃសាធារណៈ](../រង្វាស់-dora-សម្រាប់តម្លៃសាធារណៈ/) សម្រាប់គណិតវិទ្យាដូចគ្នាដែលអនុវត្តលើបំពង់ដាក់ពង្រាយកម្មវិធី ជំនួសឱ្យការងារករណី។

## ឧទាហរណ៍គណនា

**នាយកដ្ឋានផែនការរបស់អាជ្ញាធរមូលដ្ឋាន**៖ ពាក្យសុំ 400 បើកនៅគ្រប់ពេល (WIP) ក្រុមការងារដោះស្រាយ 50 ពាក្យសុំ/សប្តាហ៍ (កម្រិតឆ្លងកាត់)។

```
Cycle time = WIP / Throughput = 400 / 50 = 8 weeks
```

នោះចុះចតត្រង់គោលដៅតាមច្បាប់ 8 សប្តាហ៍សម្រាប់ពាក្យសុំតូចៗ — ដោយគ្មានទំហំសម្រាក មានន័យថាភាពប្រែប្រួលណាមួយនៃតម្រូវការចូល ឬពេលឆ្លើយតបរបស់អ្នកពិគ្រោះយោបល់ ញុំាងការសម្រេចលើសពីកាលកំណត់ផ្លូវច្បាប់។

**ប្រសិទ្ធភាពលំហូរ**៖ ក្នុង 8 សប្តាហ៍នោះ (56 ថ្ងៃប្រតិទិន) ពាក្យសុំមួយជាធម្មតាមានពេលដំណើរការជាក់ស្តែងរបស់អ្នកគ្រប់គ្រងករណីប្រហែល 6 ម៉ោង។

```
Flow efficiency = 6 hours / (56 days × 8 working hours/day)
                = 6 / 448 ≈ 1.3%
```

ស្តង់ដាររបស់ Vacanti សម្រាប់ក្រុមកម្មវិធីដាក់ប្រសិទ្ធភាពលំហូរធម្មតាត្រឹម 15–20%។ ការងារករណីរបស់រដ្ឋាភិបាល ដែលមានការផ្ទេរបន្តជាច្រើនទៅអ្នកពិគ្រោះយោបល់តាមច្បាប់ និងបង្អួចពិគ្រោះយោបល់សាធារណៈ ច្រើនតែទាបជាងមួយលំដាប់ទំហំ។ 98.7% នៃពេលវេលា "រង់ចាំ" គឺជាកន្លែងដែលប្រាំបីសប្តាហ៍ទៅជាក់ស្តែង — មិនមែនក្នុងសមត្ថភាពអ្នកគ្រប់គ្រងករណីទេ។

**អន្តរាគមន៍ដែនកំណត់ WIP**៖ កំណត់ពាក្យសុំបើកក្នុងមួយអ្នកគ្រប់គ្រងករណីត្រឹម 15 ជំនួសឱ្យ 25 ដែលគ្មានដែនកំណត់ (រក្សាកម្រិតឆ្លងកាត់ថេរ) ប្តូរ WIP ពី 400 ទៅប្រហែល 240 ក្នុងក្រុម 16 នាក់៖

```
New cycle time = 240 / 50 = 4.8 weeks
```

រយៈពេលវដ្តថយចុះជិតពាក់កណ្តាលពីការផ្លាស់ប្តូរគោលនយោបាយ មិនមែនការបន្ថែមបុគ្គលិកទេ — ដងថ្លឹងដូចគ្នាដែលក្រុមចែកចាយបែប DORA ទាញនៅពេលកំណត់ WIP របស់ sprint។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

រង្វាស់លំហូរគឺជាភាសារួមរវាងក្តារ Kanban របស់ក្រុមចែកចាយ និងជាន់ការងារករណីដែលវាកំពុងសាងសង់កម្មវិធីសម្រាប់៖ ជួរនៃអ្នកគ្រប់គ្រងករណី និងជួរ pull-request ទាំងពីរត្រូវបានគ្រប់គ្រងដោយច្បាប់របស់ Little ហើយទាំងពីរបំបែកគោលដៅរយៈពេលវដ្តតាមរបៀបដូចគ្នា — WIP ច្រើនពេកធៀបនឹងកម្រិតឆ្លងកាត់។ នេះសំខាន់ដោយផ្ទាល់សម្រាប់ [តម្លៃនៃការពន្យារពេលក្នុងកម្មវិធីសាធារណៈ](../ថ្លៃចំណាយនៃការយឺតយ៉ាវក្នុងកម្មវិធីសាធារណៈ/)៖ រយៈពេលវដ្ត × CoD គឺជាផោនដែលអង្គុយក្នុងជួរនៅគ្រប់ពេល ហើយវាសំខាន់សម្រាប់ [ស្តង់ដារសេវា និងរង្វាស់ប្រតិបត្តិការ](../ស្តង់ដារសេវា-និងរង្វាស់ប្រតិបត្តិការ/) ដែលគោលដៅពេលដំណើរការដែលបានផ្សព្វផ្សាយគឺជាការប្តេជ្ញាចិត្តរយៈពេលវដ្ត ដែលមានតែរង្វាស់លំហូរទេដែលអាចរកមូលហេតុនៅពេលខកខាន។ កម្មវិធីរបស់ប្រព័ន្ធការងារករណីគួរបង្ហាញ WIP និងរយៈពេលវដ្តជារង្វាស់ប្រតិបត្តិការលំដាប់ទីមួយ មិនកប់វាក្នុងប្រព័ន្ធគ្រប់គ្រងករណីដែលគ្មាននរណាសួរទេ។

## កំហុសដែលតែងកើតមាន

- **បន្ថែមដែនកំណត់ WIP ដោយមិនដោះស្រាយកត្តាកកស្ទះពិត**៖ ប្រសិនបើឧបសគ្គគឺពេលឆ្លើយតបរបស់អ្នកពិគ្រោះយោបល់តាមច្បាប់ខាងក្រៅ ការកំណត់ WIP របស់អ្នកគ្រប់គ្រងករណីគ្រាន់តែប្តូរជួរទៅខាងលើ ជាជាងធ្វើឱ្យខ្លី។
- **ចាត់ទុកប្រសិទ្ធភាពលំហូរជាគោលដៅដែលអាចលេងល្បិច**៖ ការប្រញាប់ 1.3% នៃពេលសកម្មស្ទើរតែមិនផ្លាស់ប្តូររយៈពេលវដ្ត។ អំណាចទាញស្ទើរតែជានិច្ចនៅក្នុងស្ថានភាពរង់ចាំ ដែលជាធម្មតាមានន័យថារចនាដំណើរការឡើងវិញ មិនមែនល្បឿនអ្នកគ្រប់គ្រងករណីទេ។
- **មិនអើពើភាពប្រែប្រួល**៖ ច្បាប់របស់ Little ពណ៌នាមធ្យម។ បន្ទុកករណីដែលមានវ៉ារ្យង់តម្រូវការខ្ពស់ត្រូវការសមត្ថភាពបម្រុង មិនមែនគ្រាន់តែដែនកំណត់ WIP តឹងជាងទេ បើមិនដូច្នេះទេកាលកំណត់តាមច្បាប់នៅតែខកខាននៅកន្ទុយដែលប្រែប្រួល ទោះមធ្យមប្រសើរឡើងក៏ដោយ។
- **វាស់ WIP មិនស៊ីសង្វាក់គ្នា**៖ ករណីដែល "បើក" នៅក្នុងប្រព័ន្ធកំណត់ត្រា ប៉ុន្តែពិតជាជាប់គាំងរង់ចាំភាគីទីបី នៅតែជា WIP។ ការដកវាចេញលម្អៀងលេខ ដោយមិនផ្លាស់ប្តូរការពិតដែលពលរដ្ឋជួបប្រទះ។
