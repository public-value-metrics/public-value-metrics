# បំណុលបច្ចេកទេសជាការកាត់បន្ថយតម្លៃសាធារណៈ

បំណុលបច្ចេកទេស (technical debt) គឺជាពាក្យប្រៀបធៀបឆ្នាំ 1992 របស់ Ward Cunningham សម្រាប់ថ្លៃចំណាយអនាគតដែលបង្កប់ពីការសម្រេចចិត្តសរសេរកូដបែបបន្ទាន់នៅអតីតកាល៖ **ប្រាក់ដើម** (ការងារកែតម្រូវដែលជំពាក់) និង **ការប្រាក់** (ភាពអូសទាញដែលវាបង្កលើការបំពេញការងារ)។ នៅក្នុងប្រព័ន្ធ IT ចាស់របស់រដ្ឋាភិបាល ការប្រាក់នោះត្រូវបានបង់ដោយផ្ទាល់ពីតម្លៃសាធារណៈ គឺការបំពេញការផ្លាស់ប្តូរតាមច្បាប់យឺតជាងមុន អត្រាបរាជ័យខ្ពស់ជាងលើសេវាដែលប្រឈមមុខនឹងពលរដ្ឋ និងចំនួនមនុស្សដែលអាចប៉ះពាល់ប្រព័ន្ធដោយសុវត្ថិភាពកំពុងថយចុះ។

## ហេតុអ្វីបានជាសំខាន់

ប្រព័ន្ធ mainframe និងសម័យ COBOL ចាស់នៅទូទាំងក្រសួងរដ្ឋាភិបាលអង់គ្លេស ដែល HMRC និង DWP ត្រូវបានលើកឡើងច្រើនបំផុត មានហានិភ័យដែលមានឯកសារបញ្ជាក់ច្បាស់លាស់ និងកើនឡើង ដែលការិយាល័យសវនកម្មជាតិ (National Audit Office) បានចង្អុលបង្ហាញម្តងហើយម្តងទៀត រួមទាំងក្នុងរបាយការណ៍ *Digital Transformation in Government* (<https://www.nao.org.uk/>)៖ វេទិកាចាស់ៗដែលថ្លៃក្នុងការផ្លាស់ប្តូរ កាន់តែពិបាកការពារសុវត្ថិភាព និងពឹងផ្អែកលើកម្លាំងពលកម្មឯកទេសដែលចូលនិវត្តន៍លឿនជាងការជំនួស។ មិនដូចការងារដែលនៅជាប់ក្នុងវិស័យឯកជនទេ បំណុលនេះស្ថិតនៅរវាងពលរដ្ឋ និងសិទ្ធិតាមច្បាប់របស់ពួកគេដោយផ្ទាល់ គឺម៉ាស៊ីនគណនាអត្ថប្រយោជន៍ដែលមិនអាចផ្លាស់ប្តូរដោយសុវត្ថិភាពបាន គឺជាឧបសគ្គនៃការអនុវត្តគោលនយោបាយ មិនមែនគ្រាន់តែជាភាពមិនងាយស្រួលខាងវិស្វកម្មទេ។ ការចាប់ផ្តើមឡើងវិញនៃកម្មវិធី IT Universal Credit ក្នុងឆ្នាំ 2013 នៅពេលដែលការិយាល័យសវនកម្មជាតិរកឃើញថា ការកសាងដើមនឹងមិនផ្តល់តម្លៃសមស្របនឹងថ្លៃចំណាយ ហើយផ្នែកសំខាន់នៃទ្រព្យសកម្មកម្មវិធីត្រូវលុបចោល គឺជាឧទាហរណ៍ស្តង់ដារនៃបំណុលបច្ចេកទេសដែលមិនបានកំណត់តម្លៃ ដែលតាមទាន់កម្មវិធីសាធារណៈដែលកំពុងដំណើរការ និងអាចមើលឃើញដោយរដ្ឋមន្ត្រី។

## ឧទាហរណ៍គណនា

ម៉ាស៊ីនដំណើរការពាក្យសុំ 250,000 បន្ទាត់ ដែលសរសេរជាភាសា 4GL ចាស់។ ដោយប្រើស្តង់ដារ CAST Appmarq ប្រហែល $3.61 នៃប្រាក់ដើមបំណុលបច្ចេកទេសក្នុងមួយបន្ទាត់កូដ (≈£2.85 តាមអត្រាបម្លែងធម្មតា)៖

```
ប្រាក់ដើម ≈ 250,000 × £2.85 ≈ £712,500
TDR ≈ 16% (ចំណាត់ថ្នាក់ C)
```

ការប្រាក់ដែលបានវាស់៖ ក្រសួងរក្សាអ្នកម៉ៅការឯកទេសបីនាក់ ក្នុងអត្រាប្រចាំថ្ងៃលើសអត្រាវិស្វករជាន់ខ្ពស់ស្តង់ដារ 40% ដោយសារជំនាញផ្ទៃក្នុងបានរលាយ គឺបន្ថែម £180,000/ឆ្នាំ លើក្រុមប្រាំមួយនាក់។ ប្រព័ន្ធក៏បង្កការដួលរលំដំណើរការធំៗ 4 ដង/ឆ្នាំ ម្តងៗផ្អាកការសម្រេចចិត្តសម្រាប់អ្នកទាមទារប្រហែល 5,000 នាក់ ហើយបង្វែរពួកគេទៅមជ្ឈមណ្ឌលទំនាក់ទំនងក្នុងតម្លៃប្រហែល £25/ការហៅ៖

```
ការប្រាក់ ≈ £180,000 (បុព្វលាភជំនាញ)
         + 4 × 5,000 × £25 = £500,000 (ថ្លៃចំណាយទំនាក់ទំនងដែលបានបង្វែរ)
         ≈ £680,000/ឆ្នាំ
```

ការកែតម្រូវដែលផ្តោតគោលដៅលើម៉ូឌុលដែលដំណើរការអន់បំផុត មានថ្លៃចំណាយ £1,200,000 ហើយត្រូវបានគំរូថាកាត់បន្ថយការប្រាក់ 70%៖

```
ការកាត់បន្ថយការប្រាក់ = 0.70 × 680,000 = £476,000/ឆ្នាំ
ការសងទុន ≈ 1,200,000 / 476,000 ≈ 2.5 ឆ្នាំ
```

ការផ្តោតគោលដៅមានសារៈសំខាន់៖ ការកែតម្រូវកូដដែលកម្រប៉ះពាល់ មិនទិញអ្វីទេ ពីព្រោះការប្រាក់ប្រមូលផ្តុំនៅកន្លែងដែលភាពញឹកញាប់នៃការផ្លាស់ប្តូរ និងដង់ស៊ីតេបំណុលឡើងដល់កម្រិតកំពូលទាំងពីរ។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

ការដាក់ក្របខ័ណ្ឌតម្លៃសាធារណៈដែលលើកកម្ពស់ករណីបំណុលបច្ចេកទេសហួសពី "កូដចាស់"៖ បង្ហាញប្រព័ន្ធចាស់ជាបញ្ជីសារពើភ័ណ្ឌនៃកន្លែងដែលសមត្ថភាពបំពេញការងារបាត់បង់ប្រមូលផ្តុំ ហើយភ្ជាប់វាយ៉ាងច្បាស់លាស់ទៅនឹង[ថ្លៃចំណាយសរុបនៃការជាម្ចាស់](../ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ក្នុង-it-របស់រដ្ឋាភិបាល/) ពីព្រោះការប្រាក់គឺជាថ្លៃចំណាយប្រតិបត្តិការដែលជាកម្មសិទ្ធិនៃបន្ទាត់ TCO ទោះហិរញ្ញវត្ថុធ្លាប់សួរឬអត់ក៏ដោយ។ ប្រព័ន្ធដែលមានបំណុលច្រើនក៏មានការប៉ះពាល់[សន្តិសុខអ៊ីនធឺណិត](../តម្លៃនៃសន្តិសុខអ៊ីនធឺណិតក្នុងវិស័យសាធារណៈ/) ច្រើនជាងសមាមាត្រដែរ ពីព្រោះភាពញឹកញាប់នៃការជួសជុល (patching) និងដង់ស៊ីតេបំណុលមានទំនាក់ទំនងគ្នា ប្រព័ន្ធចាស់ដែលមិនអាចជួសជុលបានគឺជាបំណុលបច្ចេកទេសដែលការប្រាក់របស់វាត្រូវបានបង់ដោយហានិភ័យឧប្បត្តិហេតុ ជាជាងប្រាក់ផោន។ ហើយរាល់ការជួញដូររវាងការកែតម្រូវ និងមុខងារថ្មី ខ្លួនវាជាការសម្រេចចិត្ត[ថ្លៃចំណាយនៃការពន្យារពេល](../ថ្លៃចំណាយនៃការយឺតយ៉ាវក្នុងកម្មវិធីសាធារណៈ/)៖ ការសងបំណុលពន្យារការផ្លាស់ប្តូរតាមច្បាប់បន្ទាប់ ដែលមាន CoD ផ្ទាល់ខ្លួនដែលត្រូវថ្លឹងថ្លែងធៀបនឹងការប្រាក់ដែលបានសន្សំ។

## កំហុសដែលតែងកើតមាន

- **ការរាយការណ៍តែប្រាក់ដើម**៖ ការប៉ាន់ស្មានកែតម្រូវធំគួរឱ្យខ្លាច ដោយគ្មានតួលេខការប្រាក់ មិនបង្ហាញហេតុផលអ្វីដល់អ្នកអនុម័តការចំណាយទេ។
- **ការយកតួលេខបំណុលដែលបង្កើតដោយឧបករណ៍ទៅតាមព្យញ្ជនៈ**៖ ម៉ាស៊ីនស្កេនបែប SQALE រាប់ការរំលោភច្បាប់ ពួកវាខកខានប្រភេទបំណុលថ្លៃ គឺការសម្រេចចិត្តស្ថាបត្យកម្ម និងច្បាប់អាជីវកម្មចាស់ដែលគ្មានឯកសារ ខណៈដែលចង្អុលបង្ហាញរឿងតូចតាច។
- **"ការសរសេរឡើងវិញជៀសវាងទាំងអស់"**៖ កម្មវិធីជំនួសត្រូវតែឆ្លងកាត់វិន័យដូចគ្នានឹងករណីអាជីវកម្មផ្សេងទៀត គឺថ្លៃចំណាយcounterfactual ប្រូបាបនៃជោគជ័យ និងការបញ្ចុះតម្លៃ មិនមែនការលើកលែងពីវាទេ ដូចដែលការចាប់ផ្តើម Universal Credit ឡើងវិញក្នុងឆ្នាំ 2013 បានបង្ហាញ។
- **ឧត្តមគតិបំណុលសូន្យ**៖ កម្រិតបំណុលដ៏ល្អប្រសើរមិនមែនសូន្យទេ បំណុលគឺជាអំណាចរុញ (leverage) ដែលទិញការបំពេញការងារឱ្យលឿនជាង។ សំណួរសកម្មគឺអត្រាការប្រាក់ជានិច្ច មិនមែនថាតើបំណុលមានឬអត់ទេ។
