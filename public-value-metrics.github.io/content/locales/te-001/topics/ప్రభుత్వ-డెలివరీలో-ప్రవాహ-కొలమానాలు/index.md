# ప్రభుత్వ డెలివరీలో ప్రవాహ కొలమానాలు

ప్రవాహ కొలమానాలు (flow metrics), అంటే Little's Law, వర్క్-ఇన్-ప్రోగ్రెస్ (WIP) పరిమితులు, ప్రవాహ సామర్థ్యం, పరిమిత సామర్థ్యం ఉన్న వ్యవస్థలో పని ఎంత వేగంగా కదులుతుందో వివరిస్తాయి. స్ప్రింట్ బోర్డ్ అలాంటి వ్యవస్థల్లో ఒకటి; బెనిఫిట్-క్లెయిమ్ క్యూ, ప్లానింగ్-దరఖాస్తు రిజిస్టర్, వీసా కేస్‌వర్క్ బ్యాక్‌లాగ్ కూడా అదే గణితం, వేరే యూనిఫామ్‌లో.

## ఇది ఎందుకు ముఖ్యం

ప్రభుత్వ కేస్‌లోడ్లు క్యూయింగ్ వ్యవస్థలు, ఎవరైనా కొలిచినా కొలవకపోయినా క్యూయింగ్ వ్యవస్థలు క్యూయింగ్ నియమాలను పాటిస్తాయి. చట్టబద్ధ నిర్ణయ కాలవ్యవధులు దీన్ని స్పష్టం చేస్తాయి: Town and Country Planning విధానంలో చాలా చిన్న ప్లానింగ్ దరఖాస్తులకు 8 వారాల చట్టబద్ధ నిర్ణయ లక్ష్యం, పెద్ద దరఖాస్తులకు 13 వారాలు ఉంటాయి; అంటే చట్టంలోనే పొందుపరిచిన సైకిల్-టైమ్ కట్టుబాటు. National Audit Office, Home Affairs Select Committee పదేపదే పరిశీలించిన Home Office ఆశ్రయ కేస్‌వర్క్ బ్యాక్‌లాగ్, చాలాకాలం పాటు వర్క్-ఇన్-ప్రోగ్రెస్ త్రూపుట్ కన్నా వేగంగా పెరిగి, సైకిల్ టైమ్‌ను ఏ చట్టబద్ధ లేదా సేవా అంచనాలకన్నా చాలా దూరం తీసుకెళ్లిన ప్రభుత్వ వ్యవస్థకు బాగా నమోదైన ఉదాహరణ. ఈ వైఫల్య విధానాన్ని గుణాత్మకమైన "బ్యాక్‌లాగ్ సమస్య"గా వదిలేయకుండా, ఇంజనీర్లకు, కేస్‌వర్కింగ్ మేనేజర్లకు ప్రవాహ కొలమానాలు ఉమ్మడి, పరిమాణాత్మక పదజాలాన్ని ఇస్తాయి.

## గణితం

```
Little's Law:  WIP = Throughput × Cycle Time
           →   Cycle Time = WIP / Throughput

Flow efficiency = active (touch) time / total cycle time   (Vacanti)

WIP limit effect: for fixed throughput, halving WIP roughly halves
average cycle time (Little's Law rearranged) — the lever available
without adding headcount.
```

కేస్‌వర్క్‌కు బదులు సాఫ్ట్‌వేర్ డిప్లాయ్‌మెంట్ పైప్‌లైన్‌లకు వర్తింపజేసిన సమానమైన గణితం కోసం [ప్రజా విలువ కోసం DORA కొలమానాలు](../ప్రజా-విలువ-కోసం-dora-కొలమానాలు/) చూడండి.

## ఉదాహరణ సహిత పరిష్కారం

**స్థానిక సంస్థ ప్లానింగ్ విభాగం**: ఏ సమయంలోనైనా 400 దరఖాస్తులు తెరిచి ఉన్నాయి (WIP), బృందం వారానికి 50 దరఖాస్తులను పరిష్కరిస్తుంది (త్రూపుట్).

```
Cycle time = WIP / Throughput = 400 / 50 = 8 weeks
```

ఇది చిన్న దరఖాస్తులకు చట్టబద్ధ 8 వారాల లక్ష్యం వద్దే సరిపోతుంది; ఏమాత్రం వెసులుబాటు లేదు, అంటే రాబోయే డిమాండ్‌లో లేదా కన్సల్టీ స్పందన సమయంలో ఏ హెచ్చుతగ్గు ఉన్నా నిర్ణయాలు చట్టబద్ధ గడువును దాటిపోతాయి.

**ప్రవాహ సామర్థ్యం**: ఆ 8 వారాల్లో (56 క్యాలెండర్ రోజులు), ఒక దరఖాస్తుకు సాధారణంగా సుమారు 6 గంటల వాస్తవ కేస్‌వర్కర్ ప్రాసెసింగ్ సమయం ఉంటుంది.

```
Flow efficiency = 6 hours / (56 days × 8 working hours/day)
                = 6 / 448 ≈ 1.3%
```

సాఫ్ట్‌వేర్ బృందాలకు Vacanti ప్రమాణం సాధారణ ప్రవాహ సామర్థ్యాన్ని 15–20% అంటుంది; అనేక చట్టబద్ధ కన్సల్టీ హ్యాండ్‌ఆఫ్‌లు, ప్రజా సంప్రదింపు విండోలతో ప్రభుత్వ కేస్‌వర్క్ తరచూ ఒక ఆర్డర్ ఆఫ్ మాగ్నిట్యూడ్ తక్కువగా ఉంటుంది. ఎనిమిది వారాలు నిజంగా గడిచేది 98.7% "నిరీక్షణ" సమయంలోనే, కేస్‌వర్కర్ సామర్థ్యంలో కాదు.

**WIP-పరిమితి జోక్యం**: ప్రతి కేస్‌వర్కర్‌కు తెరిచి ఉన్న దరఖాస్తులను అపరిమితమైన 25కు బదులు 15కు పరిమితం చేస్తే (త్రూపుట్ స్థిరంగా ఉంచి), 16 మంది బృందంలో WIP 400 నుంచి సుమారు 240కి మారుతుంది:

```
New cycle time = 240 / 50 = 4.8 weeks
```

సిబ్బంది పెంపుతో కాక విధాన మార్పుతో సైకిల్ టైమ్ దాదాపు సగానికి తగ్గింది; DORA తరహా డెలివరీ బృందాలు స్ప్రింట్ WIPని పరిమితం చేసేటప్పుడు లాగే అదే లివర్ ఇది.

## సాఫ్ట్‌వేర్ ఇంజనీరింగ్‌తో సంబంధం

ప్రవాహ కొలమానాలు డెలివరీ బృందం కాన్బన్ బోర్డ్‌కు, అది సాఫ్ట్‌వేర్ నిర్మిస్తున్న కేస్‌వర్క్ ఫ్లోర్‌కు మధ్య ఉమ్మడి భాష: కేస్‌వర్కర్ క్యూ, పుల్-రిక్వెస్ట్ క్యూ రెండూ Little's Law ప్రకారమే నడుస్తాయి, రెండూ ఒకే విధంగా సైకిల్-టైమ్ లక్ష్యాలను అతిక్రమిస్తాయి: త్రూపుట్‌కు సాపేక్షంగా ఎక్కువ WIP. ఇది [ప్రజా కార్యక్రమాల్లో ఆలస్యపు వ్యయం](../ప్రజా-కార్యక్రమాల్లో-ఆలస్యం-వ్యయం/)కు నేరుగా వర్తిస్తుంది: సైకిల్ టైమ్ × CoD అంటే ఏ క్షణంలోనైనా క్యూలో ఉన్న పౌండ్లు; [సేవా ప్రమాణాలు మరియు లావాదేవీ కొలమానాలు](../సర్వీస్-స్టాండర్డ్స్-లావాదేవీ-మెట్రిక్స్/)కు కూడా వర్తిస్తుంది, అక్కడ ప్రచురించిన టర్నరౌండ్ లక్ష్యం ఒక సైకిల్-టైమ్ కట్టుబాటు, అది తప్పినప్పుడు ప్రవాహ కొలమానాలే దాన్ని నిర్ధారించగలవు. కేస్‌వర్క్ వ్యవస్థ సాఫ్ట్‌వేర్ WIP, సైకిల్ టైమ్‌ను ఎవరూ క్వెరీ చేయని కేస్-మేనేజ్‌మెంట్ వ్యవస్థలో పాతిపెట్టకుండా, ప్రథమ శ్రేణి కార్యాచరణ కొలమానాలుగా చూపాలి.

## సాధారణ లోపాలు

- **అసలు అడ్డంకిని సరిచేయకుండా WIP పరిమితులు పెట్టడం**: పరిమితి బయటి చట్టబద్ధ కన్సల్టీ స్పందన సమయమైతే, కేస్‌వర్కర్ WIPని పరిమితం చేయడం క్యూను తగ్గించకుండా పైకి జరుపుతుంది మాత్రమే.
- **ప్రవాహ సామర్థ్యాన్ని మోసం చేసే లక్ష్యంగా చూడటం**: 1.3% వాస్తవ సమయాన్ని తొందరపెట్టడం సైకిల్ టైమ్‌ను ఏమాత్రం కదిలించదు; లివరేజ్ దాదాపు ఎల్లప్పుడూ నిరీక్షణ స్థితుల్లోనే ఉంటుంది, అంటే ప్రక్రియ పునఃరూపకల్పన, కేస్‌వర్కర్ వేగం కాదు.
- **వైవిధ్యాన్ని విస్మరించడం**: Little's Law సగటులను వివరిస్తుంది; డిమాండ్ వైవిధ్యం ఎక్కువగా ఉన్న కేస్‌లోడ్‌కు కేవలం కఠినమైన WIP పరిమితి కాక బఫర్ సామర్థ్యం కావాలి, లేకపోతే సగటు మెరుగుపడినా అస్థిర తోకలో చట్టబద్ధ గడువులు తప్పుతూనే ఉంటాయి.
- **WIPని అస్థిరంగా కొలవడం**: రికార్డ్ వ్యవస్థలో "తెరిచి" ఉండి వాస్తవానికి మూడో పక్షం కోసం ఆగిపోయిన కేసు కూడా WIPనే; దాన్ని మినహాయిస్తే పౌరులకు కనిపించే వాస్తవం మారకుండానే సంఖ్యలు మెరుగ్గా కనిపిస్తాయి.
