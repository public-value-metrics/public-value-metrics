# ವೇದಿಕೆಯಾಗಿ ಸರ್ಕಾರ (GaaP)

ವೇದಿಕೆಯಾಗಿ ಸರ್ಕಾರ ಎಂದರೆ ಹಂಚಿಕೆಯ, ಮರುಬಳಸಬಹುದಾದ ಘಟಕಗಳನ್ನು (ಅಧಿಸೂಚನಾ ಸೇವೆ, ಪಾವತಿ ಸೇವೆ, ಗುರುತಿನ ಸೇವೆ) ಒಮ್ಮೆ, ಕೇಂದ್ರೀಯವಾಗಿ ನಿರ್ಮಿಸುವ ಕಾರ್ಯತಂತ್ರ; ಇದರಿಂದ ನೂರಾರು ಸರ್ಕಾರಿ ಸೇವೆಗಳು ಪ್ರತಿಯೊಂದೂ ತನ್ನದನ್ನು ನಿರ್ಮಿಸುವ ಬದಲು ಅವನ್ನು ಬಳಸಿಕೊಳ್ಳುತ್ತವೆ. ಇದು ಸಾರ್ವಜನಿಕ ಡಿಜಿಟಲ್ ಮೂಲಸೌಕರ್ಯವನ್ನು ವೇದಿಕೆ-ಅರ್ಥಶಾಸ್ತ್ರದ ಸಮಸ್ಯೆಯಾಗಿ ಮರುರೂಪಿಸುತ್ತದೆ: ಮೌಲ್ಯವಿರುವುದು ಯಾವುದೇ ಒಂದು ಸಂಯೋಜನೆಯಲ್ಲಿ ಅಲ್ಲ, ಅದನ್ನು ಅಳವಡಿಸಿಕೊಳ್ಳುವ *ಮುಂದಿನ* ತಂಡದ ಅಂಚಿನ ವೆಚ್ಚ ಶೂನ್ಯವನ್ನು ಸಮೀಪಿಸುವುದರಲ್ಲಿ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

GDS ಈ ಕಾರ್ಯತಂತ್ರವನ್ನು 2015ರ "Government as a Platform" ಪ್ರಕಟಣೆಯಲ್ಲಿ ಔಪಚಾರಿಕವಾಗಿ ಮಂಡಿಸಿತು. ಪಾವತಿ ಸ್ವೀಕಾರ, ಬಳಕೆದಾರರಿಗೆ ಅಧಿಸೂಚನೆ, ಗುರುತು ಪರಿಶೀಲನೆ, ವಿಳಾಸ ಹುಡುಕಾಟದಂತಹ ಒಂದೇ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಸರ್ಕಾರ ಸೇವೆಯಿಂದ ಸೇವೆಗೆ ಪ್ರತ್ಯೇಕವಾಗಿ ನಿರ್ಮಿಸುತ್ತಿತ್ತು, ಪ್ರತಿಯೊಂದೂ ತನ್ನದೇ ಖರೀದಿ, ಭದ್ರತಾ ಮೌಲ್ಯಮಾಪನ ಮತ್ತು ನಿರಂತರ ಬೆಂಬಲದ ಹೊರೆ ಹೊತ್ತು ಎಂದು ಅದು ವಾದಿಸಿತು. ಪರ್ಯಾಯ: ಒಮ್ಮೆ ಉನ್ನತ ಗುಣಮಟ್ಟಕ್ಕೆ ನಿರ್ಮಿಸಿ ಎಲ್ಲೆಡೆ ಮರುಬಳಸುವ ಕೆಲವೇ ಹಂಚಿಕೆಯ ವೇದಿಕೆಗಳು: ಇಮೇಲ್, ಪಠ್ಯ ಸಂದೇಶ ಮತ್ತು ಪತ್ರ ಕಳುಹಿಸಲು GOV.UK Notify, ಆನ್‌ಲೈನ್ ಪಾವತಿ ಸ್ವೀಕರಿಸಲು GOV.UK Pay, ಮತ್ತು ಗುರುತು ಪರಿಶೀಲನೆಗೆ GOV.UK One Login (ಹಿಂದಿನ GOV.UK Verify ಗುರುತು ಕಾರ್ಯಕ್ರಮದ ಉತ್ತರಾಧಿಕಾರಿ). ಈ ವೇದಿಕೆಗಳು ತಲುಪಿದ ಪ್ರಮಾಣವೇ ಕಾರ್ಯತಂತ್ರ ಕೆಲಸ ಮಾಡಿದ್ದರ ಸ್ಪಷ್ಟ ಸಾಕ್ಷ್ಯ: GOV.UK Pay ಸುಮಾರು 1,800 ಪ್ರತ್ಯೇಕ ಸೇವೆಗಳಾದ್ಯಂತ £10 ಬಿಲಿಯನ್‌ಗಿಂತ ಹೆಚ್ಚು ವಹಿವಾಟುಗಳನ್ನು ಸಂಸ್ಕರಿಸಿದೆ, ಮತ್ತು ತನ್ನ ಮೊದಲ £1 ಬಿಲಿಯನ್ ಸಂಸ್ಕರಿಸಲು ಸುಮಾರು ನಾಲ್ಕು ವರ್ಷ ತೆಗೆದುಕೊಂಡಿದ್ದ ಅದು ಈಗ ಅಷ್ಟನ್ನು ಸುಮಾರು ಐದು ತಿಂಗಳಲ್ಲಿ ಸಂಸ್ಕರಿಸುತ್ತದೆ; GOV.UK Notify 1,500ಕ್ಕೂ ಹೆಚ್ಚು ಸರ್ಕಾರಿ ಸಂಸ್ಥೆಗಳ ಪರವಾಗಿ 9 ಬಿಲಿಯನ್‌ಗಿಂತ ಹೆಚ್ಚು ಸಂದೇಶಗಳನ್ನು ಕಳುಹಿಸಿದೆ. ಅಳವಡಿಸಿಕೊಂಡ ಪ್ರತಿ ಸೇವೆಯೂ ತನ್ನದೇ ಪಾವತಿ ಗೇಟ್‌ವೇ ಅಥವಾ ಸಂದೇಶ ಪೈಪ್‌ಲೈನ್ ಅನ್ನು ನಿರ್ಮಿಸುವುದು, ಭದ್ರಪಡಿಸುವುದು ಮತ್ತು ನಿರ್ವಹಿಸುವುದನ್ನು ತಪ್ಪಿಸಿತು.

## ಗಣಿತ

```
Build cost per service (no platform) = N services × cost to build,
  secure-assess, and run one payment/notification/identity system

Platform cost = fixed platform build cost
              + marginal cost per adopting service (integration,
              configuration, ongoing platform-team support)

Reuse breaks even once:
  platform build cost < N × (per-service build cost − marginal
  integration cost)

For a mature platform, marginal cost per additional adopter approaches
the transaction/message fee alone — the fixed cost is amortized across
the whole government estate, not one department's budget, which is
why GaaP components are usually funded centrally rather than charged
at full cost-recovery to early adopters.
```

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

**ಪಾವತಿ ಗೇಟ್‌ವೇ ನಿರ್ಮಿಸುವ ಬದಲು GOV.UK Pay ಅಳವಡಿಸಿಕೊಳ್ಳುವ ಸ್ಥಳೀಯ ಪ್ರಾಧಿಕಾರ**:

```
Build-your-own estimate:
  PCI-DSS compliance work + integration + ongoing maintenance
  ≈ £85,000 build + £22,000/year maintenance

GOV.UK Pay adoption:
  Integration effort ≈ £12,000 (developer time)
  Transaction fees: government-to-citizen card payments typically
  charged at a small percentage + fixed fee per transaction, no
  separate PCI-DSS burden carried by the council
  ≈ £12,000 one-off, ongoing cost variable with volume, not fixed

First-year saving ≈ £85,000 − £12,000 = £73,000, before counting the
avoided £22,000/year maintenance and the avoided compliance risk of
holding card data in a council-run system at all — this second
category is the security value covered in
public-sector-cybersecurity-value.
```

ಆ £73,000 ಅನ್ನು ಈಗ GOV.UK Pay ಬಳಸುತ್ತಿರುವ ಸುಮಾರು 1,800 ಸೇವೆಗಳಿಗೆ ಹರಡಿದರೆ, ಸರ್ಕಾರದಾದ್ಯಂತ ತಪ್ಪಿಸಿದ ನಿರ್ಮಾಣ ವೆಚ್ಚ ನೂರಾರು ಮಿಲಿಯನ್‌ಗಳಲ್ಲಿರುತ್ತದೆ; ಕಾರ್ಯತಂತ್ರದ ಮೌಲ್ಯ ನಿಜವಾಗಿ ಇರುವುದು ವೇದಿಕೆ ಅರ್ಥಶಾಸ್ತ್ರದಲ್ಲಿ, ಯಾವುದೇ ಒಂದು ಸಂಯೋಜನೆಯಲ್ಲಿ ಅಲ್ಲ.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್ ಸಂಪರ್ಕ

ವೇದಿಕೆಯಾಗಿ ಸರ್ಕಾರವು [ಸರ್ಕಾರದಲ್ಲಿ ನಿರ್ಮಿಸುವುದೋ ಖರೀದಿಸುವುದೋ](../ಸರ್ಕಾರದಲ್ಲಿ-ನಿರ್ಮಿಸುವುದೇ-ಅಥವಾ-ಖರೀದಿಸುವುದೇ/) ಪರವಾಗಿ ನೇರ ವಾದ: ಹಂಚಿಕೆಯ, ಮೌಲ್ಯಮಾಪನಗೊಂಡ, ಉತ್ತಮವಾಗಿ ನಡೆಯುವ ಘಟಕ ಇರುವಾಗ ಅದರ ಕಸ್ಟಮ್ ಸಮಾನವನ್ನು ನಿರ್ಮಿಸುವುದು ಅಪರೂಪವಾಗಿ ಉತ್ತಮ [ಹಣಕ್ಕೆ ತಕ್ಕ ಮೌಲ್ಯ](../ಹಣಕ್ಕೆ-ತಕ್ಕ-ಮೌಲ್ಯ/) ಆಯ್ಕೆ, ಮತ್ತು ಅದು ವ್ಯಾಖ್ಯಾನದಿಂದಲೇ ಹೆಚ್ಚು ಕಡಿಮೆ [ಡಿಜಿಟಲ್ ಸೇವಾ ಮಾನದಂಡ](../ಡಿಜಿಟಲ್-ಸೇವಾ-ಮಾನದಂಡ/) ಅಂಶ 13ರಲ್ಲಿ ("ಮುಕ್ತ ಮಾನದಂಡಗಳು, ಸಾಮಾನ್ಯ ಘಟಕಗಳು ಮತ್ತು ಮಾದರಿಗಳನ್ನು ಬಳಸಿ ಮತ್ತು ಅವಕ್ಕೆ ಕೊಡುಗೆ ನೀಡಿ") ವಿಫಲವಾಗುತ್ತದೆ. ಇದು [ಸರ್ಕಾರಿ ಐಟಿಯಲ್ಲಿ ಒಟ್ಟು ಮಾಲೀಕತ್ವ ವೆಚ್ಚ](../ಸರ್ಕಾರಿ-ಐಟಿಯಲ್ಲಿ-ಒಟ್ಟು-ಮಾಲೀಕತ್ವ-ವೆಚ್ಚ/) ಯ ಸ್ವರೂಪವನ್ನೂ ಬದಲಿಸುತ್ತದೆ: ವೇದಿಕೆ ಅಳವಡಿಕೆಯು ದೊಡ್ಡ ಬಂಡವಾಳ ಮತ್ತು ನಿರ್ವಹಣಾ ಸಾಲನ್ನು ಚಿಕ್ಕ, ಬಳಕೆ-ಸಂಬಂಧಿತ ಕಾರ್ಯಾಚರಣೆ ವೆಚ್ಚದೊಂದಿಗೆ ವಿನಿಮಯಿಸುತ್ತದೆ; ಅದನ್ನು ಮುನ್ನಂದಾಜು ಮಾಡುವುದು ಸುಲಭ, ಮತ್ತು ಸೇವೆಯನ್ನು ಸ್ಥಗಿತಗೊಳಿಸಿದರೆ ಹಣ ನಿಲ್ಲಿಸುವುದೂ ಸುಲಭ. ಘಟಕಗಳ ಮುಕ್ತ ಮರುಬಳಕೆಗೆ [ಮುಕ್ತ ದತ್ತಾಂಶದ ಮೌಲ್ಯ](../ಮುಕ್ತ-ಡೇಟಾದ-ಮೌಲ್ಯ/) ಸೋದರಸಂಬಂಧಿ: ಎರಡೂ ಸರ್ಕಾರ ಒಮ್ಮೆ ಉತ್ಪಾದಿಸುವುದನ್ನು ಇಲಾಖೆಯ ಆಸ್ತಿಯಾಗಿ ಅಲ್ಲ, ಹಂಚಿಕೆಯ ಮೂಲಸೌಕರ್ಯವಾಗಿ ಪರಿಗಣಿಸುವ ಕಾರ್ಯತಂತ್ರಗಳು.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **ನೆರಳು ಮರುನಿರ್ಮಾಣ**: ವೇದಿಕೆಯ ಆನ್‌ಬೋರ್ಡಿಂಗ್ ಪ್ರಕ್ರಿಯೆ ಸ್ವತಃ ಮಾಡುವುದಕ್ಕಿಂತ ನಿಧಾನ ಎಂಬ ಕಾರಣಕ್ಕೆ ತಂಡಗಳು ಮೌನವಾಗಿ ತಮ್ಮದೇ ಪಾವತಿ ಅಥವಾ ಅಧಿಸೂಚನಾ ಸಂಯೋಜನೆಯನ್ನು ನಿರ್ಮಿಸುತ್ತವೆ; ಇದು ತಂತ್ರಜ್ಞಾನದ ಸಮಸ್ಯೆಯಲ್ಲ, ಆಡಳಿತ ಘರ್ಷಣೆಯ ಸಮಸ್ಯೆ, ಮತ್ತು ಇಡೀ ಕಾರ್ಯತಂತ್ರ ಅವಲಂಬಿಸಿರುವ ಮರುಬಳಕೆ ಅರ್ಥಶಾಸ್ತ್ರವನ್ನು ಮೌನವಾಗಿ ಸವೆಸುತ್ತದೆ.
- **ವೇದಿಕೆ ತಂಡಕ್ಕೆ ಅದು ಸೃಷ್ಟಿಸುವ ಮೌಲ್ಯಕ್ಕೆ ಹೋಲಿಸಿದರೆ ಕಡಿಮೆ ಹಣ ನೀಡುವುದು**: ಮೌಲ್ಯವು ಬಳಸುವ ಇಲಾಖೆಗಳಿಗೆ ಸೇರುತ್ತದೆ, ವೆಚ್ಚ ವೇದಿಕೆ ತಂಡದ ಮೇಲಿರುತ್ತದೆ; ಹಣಕಾಸು ಕೇಂದ್ರೀಕೃತ ಮತ್ತು ರಕ್ಷಿತವಾಗಿಲ್ಲದಿದ್ದರೆ ದೀರ್ಘಕಾಲದ ಕಡಿಮೆ ಹೂಡಿಕೆಯ ಅಪಾಯ ಉಂಟಾಗುತ್ತದೆ; ಇದು ಸಾಮಾನ್ಯರ ದುರಂತದ ಒಂದು ರೂಪ.
- **ವೇದಿಕೆಯ ಯಶಸ್ಸನ್ನು ಬಳಕೆಯಿಂದ ಮಾತ್ರ ಅಳೆಯುವುದು**: ಅಳವಡಿಕೆ ಸಂಖ್ಯೆಗಳು (ಆನ್‌ಬೋರ್ಡ್ ಆದ ಸೇವೆಗಳು, ಕಳುಹಿಸಿದ ಸಂದೇಶಗಳು) ಮುಂಚೂಣಿ ಸೂಚಕ, ಮೌಲ್ಯದ ಪುರಾವೆಯಲ್ಲ; ನಿಜವಾದ ಪರೀಕ್ಷೆ ಮೇಲಿನ ತಪ್ಪಿಸಿದ-ನಿರ್ಮಾಣ-ವೆಚ್ಚ ಮತ್ತು ತಪ್ಪಿಸಿದ-ಅಪಾಯದ ಲೆಕ್ಕಾಚಾರ.
- **"ವೇದಿಕೆ"ಯನ್ನು "ಮೊನೊಲಿತ್"ಗೆ ಸಮಾನಾರ್ಥಕವೆಂದು ಪರಿಗಣಿಸುವುದು**: ಪ್ರತಿ GaaP ಘಟಕ ಕಿರಿದಾದ, ಸ್ಥಿರ ಇಂಟರ್ಫೇಸ್‌ನೊಂದಿಗೆ ಒಂದೇ ಕೆಲಸವನ್ನು ಚೆನ್ನಾಗಿ ಮಾಡುವುದರಿಂದ ಯಶಸ್ವಿಯಾಗುತ್ತದೆ; ಸಂಬಂಧವಿಲ್ಲದ ಸಾಮರ್ಥ್ಯಗಳನ್ನು ಒಂದೇ "ವೇದಿಕೆ"ಯಲ್ಲಿ ಕಟ್ಟುವುದು ಕಸ್ಟಮ್-ನಿರ್ಮಾಣ ಸಮಸ್ಯೆಯನ್ನು ಬೇರೆ ಮಟ್ಟದಲ್ಲಿ ಮರುಸೃಷ್ಟಿಸುತ್ತದೆ.
