# ಮುಕ್ತ ಡೇಟಾದ ಮೌಲ್ಯ

ಮುಕ್ತ ಡೇಟಾದ ಮೌಲ್ಯ ಎಂದರೆ ಬೆಲೆಯೇ ಇಲ್ಲದ ಸರ್ಕಾರಿ ಮತ್ತು ಸಾರ್ವಜನಿಕ ಡೇಟಾ ಎಷ್ಟು ಮೌಲ್ಯದ್ದು ಎಂದು ಅಂದಾಜು ಮಾಡುವ ಸಮಸ್ಯೆ: ಅದನ್ನು ಮಾರುವುದಿಲ್ಲ, ಆದ್ದರಿಂದ ಆದಾಯದ ಸಾಲು ಇಲ್ಲ;
ಆದರೂ ಅದನ್ನು ಬಿಡುಗಡೆ ಮಾಡುವುದು (ಹವಾಮಾನ ದಾಖಲೆಗಳು, ಸಾರಿಗೆ ವೇಳಾಪಟ್ಟಿಗಳು, ಅಂಚೆ ಸಂಕೇತ ಗಡಿಗಳು, ಕಂಪನಿ ನೋಂದಣಿಗಳು) ಕೆಳಹಂತದಲ್ಲಿ ಆರ್ಥಿಕ ಮತ್ತು ಸಾಮಾಜಿಕ ಚಟುವಟಿಕೆಯನ್ನು
ಸ್ಪಷ್ಟವಾಗಿ ಹುಟ್ಟಿಸುತ್ತದೆ. ಇದಕ್ಕೆ ಚೆನ್ನಾಗಿ ಮೌಲ್ಯ ಕಟ್ಟುವುದು ಮುಖ್ಯ, ಏಕೆಂದರೆ "ಬಿಡುಗಡೆ ಮಾಡಲು ಉಚಿತ" ಮತ್ತು "ಮೌಲ್ಯರಹಿತ" ಎರಡೂ ತಪ್ಪು; ಒಂದು API ಅಥವಾ ಡೇಟಾಸೆಟ್ ತೆರೆಯಬೇಕೇ ಎಂದು
ನಿರ್ಧರಿಸುವ ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರ್‌ಗೆ ಇವೆರಡಕ್ಕಿಂತ ಉತ್ತಮ ವಾದ ಬೇಕು.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಹೆಚ್ಚು ಉಲ್ಲೇಖಿಸಲಾದ ಮೇಲಿನಿಂದ-ಕೆಳಗಿನ ಅಂದಾಜು McKinsey Global Institute ಯ 2013 ರ ವರದಿ "Open data: Unlocking innovation and performance with liquid information" ನಿಂದ ಬಂದಿದೆ;
ಅದು ಶಿಕ್ಷಣ, ಸಾರಿಗೆ, ಗ್ರಾಹಕ ಉತ್ಪನ್ನಗಳು, ವಿದ್ಯುತ್, ತೈಲ ಮತ್ತು ಅನಿಲ, ಆರೋಗ್ಯ ಹಾಗೂ ಗ್ರಾಹಕ ಹಣಕಾಸು ಎಂಬ ಏಳು ವಲಯಗಳಲ್ಲಿ ಮುಕ್ತ ಡೇಟಾದ ಸಂಭಾವ್ಯ ವಾರ್ಷಿಕ ಮೌಲ್ಯವನ್ನು ಜಾಗತಿಕವಾಗಿ
ವರ್ಷಕ್ಕೆ $3 ಟ್ರಿಲಿಯನ್‌ನಿಂದ $5 ಟ್ರಿಲಿಯನ್ ಎಂದು ಅಂದಾಜಿಸಿತು; ಹೆಚ್ಚಿನ ಪಾರದರ್ಶಕತೆ, ಪೂರೈಕೆಯನ್ನು ಬೇಡಿಕೆಗೆ ಹೆಚ್ಚು ದಕ್ಷವಾಗಿ ಹೊಂದಿಸುವುದು ಮತ್ತು ಡೇಟಾದ ಮೇಲೆ ಕಟ್ಟಿದ ಹೊಸ ಉತ್ಪನ್ನ
ಹಾಗೂ ಸೇವೆಗಳು ಇದರ ಕಾರ್ಯವಿಧಾನಗಳು. ಆ ಸಂಖ್ಯೆ ಒಂದು ಸನ್ನಿವೇಶ ಅಂದಾಜು, ಅಳೆದ ವಾಸ್ತವ ಫಲಿತಾಂಶವಲ್ಲ; ಮತ್ತು ಸರ್ಕಾರ ನೇರವಾಗಿ ಪಡೆಯಬಹುದಾದ ಆದಾಯವೆಂಬಂತೆ ಅದನ್ನು ವಾಡಿಕೆಯಾಗಿ
ತಪ್ಪಾಗಿ ಉಲ್ಲೇಖಿಸಲಾಗುತ್ತದೆ; ವಾಸ್ತವದಲ್ಲಿ ಮೌಲ್ಯವು ಹೆಚ್ಚಾಗಿ ಡೇಟಾ ಬಳಸುವ ಮೂರನೇ ಪಕ್ಷಗಳಿಗೆ — ವ್ಯವಹಾರಗಳು, ಸಂಶೋಧಕರು, ನಾಗರಿಕರು — ಸೇರುತ್ತದೆ; ಮಾರುವ ಬದಲು ತೆರೆಯುವುದರ ಉದ್ದೇಶವೇ ಅದು.
2012 ರಲ್ಲಿ Sir Tim Berners-Lee ಮತ್ತು Sir Nigel Shadbolt ಸಹ-ಸ್ಥಾಪಿಸಿದ ಬ್ರಿಟನ್‌ನ Open Data Institute ನಂತರ ವಲಯದಿಂದ ವಲಯಕ್ಕೆ, ಡೇಟಾಸೆಟ್‌ನಿಂದ ಡೇಟಾಸೆಟ್‌ಗೆ ಹೆಚ್ಚು ವಿವರವಾದ,
ಕೆಳಗಿನಿಂದ-ಮೇಲಿನ ಪ್ರಕರಣ ಅಧ್ಯಯನಗಳ ಸಮೂಹವನ್ನು ಕಟ್ಟಿದೆ; ಇವು ನಿಜವಾದ ವ್ಯವಹಾರ ಪ್ರಕರಣಕ್ಕೆ McKinsey ಯ ಮುಖ್ಯ ಸಂಖ್ಯೆಗಿಂತ ಹೆಚ್ಚು ಉಪಯುಕ್ತ, ಏಕೆಂದರೆ ಮೌಲ್ಯದ ಒಟ್ಟು ಗಾತ್ರವನ್ನಷ್ಟೇ ಅಲ್ಲ,
ಮೌಲ್ಯ ಸೃಷ್ಟಿಯ ಕಾರ್ಯವಿಧಾನವನ್ನೂ ತೋರಿಸುತ್ತವೆ.

## ಗಣಿತ

ಮುಕ್ತ ಡೇಟಾಗೆ ಮಾರುಕಟ್ಟೆ ಬೆಲೆ ಇಲ್ಲ, ಆದ್ದರಿಂದ ಮೌಲ್ಯಮಾಪನ ವಿಧಾನಗಳು ಅದರ ಸ್ಥಾನ ತುಂಬುತ್ತವೆ; ಮೂರು ವಿಧಾನಗಳು ಪುನರಾವರ್ತಿತವಾಗಿ ಬರುತ್ತವೆ, ಮತ್ತು ಯಾವುದೂ ಒಂಟಿಯಾಗಿ ಸಾಕಾಗದು:

```
1. Cost-avoided / replacement-cost method:
   value ≈ what users would have paid to produce or licence the
   equivalent data themselves — a lower bound, ignores value created
   by uses the original producer never anticipated

2. Market-analogue / downstream-activity method:
   value ≈ revenue or savings generated by businesses/services built
   on the data (e.g. satnav apps built on open mapping and traffic
   data) — captures real economic activity but is hard to attribute
   cleanly to the data release itself (see additionality-and-deadweight)

3. Contingent/stated-preference method:
   value ≈ what users say they would pay, or the time they say it
   saves them — see stated-preference-valuation for the general
   method and its biases

None of these produces a figure as clean as a market price; credible
open data business cases triangulate across two or more, and are
explicit about which mechanism is doing the work.
```

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

**ವಿವರಣಾತ್ಮಕ ರಾಷ್ಟ್ರೀಯ ನಕ್ಷೆ/ವಿಳಾಸ ಡೇಟಾ ಬಿಡುಗಡೆ** (ODI ಶೈಲಿಯ ಪ್ರಕರಣ ಅಧ್ಯಯನಗಳ ವಿಧಾನ; ಅಂಕಿಅಂಶಗಳು ಅಂತಹ ಅಧ್ಯಯನಗಳು ಸಾಮಾನ್ಯವಾಗಿ ಕಾಣುವ ಪ್ರಮಾಣದ ವಿವರಣೆ ಮಾತ್ರ):

```
Cost-avoided estimate:
  Businesses that would otherwise licence equivalent address-matching
  data commercially, at an estimated average licence cost of £4,000/
  year, across an estimated 15,000 SMEs now using the free open dataset
  = 15,000 × £4,000 = £60,000,000/year in avoided licensing cost alone

Downstream-activity estimate (more speculative, needs a counterfactual):
  New delivery-routing and logistics products built on the open data
  that would not exist, or would be materially worse, without it —
  requires a comparison against the counterfactual of the data staying
  closed or commercially licensed (counterfactual-analysis), because
  some of that activity would happen anyway on paid data at a higher
  price, which is deadweight in the "value created by opening it" sense

A defensible business case reports the cost-avoided figure as the
solid lower bound, and treats the downstream-activity figure as an
upper-bound scenario, not a fact.
```

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್ ಸಂಪರ್ಕ

ಎಂಜಿನಿಯರ್‌ಗಳಿಗೆ ಮುಕ್ತ ಡೇಟಾ ಮೌಲ್ಯದ ಪ್ರಾಯೋಗಿಕ ಪ್ರಶ್ನೆ ಸಾಮಾನ್ಯವಾಗಿ ರಾಷ್ಟ್ರೀಯ ಮುಖ್ಯ ಅಂಕಿಅಂಶಗಳಿಗಿಂತ ಕಿರಿದು: ಈ ನಿರ್ದಿಷ್ಟ API ಅಥವಾ ಡೇಟಾಸೆಟ್ ಅನ್ನು (ಪಾಲುದಾರ ಒಪ್ಪಂದದ ಹಿಂದೆ ಇಡುವ ಬದಲು)
ತೆರೆಯುವುದು, ಅದನ್ನು ಸಾರ್ವಜನಿಕ ಇಂಟರ್‌ಫೇಸ್ ಆಗಿ ದಾಖಲಿಸುವ, ಆವೃತ್ತಿ ನಿರ್ವಹಿಸುವ ಮತ್ತು ಬೆಂಬಲಿಸುವ ನಿರಂತರ ವೆಚ್ಚವನ್ನು ಸಮರ್ಥಿಸುವಷ್ಟು ಮರುಬಳಕೆಯನ್ನು ಹೆಚ್ಚಿಸುತ್ತದೆಯೇ? ಆ ನಿರ್ವಹಣಾ ವೆಚ್ಚ ನೈಜ,
ಮತ್ತು ಅದು [ವೇದಿಕೆಯಾಗಿ ಸರ್ಕಾರ](../ವೇದಿಕೆಯಾಗಿ-ಸರ್ಕಾರ/) ದ ಒಮ್ಮೆ-ಕಟ್ಟಿ-ಹಲವು ಬಾರಿ-ಬಳಸುವ ಅರ್ಥಶಾಸ್ತ್ರದ ಪ್ರತಿರೂಪ — ಈ ಎರಡು ವಿಷಯಗಳು ಹತ್ತಿರದ ಸೋದರ ವಿಷಯಗಳು; ಒಂದು ಹಂಚಿಕೆಯ ಕೋಡ್ ಮತ್ತು
ಮೂಲಸೌಕರ್ಯದ ಬಗ್ಗೆ, ಇನ್ನೊಂದು ಹಂಚಿಕೆಯ ಡೇಟಾದ ಬಗ್ಗೆ. ಯಾವುದೇ ಮುಕ್ತ ಡೇಟಾ ಮೌಲ್ಯದ ಹೇಳಿಕೆಯನ್ನು ವ್ಯವಹಾರ ಪ್ರಕರಣಕ್ಕೆ ಸೇರಿಸುವ ಮೊದಲು
[ಹೆಚ್ಚುವರಿತನ ಮತ್ತು ಡೆಡ್‌ವೇಟ್](../ಹೆಚ್ಚುವರಿತನ-ಮತ್ತು-ಡೆಡ್-ವೇಟ್/) ವಿರುದ್ಧ ಪರಿಶೀಲಿಸಬೇಕು: ವಾಣಿಜ್ಯವಾಗಿ ಪರವಾನಗಿ ಪಡೆದ ಡೇಟಾದ ಮೇಲೆ ಹೇಗಿದ್ದರೂ ನಡೆಯುತ್ತಿದ್ದ ಚಟುವಟಿಕೆ, *ತೆರೆಯುವಿಕೆ* ಸೃಷ್ಟಿಸಿದ ಮೌಲ್ಯವಲ್ಲ.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **McKinsey ಯ $3–5 ಟ್ರಿಲಿಯನ್ ಅಂಕಿಅಂಶವನ್ನು ಬ್ರಿಟನ್‌ಗೆ ಮಾತ್ರ ಅನ್ವಯಿಸುವಂತೆ ಅಥವಾ ಈ ಡೇಟಾಸೆಟ್‌ನ ಪಾಲು ಎಂದು ಉಲ್ಲೇಖಿಸುವುದು**: ಇದು 2013 ರ ಜಾಗತಿಕ, ಏಳು-ವಲಯದ ಸನ್ನಿವೇಶ ಅಂದಾಜು — ಒಂದೇ ರಾಷ್ಟ್ರೀಯ ಡೇಟಾಸೆಟ್‌ಗೆ ನಿಖರ ಗುಣಕವಾಗಿ ಬಳಸಿದರೆ ಆ ಸಂಖ್ಯೆ ಏನೆಂಬುದನ್ನು ತಪ್ಪಾಗಿ ಬಿಂಬಿಸಿದಂತಾಗುತ್ತದೆ.
- **ಪ್ರತಿವಾಸ್ತವವಿಲ್ಲದಿರುವುದು**: ಮುಕ್ತ ಡೇಟಾದ ಮೇಲೆ ಕಟ್ಟಿದ ಎಲ್ಲ ಕೆಳಹಂತದ ಆರ್ಥಿಕ ಚಟುವಟಿಕೆಗೆ ಶ್ರೇಯ ಪಡೆಯುವುದು, ಅದರಲ್ಲಿ ಎಷ್ಟು ಹೇಗಿದ್ದರೂ ಹೆಚ್ಚಿನ ಬೆಲೆಯ ಪಾವತಿಸಿದ ಅಥವಾ ಪರವಾನಗಿ ಡೇಟಾದ ಮೇಲೆ ನಡೆಯುತ್ತಿತ್ತು ಎಂದು ಕೇಳದೆ
  (ನೋಡಿ [ಹೆಚ್ಚುವರಿತನ ಮತ್ತು ಡೆಡ್‌ವೇಟ್](../ಹೆಚ್ಚುವರಿತನ-ಮತ್ತು-ಡೆಡ್-ವೇಟ್/) ಮತ್ತು [ಪ್ರತಿವಾಸ್ತವ ವಿಶ್ಲೇಷಣೆ](../ಪ್ರತಿವಾಸ್ತವಿಕ-ವಿಶ್ಲೇಷಣೆ/)).
- **ಉತ್ಪಾದನಾ ವೆಚ್ಚವನ್ನು ಸೃಷ್ಟಿಸಿದ ಮೌಲ್ಯದೊಂದಿಗೆ ಗೊಂದಲ ಮಾಡುವುದು**: ಸಂಗ್ರಹಿಸಲು ದುಬಾರಿಯಾದ ಡೇಟಾಸೆಟ್ ಬಿಡುಗಡೆ ಮಾಡಲು ತನ್ನಿಂದ ತಾನೇ ಮೌಲ್ಯಯುತವಲ್ಲ, ಮತ್ತು ಅಗ್ಗದ್ದು ತನ್ನಿಂದ ತಾನೇ ಕಡಿಮೆ
  ಮೌಲ್ಯದ್ದಲ್ಲ — ಮೌಲ್ಯವು ಮೇಲ್ಮಟ್ಟದ ವೆಚ್ಚವನ್ನಲ್ಲ, ಕೆಳಹಂತದ ಬಳಕೆಯನ್ನು ಅನುಸರಿಸುತ್ತದೆ.
- **"ಮುಕ್ತ"ದ ನಿರಂತರ ನಿರ್ವಹಣಾ ವೆಚ್ಚವನ್ನು ನಿರ್ಲಕ್ಷಿಸುವುದು**: ಒಂದು ಬಾರಿಯ CSV ಸಾರವನ್ನು ಪ್ರಕಟಿಸುವುದು, ದಾಖಲಿತ, ಆವೃತ್ತಿ ನಿರ್ವಹಿತ, ಬೆಂಬಲಿತ ಮುಕ್ತ API ಅನ್ನು ನಡೆಸುವಷ್ಟೇ ಬದ್ಧತೆಯಲ್ಲ —
  ಬಿಡುಗಡೆ ಘೋಷಣೆಯ ನಂತರ ಎರಡನೆಯದಕ್ಕೆ ಸಾಕಷ್ಟು ಹಣ ನೀಡದಿರುವುದು ಸಾಮಾನ್ಯ ವೈಫಲ್ಯ ವಿಧಾನ.
