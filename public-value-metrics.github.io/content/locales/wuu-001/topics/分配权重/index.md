# 分配权重

分配权重（distributional weighting）是根据成本或者收益落勒啥人手里，来调整伊个货币价值，道理是：多一镑钞票，对穷人家来讲比对富人家来讲更值钿。英国财政部个 Green Book（《绿皮书》）提供了一套明确个办法来应用搿种权重，建立勒收入边际效用递减个基础上，搿样评估辰光就勿会悄悄拿最富裕个十分位拿到个一镑，当作搭最穷个十分位拿到个一镑价值一样。

## 为啥重要

标准个成本收益分析是拿镑数加起来，勿问搿些是啥人个镑，伊默认一镑对啥人来讲侪是一样值钿——经济学家老早就晓得搿个假设是勿对个。一户一年收入 £15,000 个人家，搭一户一年收入 £150,000 个人家，对 £1,000 个收益个感受完全勿一样，因为收入越高，收入个边际效用越低。勿加权重个话，标准评估会系统性地偏向让更有钞票、本来就过得更好个群体受益个干预，因为伊拉购买力高，会拿触达伊拉个收益个货币估值抬高（一个高档住宅区附近个公园改造，会"显示"出比便宜住宅区附近同样个改造更大个房产增值收益，纯粹是因为房价高，勿是因为福利增进更大）。

Green Book 关于分配分析个补充指引，勒 2020 年财政部个评审之后得到加强——搿次评审是回应批评，批评讲评估方法系统性地偏向伦敦搭英格兰东南部——提出了一套正式个加权办法，假设收入边际效用弹性约为 1.3，意思是收入翻一倍，多一镑个边际价值大概减半（准确讲是 2^-1.3 ≈ 0.41 倍）。搿勿是四舍五入个小调整：用了伊，两个互相竞争个项目里哪个净现值（net present value）更高，可能就会换个位置，特别是拿集中勒贫困地区个干预搭铺勒普通人口身上个干预相比个辰光。

## 数学

Green Book 里，落勒收入水平 y 个家庭个一镑收益，相对于全国平均收入水平 ȳ 个一镑，分配权重是：

```
Weight(y) = (ȳ / y)^e

where:
  y  = household income (or income of the affected group)
  ȳ  = average (reference) household income
  e  = elasticity of marginal utility of income (Green Book: approximately 1.3)
```

拿权重用到净收益上：

```
Weighted benefit = Σ [unweighted benefit to group i × Weight(y_i)]
```

收入是全国平均一半个群体（y = 0.5ȳ），权重是 (1/0.5)^1.3 = 2^1.3 ≈ 2.46——搿个群体拿到个每一镑收益，算起来值平均收入家庭个大概 2.46 镑。

## 实例演算

**两个互相竞争个地方项目**，每个未加权个年度净收益侪是 £2 million，争取同一笔区域增长基金：

- *项目 A*：一个富裕市镇里个企业扶持计划，家庭平均收入 £45,000（大概是假设个全国平均 £35,000 个 1.3 倍）。
- *项目 B*：一个贫困选区里个技能培训项目，家庭平均收入 £18,000（大概是全国平均个 0.51 倍）。

```
Weight(A) = (35,000 / 45,000)^1.3 = (0.778)^1.3 ≈ 0.72
Weight(B) = (35,000 / 18,000)^1.3 = (1.944)^1.3 ≈ 2.53

Weighted benefit A = £2,000,000 × 0.72 = £1.44 million
Weighted benefit B = £2,000,000 × 2.53 = £5.06 million
```

勿加权个辰光，两个项目打平。按分配影响加权之后，项目 B 个收益大了三倍多——搿个结果会拿资助建议倒过来，也体现了 Green Book 要求一定要展示加权结果、而勿光是展示未加权个收益成本比个明确用意。

**慈善资助分配**：一个出资方比较两笔 £500,000 个资助：一笔触达 1,000 户低收入家庭（权重约 2.0，加权价值相当于 £1 million），另一笔触达 1,000 户中等收入家庭（权重约 1.0，加权价值相当于 £500,000）。伊应该勒董事会文件里明明白白展示搿个分配层面个理由，而勿是留拨读个人自家去推断。

## 搭软件工程个关联

分配权重难得直接出现勒软件交付个指标里，但是伊应该影响工程搭数据团队哪能设计度量搭定向：

- 做影响力仪表盘或者收益计算器个辰光，要展示受影响个人个收入或者贫困程度画像，勿要光有一个收益总数——勿做分配拆分个汇总数字，恰恰会拿上面展示个搿种逆转遮过去。
- 服务设计里个定向逻辑，要搭 Green Book 用个同一套贫困数据挂钩——参见 [多重剥夺指数](../多重剥夺指数/)——搿样一项数字服务个触达范围，就可以评估公平性，而勿光是效率（搿是 [物有所值](../物有所值/) 里个、有争议个第四个 E）。
- 算法分配稀缺资源（预约名额、个案工作者个辰光、补贴）个辰光，一个未加权个"总收益最大化"目标函数，按构造就会重现 Green Book 加权要纠正个同样个偏见——优化之前要明确拿搿一点告诉政策负责人。

## 容易踏个坑

- **勒整个项目组合里前后勿一致地应用分配权重。** 拿一个项目个收益加权、对比项目却勿加权，得出个是有偏、而勿是更公平个比较；Green Book 要求同等对待。
- **勿经调整就拿房产或者市场价值当福利个替代指标。** 市场价格本身就被已有个收入不平等扭曲了，而搿恰恰是分配权重要纠正个东西——直接用未调整个市场价值，可能拿偏差重复计算两趟。
- **忽略群体内部个差异。** 按地区平均收入（比方多重剥夺指数个十分位）加权，对搿些搭所在地区平均水平勿一样个个人会失真；要用合理能拿到个最细颗粒度个收入数据。
- **拿 1.3 个弹性当成通用常数。** Green Book 本身就讲明，搿是一个有合理区间个估计值；重大决策要对替代弹性做敏感性检验，而勿是拿 1.3 当作精确值。
