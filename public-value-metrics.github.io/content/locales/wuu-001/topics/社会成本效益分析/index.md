# 社会成本效益分析(SCBA)

社会成本效益分析,拿一项政策或者项目个每一项成本搭效益 — 市场个搭非市场个 — 侪换算成统一个货币单位,拿未来个现金流贴现成现值,再互相抵消,得出一个单一个数字:搿个提案是否让社会变好,变好多少?

## 为啥重要

SCBA 是[《绿皮书》评估](../green-book-评估/)经济案例里默认个定量方法:英国财政部个指引要求,只要效益可以可信地货币化,提案就必须证明净社会现值(NPSV)为正,非市场物品个基本估值原则是支付意愿(<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>,第 5 章)。伊强制个规矩是,"社会"成本效益分析搭私营部门个投资评估勿是一回事:伊必须包括落辣勿参与交易个第三方头上个成本搭效益(外部性),必须用[社会贴现率](../社会贴现率/)而勿是商业资本成本,而且辣一镑对穷家庭比对富家庭更要紧个地方,应该用[分配加权](../分配权重/)。

SCBA 个短处恰恰辣批评者预料个地方:呒没市场对应物个物品 — 清洁空气、社会凝聚力、救下一条命个价值 — 必须用[陈述偏好](../陈述偏好估值/)或者[显示偏好](../显示偏好估值/)方法货币化,或者构造一个[影子价格](../影子价格/)。货币化是有争议而勿光是困难个辰光,《绿皮书》本身建议退回[成本效果分析](../政府个成本效益分析/)或者[多准则决策分析](../多准则决策分析/),而勿是硬塞一个呒人相信个数字。

## 数学

```
NPSV = Σ [t=0 到 T] (Benefit_t − Cost_t) / (1 + r)^t

其中:
  Benefit_t = 第 t 年所有货币化个效益,包括通过陈述/显示偏好
              或者影子价格估值个非市场物品
  Cost_t    = 第 t 年所有货币化个成本,包括资源个机会成本
              (见 ../opportunity-cost-in-public-spending/)
  r         = 社会贴现率(英国财政部设为 3.5%,30 年之后依据
              《绿皮书》附录 A 递减到更低个税率)
  T         = 评估期

效益成本比(BCR)= Σ PV(效益) / Σ PV(成本)
```

BCR 大于 1(或者 NPSV 大于零)表示有净社会价值。《绿皮书》个物有所值分类(交通搭基础设施评估里使用)给 BCR 区间贴标签:低于 1.0 是物有所值差,1.0–1.5 是低,1.5–2.0 是中,2.0–4.0 是高,高于 4.0 是非常高。敏感性分析 — 辣悲观搭乐观假设下重新跑 NPSV — 是强制个,勿是可选个,因为货币化个非市场效益带有宽阔个不确定区间。

## 实例演算

**地方政府**:一个市议会评估辣 20 年评估期内、按 3.5% 贴现率,投资 £3m 建新个骑行搭步行网络。

```
成本:第 0 年资本 £3m,每年维护 £50,000(第 1-20 年)
PV(维护)≈ £50,000 × 14.2(3.5% 下 20 年年金系数)≈ £710,000
总 PV(成本)≈ £3.71m

效益(侪用公布个 DfT/WHO 估值工具货币化):
  增加体育活动带来个健康效益:£180,000/年
  减少缺勤:£40,000/年
  缓解拥堵(少几趟汽车出行):£60,000/年
  效益流合计:£280,000/年
PV(效益)≈ £280,000 × 14.2 ≈ £3.98m

NPSV = £3.98m − £3.71m = +£0.27m
BCR = 3.98 / 3.71 = 1.07 → 物有所值"低"
```

搿个方案过仔线,但是只是刚刚过;如果拿健康效益估算降低 20%(反映体育活动估值里真实个不确定性)跑一遍敏感性,BCR 就跌到 1.0 以下,搿就是为啥《绿皮书》要求敏感性表搭标题数字一道公布,而勿光是中心估计。

**慈善机构**:一个每年花费 £500,000 个婴儿死亡预防项目,用统计生命价值(VSL)评估 — 是影子价格,勿是观察到个市场价格 — 大约 £2.1m(英国财政部 2023 年更新个数字,伊本身来自陈述偏好研究)。每年避免一例婴儿死亡,对 £500,000 个成本,BCR 是 4.2,稳稳个"非常高"物有所值 — 但是整个结果建立辣 VSL 数字上,所以任何用 VSL 个 SCBA 必须拿伊当假设披露,勿是当事实。

## 搭软件工程个关联

SCBA 是政府软件里平台搭基础设施投资决策个自然框架 — 比方拿共享身份平台搭各部门个点状方案相比较,就要拿减少重复注册成本、减少欺诈、更快上线服务搿些本身呒没市场价格个效益货币化。搭建底层服务个工程师应该预期项目负责人会要求搿个分析个输入:交易个单位成本(见[每笔交易成本](../每笔交易成本/))、预期交易量,搭降级/停机成本。最值得引进个规矩:拿未来效益贴现,明确点出反事实基线(见[反事实分析](../反事实分析/)),而且勿要拿单一个点估计搭伊个敏感性区间分开单独展示。

## 容易踏个坑

- **重复计算效益。** 拿"节省个辰光"搭"搿段辰光带来个生产率"当作两行勿同个效益,会夸大方案;节省个辰光就是效益,伊个后续用途勿是额外个效益,除非有独立个证据。
- **遗漏被挤出个成本。** 一个方案拿拥堵从一条路搬到另一条路,或者拿欺诈从一个渠道搬到另一个渠道,并呒没创造出标题 NPSV 所暗示个净效益 — 见[挤出搭归因](../挤出效应搭归因/)。
- **用私人贴现率。** 用商业资本成本(比方 8–10%)而勿是社会贴现率,会系统性低估健康搭环境收益搿类长期公共效益 — 见[社会贴现率](../社会贴现率/)。
- **拿无争议个货币化,拿有争议个一笔带过。** 如果一个提案三分之二个效益是有把握货币化个效率节省,三分之一是靠勿牢个福祉收益,标题 NPSV 就悄悄拿一个硬数字搭一个软数字混辣一道;应该分开报告。
