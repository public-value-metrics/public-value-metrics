# ການປະເມີນຜົນກະທົບ ທຽບກັບ ການປະເມີນຂະບວນການ

ການປະເມີນຜົນກະທົບ (impact evaluation) ຖາມວ່າໂຄງການເປັນສາເຫດຂອງຜົນລັບທີ່ຕັ້ງໃຈຫຼືບໍ່. ການປະເມີນຂະບວນການ (process evaluation) ຖາມວ່າໂຄງການຖືກສົ່ງມອບຕາມທີ່ອອກແບບແທ້ຫຼືບໍ່ — ໃຫ້ໃຜ, ໃນປະລິມານເທົ່າໃດ ແລະ ມີອຸປະສັກ ຫຼື ປັດໃຈຫຍໍ້ທໍ້ຫຍັງຕະຫຼອດທາງ. ນີ້ແມ່ນຄຳຖາມທີ່ແຕກຕ່າງກັນທີ່ຕ້ອງການວິທີການຕ່າງກັນ ແລະ Magenta Book ຂອງ HM Treasury ຖືການວ່າຈ້າງທັງສອງຮ່ວມກັນເປັນການປະຕິບັດມາດຕະຖານ ເພາະຜົນກະທົບທີ່ອ່ອນ ຫຼື ເປັນສູນບໍ່ສາມາດຕີຄວາມໝາຍດ້ວຍຕົວມັນເອງ: ມັນບອກບໍ່ໄດ້ວ່າທິດສະດີພື້ນຖານຂອງໂຄງການຜິດ ຫຼື ທິດສະດີທີ່ດີບໍ່ເຄີຍຖືກສົ່ງມອບຢ່າງຖືກຕ້ອງ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ການປະເມີນຂອງລັດຖະບານພົບຊ້ຳແລ້ວຊ້ຳອີກວ່າບໍ່ມີຜົນທີ່ວັດໄດ້ຈາກໂຄງການ ໃນຂະນະທີ່ບໍ່ມີການປະເມີນຂະບວນການອະທິບາຍວ່າເປັນຫຍັງ — ປ່ອຍໃຫ້ຜູ້ວ່າຈ້າງແຍກບໍ່ໄດ້ລະຫວ່າງ "ແນວຄິດນີ້ບໍ່ໄດ້ຜົນ" (ຄວາມລົ້ມເຫຼວຂອງທິດສະດີ) ກັບ "ແນວຄິດນີ້ບໍ່ເຄີຍຖືກລອງຢ່າງຖືກຕ້ອງແທ້" (ຄວາມລົ້ມເຫຼວຂອງການປະຕິບັດ). ຄຳແນະນຳຂອງ Medical Research Council ກ່ຽວກັບການປະເມີນຂະບວນການຂອງການແຊກແຊງທີ່ຊັບຊ້ອນ ທີ່ເຜີຍແຜ່ໃນ BMJ ປີ 2015 ແລະ ຖືກອ້າງອີງຢ່າງກວ້າງຂວາງຄຽງຄູ່ກັບ Magenta Book ກຳນົດຄວາມຊື່ສັດຕໍ່ແບບຈຳລອງ (fidelity), ປະລິມານ (dose) ແລະ ການເຂົ້າເຖິງ (reach) ເປັນສິ່ງຫຼັກທີ່ການປະເມີນຂະບວນການຕ້ອງວັດ. ການວ່າຈ້າງການປະເມີນຜົນກະທົບໂດຍບໍ່ມີການປະເມີນຂະບວນການສ່ຽງທີ່ຈະປະຖິ້ມການອອກແບບໂຄງການທີ່ແຂງແກ່ນແທ້ໆ ເພາະມັນຖືກສົ່ງມອບໃຫ້ເຄິ່ງໜຶ່ງຂອງປະຊາກອນທີ່ຕັ້ງໃຈໄວ້ ດ້ວຍຄວາມເຂັ້ມພຽງສ່ວນນ້ອຍຂອງທີ່ຕັ້ງໃຈ — ຄວາມຜິດພາດທີ່ຜູ້ສ້າງລະບົບຢູ່ໃນຕຳແໜ່ງດີທີ່ຈະປ້ອງກັນ ເພາະຄວາມຊື່ສັດຕໍ່ການສົ່ງມອບແມ່ນສິ່ງທີ່ລະບົບຂໍ້ມູນການດຳເນີນງານບັນທຶກໄດ້ໃນເວລາເກືອບຈິງ.

## ຄະນິດສາດ

```
Process evaluation asks:
 - Was it delivered to the target population, at the planned dose/intensity?
 - Did delivery match the logic model / theory of change design?
 - What barriers or facilitators affected delivery?
 Methods: fidelity checks against pre-specified thresholds, case studies, interviews,
          administrative delivery data.

Impact evaluation asks:
 - What changed, and how much of that change is attributable to the programme?
 Methods: RCT, DiD, PSM, RDD — see impact-evaluation-methods — against a counterfactual.

Combined diagnosis:
 No effect  + high fidelity  → theory failure: the model itself did not produce the outcome
 No effect  + low fidelity   → implementation failure: the model was never properly tested
 Effect found + high fidelity → replicate with confidence
 Effect found + low fidelity  → investigate further: the effect may be fragile or site-specific
```

## ຕົວຢ່າງການຄິດໄລ່

**ອົງການປົກຄອງທ້ອງຖິ່ນ (ໂຄງການເຮັດໜ້າທີ່ພໍ່ແມ່)**: ການປະເມີນຜົນກະທົບທີ່ໃຊ້ difference-in-differences ພົບການປ່ຽນແປງ +2 ຈຸດເປີເຊັນໃນຕົວວັດຄວາມຢູ່ດີກິນດີຂອງເດັກ — ບໍ່ມີນັຍສຳຄັນທາງສະຖິຕິ. ການປະເມີນຂະບວນການທີ່ດຳເນີນຄຽງຄູ່ພົບວ່າໂຄງການເຂົ້າເຖິງພຽງ 210 ຈາກ 500 ຄອບຄົວເປົ້າໝາຍ (ການເຂົ້າເຖິງ 42%) ແລະ ໃນນັ້ນມີພຽງ 95 ຄອບຄົວທີ່ຜ່ານຂີດຄວາມຊື່ສັດທີ່ກຳນົດໄວ້ລ່ວງໜ້າຄື ເຂົ້າຮ່ວມ 75%+ ຂອງຊຸດ — 19% ຂອງການເຂົ້າເຖິງທີ່ວາງແຜນເດີມ. ບົດສະຫຼຸບ: ຜົນກະທົບທີ່ອ່ອນສອດຄ່ອງກັບຄວາມລົ້ມເຫຼວຂອງການປະຕິບັດ ບໍ່ແມ່ນຫຼັກຖານວ່າແບບຈຳລອງໂຄງການບໍ່ໄດ້ຜົນ; ການຕອບສະໜອງທີ່ເໝາະສົມແມ່ນແກ້ເສັ້ນທາງການສົ່ງຕໍ່ທີ່ເຮັດໃຫ້ຫຼຸດອອກ 58% ບໍ່ແມ່ນປະຖິ້ມການອອກແບບໂຄງການ.

**ອົງການກຸສົນ (ໂຄງການຄວາມຮູ້ດິຈິຕອນ)**: ການປະເມີນຜົນກະທົບພົບຜົນທີ່ແຂງແຮງ (+18 ຈຸດເປີເຊັນຂອງຄະແນນຄວາມໝັ້ນໃຈດ້ານດິຈິຕອນ) ແລະ ການປະເມີນຂະບວນການຂະໜານຢືນຢັນຄວາມຊື່ສັດ 92% ຕໍ່ຫຼັກສູດທີ່ວາງແຜນໃນທຸກ 12 ສະຖານທີ່ສົ່ງມອບ. ເມື່ອລວມກັນ ຜູ້ໃຫ້ທຶນສາມາດຂະຫຍາຍໂຄງການດ້ວຍຄວາມໝັ້ນໃຈ ເພາະຜົນຖືກສະແດງວ່າຄົງຢູ່ຢ່າງສອດຄ່ອງ ແທນທີ່ຈະເປັນຜົນຜະລິດຂອງສະຖານທີ່ທີ່ດີຜິດປົກກະຕິແຫ່ງດຽວ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ຂໍ້ມູນການປະເມີນຂະບວນການຄືສິ່ງທີ່ລະບົບສົ່ງມອບຢູ່ໃນຕຳແໜ່ງດີທີ່ຈະເກັບ: ການເຂົ້າຮ່ວມທຽບກັບແຜນ, ປະລິມານຊຸດ ແລະ ການຫຼຸດອອກໃນແຕ່ລະຂັ້ນຕອນຂອງຟັນເນວການສົ່ງຕໍ່ ຫຼື ການລົງທະບຽນ — ການວິເຄາະຟັນເນວດຽວກັນທີ່ວິສະວະກອນສ້າງໃຫ້ຄຸນສົມບັດຜະລິດຕະພັນຢູ່ແລ້ວ ແຕ່ນຳໄປໃຊ້ກັບທໍ່ການສົ່ງມອບຂອງໂຄງການສັງຄົມແທນ. ການສົ່ງຕົວຊີ້ວັດຄວາມຊື່ສັດ ແລະ ການເຂົ້າເຖິງໃຫ້ຜູ້ຈັດການໂຄງການໃນເວລາເກືອບຈິງ ແທນທີ່ຈະລໍການປະເມີນເມື່ອສິ້ນສຸດທຶນ ຊ່ວຍໃຫ້ແກ້ເສັ້ນທາງການສົ່ງຕໍ່ທີ່ເສຍໄດ້ກາງໂຄງການ ແທນທີ່ຈະຄົ້ນພົບພຽງເມື່ອໄລຍະທຶນສິ້ນສຸດ. ເບິ່ງ [ວິທີການປະເມີນຜົນກະທົບ](../ວິທີການປະເມີນຜົນກະທົບ/) ສຳລັບການອອກແບບເຊີງສາເຫດທີ່ການປະເມີນຂະບວນການຈັບຄູ່, [ທິດສະດີແຫ່ງການປ່ຽນແປງ](../ທິດສະດີການປ່ຽນແປງ/) ແລະ [ແບບຈຳລອງຕັກກະ](../ແບບຈຳລອງເຫດຜົນ/) ສຳລັບການອອກແບບທີ່ການປະເມີນຂະບວນການກວດຄວາມຊື່ສັດ ແລະ [ການຮັບຮູ້ຜົນປະໂຫຍດ](../ການຮັບຮູ້ຜົນປະໂຫຍດໃຫ້ເປັນຈິງ/) ສຳລັບການຕິດຕາມການສົ່ງມອບຈົນເຖິງຜົນລັບທີ່ສັນຍາໄວ້.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ວ່າຈ້າງສະເພາະການປະເມີນຜົນກະທົບ.** ຜົນທີ່ເປັນສູນ ຫຼື ອ່ອນຈະຕີຄວາມໝາຍເປັນຄວາມລົ້ມເຫຼວຂອງທິດສະດີ ຫຼື ຄວາມລົ້ມເຫຼວຂອງການປະຕິບັດບໍ່ໄດ້ ເຊິ່ງເປັນຄວາມແຕກຕ່າງທີ່ສຳຄັນສຳລັບການຕັດສິນໃຈວ່າຈະເຮັດຫຍັງຕໍ່.
- **ຖືການປະເມີນຂະບວນການເປັນສ່ວນເສີມອ່ອນໆ.** ມັນຕ້ອງການຄວາມເຂັ້ມງວດ ແລະ ເກນຄວາມຊື່ສັດທີ່ກຳນົດໄວ້ລ່ວງໜ້າເທົ່າກັບການອອກແບບຜົນກະທົບ ບໍ່ດັ່ງນັ້ນມັນຈະຫຍໍ້ເປັນເລື່ອງເລົ່າເມື່ອຜົນອອກມາ.
- **ສັບສົນ "ທັນເວລາ ແລະ ຢູ່ໃນງົບ" ກັບ "ສົ່ງມອບຕາມທີ່ອອກແບບ".** ການປະເມີນຂະບວນການກວດຄວາມຊື່ສັດຕໍ່ແບບຈຳລອງ — ປະລິມານ, ກຸ່ມເປົ້າໝາຍ, ເນື້ອຫາ — ບໍ່ແມ່ນສະຖານະ RAG ຂອງການຈັດການໂຄງການ.
- **ບໍ່ລົງທະບຽນຂີດຄວາມຊື່ສັດລ່ວງໜ້າ.** ການຕັດສິນພາຍຫຼັງວ່າຫຍັງນັບເປັນ "ປະລິມານທີ່ພຽງພໍ" ເຮັດໃຫ້ຄຳອະທິບາຍຜົນກະທົບທີ່ໜ້າຜິດຫວັງໃດໆເບິ່ງຄືການສ້າງຂໍ້ແກ້ຕົວຫຼັງເຫດການ.
