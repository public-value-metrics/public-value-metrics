# બહુ-માપદંડ નિર્ણય વિશ્લેષણ (MCDA)

MCDA એક સાથે અનેક અલગ, ભારિત માપદંડો સામે વિકલ્પોને ગુણ આપે છે અને તોલે છે, અને દરેક માપદંડને એક જ નાણાકીય કે કુદરતી એકમમાં ઢાળ્યા વગર ક્રમાંકિત સરખામણી આપે છે. જ્યાં મહત્વના પરિણામોને ખરેખર એક જ સંખ્યામાં ઘટાડી શકાતા નથી તેવા નિર્ણયો માટેની તે મૂલ્યાંકન પદ્ધતિ છે.

## તે શા માટે મહત્વનું છે

Green Book (બ્રિટિશ સરકારની મૂલ્યાંકન માર્ગદર્શિકા) સ્પષ્ટપણે MCDA ને માન્યતા આપે છે (તેના Box 2 કેસ-સ્ટડી પરિશિષ્ટ અને Annex A બંનેમાં તેની સીધી ચર્ચા છે) એવા મૂલ્યાંકનો માટે જ્યાં લાભો "ખરેખર અતુલ્ય (incommensurable)" હોય, એટલે કે જ્યાં [સામાજિક ખર્ચ-લાભ વિશ્લેષણ](../સામાજિક-ખર્ચ-લાભ-વિશ્લેષણ/) દ્વારા બધું નાણાંમાં, અથવા [ખર્ચ-અસરકારકતા વિશ્લેષણ](../સરકારમાં-ખર્ચ-અસરકારકતા-વિશ્લેષણ/) દ્વારા એક જ પરિણામમાં ફેરવવાથી નિર્ણય સ્પષ્ટ થવાને બદલે ખોટો ચિતરાય
(<https://www.gov.uk/government/publications/the-green-book-appraisal-and-evaluation-in-central-government>).
દાખલા તરીકે, નવી જેલ માટે સ્થળ પસંદ કરવામાં મૂડી ખર્ચ, સમુદાય પરની અસર, પરિવહન જોડાણ, પર્યાવરણીય અસર અને સ્ટાફની ભરતીક્ષમતા વચ્ચે સમતોલન કરવું પડે છે. આ માપદંડોનું કોઈ સામાન્ય એકમ નથી, અને સામાન્ય એકમ (સામાન્ય રીતે નાણાં) લાદવાથી, ઉદાહરણ તરીકે, પર્યાવરણીય અસર અને ખર્ચના સાપેક્ષ મહત્વ વિશેનો મૂલ્ય-નિર્ણય, ઉદ્દેશ્યલક્ષી ગણિતના વેશમાં ચૂપચાપ અંદર ઘૂસી જાય છે.

MCDA ની પ્રામાણિકતા જ તેની મુખ્ય નબળાઈ પણ છે: કારણ કે ભાર મૂલ્યાંકન કરનાર (અથવા પૅનલ) નક્કી કરે છે, પદ્ધતિ એટલી જ વાજબી છે જેટલી ભાર નક્કી કરવાની પ્રક્રિયા. Green Book માર્ગદર્શન સ્પષ્ટ છે કે માપદંડો અને ભાર વિકલ્પોને ગુણ અપાય તે *પહેલાં* નક્કી અને પ્રકાશિત થવા જોઈએ, જેથી કોઈ સમીક્ષક પસંદગીના વિકલ્પથી પાછળ જઈને તેને યોગ્ય ઠેરવતા ભાર ન ગોઠવી શકે.

## ગણિત

```
For each option i and criterion j:
  Score_ij   = the option's performance against that criterion (often 0-100
               or 1-10, from evidence, expert judgement, or stakeholder scoring)
  Weight_j   = relative importance of criterion j, weights sum to 1 (or 100)

Weighted score of option i = Σ_j (Score_ij × Weight_j)

Procedure:
1. Agree the criteria set and weights BEFORE scoring any option (swing
   weighting or pairwise comparison, e.g. AHP, are common elicitation methods).
2. Score every option against every criterion on a common scale, from
   evidence where possible.
3. Compute weighted totals; rank options.
4. Sensitivity-test the weights: does the ranking survive plausible
   disagreement about how much each criterion should matter?
```

SCBA ના ચોખ્ખા વર્તમાન મૂલ્યની જેમ MCDA કોઈ સમર્થનીય નિરપેક્ષ મૂલ્ય આપતું નથી; તે માત્ર સંમત ભાર પર આધારિત ક્રમાંક આપે છે. જ્યારે નિર્ણય ખરેખર અતુલ્ય ચીજોની અદલાબદલીનો હોય ત્યારે આ ખૂબી છે, અને જ્યાં નાણાંમાં રૂપાંતર ખરેખર શક્ય હતું ત્યાં એ કઠિન કામ ટાળવા માટે વપરાય ત્યારે ખામી છે.

## ઉદાહરણ સાથે ગણતરી

**સ્થાનિક સત્તામંડળ**: ઘરેલુ કચરા રિસાયક્લિંગ કેન્દ્ર માટે સ્થળ પસંદ કરતી એક નગર પરિષદ, કોઈ પણ સ્થળ-મુલાકાત પહેલાં આંતર-વિભાગીય પૅનલ દ્વારા ભાર નક્કી કરીને, ત્રણ સ્થળોને ચાર માપદંડો સામે ગુણ આપે છે:

```
Criteria (weight):        Capital cost (30%)  Transport access (25%)
                           Community impact (25%)  Environmental impact (20%)

Site scores (0-100, higher = better):
Site A: cost 80, access 60, community 40, environment 70
Site B: cost 60, access 90, community 70, environment 50
Site C: cost 90, access 50, community 80, environment 60

Weighted totals:
Site A = 80(.30) + 60(.25) + 40(.25) + 70(.20) = 24+15+10+14 = 63
Site B = 60(.30) + 90(.25) + 70(.25) + 50(.20) = 18+22.5+17.5+10 = 68
Site C = 90(.30) + 50(.25) + 80(.25) + 60(.20) = 27+12.5+20+12 = 71.5
```

સ્થળ C સૌથી ઉપર આવે છે. સમુદાય-અસરનો ભાર 25% થી 35% કરતી (મૂડી ખર્ચમાંથી 10 પૉઇન્ટ લઈને) સંવેદનશીલતા ચકાસણી સ્થળ C નો કુલ 71.5 − 3 + 8 = 76.5 અને સ્થળ B નો 68 − 6 + 7 = 69 કરે છે. સ્થળ C હજુ આગળ છે, એટલે ભારની બાબતમાં આ વાજબી મતભેદ સામે ક્રમાંક ટકી રહે છે, અને Green Book બરાબર આ જ ચકાસણીનો અહેવાલ જોવા માગે છે.

**સખાવતી સંસ્થા**: દેવા-સલાહ સેવા, ફૂડ બૅન્ક નેટવર્ક અને નાણાકીય-સાક્ષરતા કાર્યક્રમ વચ્ચે ભંડોળ ફાળવવા માંગતું એક અનુદાન-દાતા ફાઉન્ડેશન SROI (જુઓ [સામાજિક રોકાણ પર વળતર](../સામાજિક-રોકાણ-પર-વળતર/)) ને બદલે MCDA વાપરે છે, કારણ કે ટ્રસ્ટીઓ સદ્ભાવનાથી એ બાબતે અસહમત છે કે સંકટ-રાહતને વધુ ભાર મળવો જોઈએ કે નિવારણને. MCDA તેમને મતભેદનો *આકાર* (ભારની શ્રેણી) પર સહમત થવા દે છે, એક જ SROI ગુણોત્તર તેનો ઉકેલ લાવે છે એવો ડોળ કર્યા વગર.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

જ્યારે માપદંડો ખરેખર એકબીજા સાથે ટકરાય ત્યારે વિક્રેતા અને આર્કિટેક્ચરની પસંદગી માટે MCDA સ્વાભાવિક સાધન છે. ક્લાઉડ-હોસ્ટેડ અને ઓન-પ્રેમિસિસ કેસ મેનેજમેન્ટ સિસ્ટમ વચ્ચે પસંદગી કરવામાં ખર્ચ, ડેટા-સાર્વભૌમત્વનું જોખમ, સુલભતા અને ડિલિવરીની ઝડપ વચ્ચે એવી અદલાબદલી છે જે એક જ સંખ્યામાં સમાતી નથી. એન્જિનિયરિંગ લીડે આગ્રહ રાખવો જોઈએ કે ભાર વિકલ્પોને ગુણ અપાય તે પહેલાં નક્કી થાય, જેમ Green Book માગે છે, કારણ કે શૉર્ટલિસ્ટ જોયા પછી કરાયેલી ભાર-કસરત અચૂક તે વિકલ્પ તરફ ઢળે છે જે સભાખંડને પહેલેથી ગમતો હોય. MCDA ના સામાન્ય ઉપયોગ માટે [સરકારમાં બનાવવું કે ખરીદવું](../સરકારમાં-બનાવવું-કે-ખરીદવું/) જુઓ, અને નિર્ણય *પહેલાં* નહીં પણ *પછી* વપરાતા સંબંધિત માળખાગત ગુણાંકન સાધન માટે [જાહેર મૂલ્ય સ્કોરકાર્ડ](../જાહેર-મૂલ્ય-સ્કોરકાર્ડ/) જુઓ.

## સામાન્ય ભૂલો

- **વિકલ્પો જોયા પછી ભાર નક્કી કરવા.** MCDA સાથે ચેડાં કરવાની, ઇરાદાપૂર્વક કે અજાણતાં, આ સૌથી સામાન્ય રીત છે; ગુણ આપતાં પહેલાં ભાર પ્રકાશિત કરો, અને તે કોણે નક્કી કર્યા તેની નોંધ રાખો.
- **ભારિત કુલને પાકી સંખ્યા ગણવી.** સંવેદનશીલતા વિશ્લેષણ ક્રમાંકની સ્થિરતા ન ચકાસે ત્યાં સુધી 71.5 વિરુદ્ધ 68 નો તફાવત આંકડાકીય રીતે અર્થપૂર્ણ નથી; ખોટી ચોકસાઈને બદલે શ્રેણીઓ જણાવો.
- **જ્યાં નાણાંમાં રૂપાંતર ખરેખર શક્ય હતું ત્યાં તેને ટાળવા MCDA વાપરવું.** જો મોટા ભાગના માપદંડોની વિશ્વસનીય કિંમત આંકી શકાતી હોય, તો [SCBA](../સામાજિક-ખર્ચ-લાભ-વિશ્લેષણ/) ને બદલે MCDA અપનાવવાથી મૂલ્યાંકન જે માહિતી વાપરી શકત તે ફેંકાઈ જાય છે.
- **એક પ્રભાવશાળી હિતધારકને બધા ભાર એકલા નક્કી કરવા દેવા.** Green Book ની સારી પ્રથા અપેક્ષા રાખે છે કે ભાર પ્રતિનિધિ પૅનલ પાસેથી મેળવાય, પ્રાયોજક નિયામક પાસેથી નહીં, જેથી મૂલ્યાંકન એ વ્યક્તિની પહેલેથી જે ઇચ્છા હતી તેને ફરી તારવી ન કાઢે.
