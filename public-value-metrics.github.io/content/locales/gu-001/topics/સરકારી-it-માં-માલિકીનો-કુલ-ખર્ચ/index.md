# સરકારી IT માં માલિકીનો કુલ ખર્ચ (TCO)

માલિકીનો કુલ ખર્ચ (Total Cost of Ownership) એ સિસ્ટમનો સંપૂર્ણ જીવનચક્ર ખર્ચ છે — પ્રાપ્તિ વત્તા તેને ચલાવવાનું દરેક વર્ષ — સામાન્ય તારીખે ડિસ્કાઉન્ટ કરેલો. સરકારી IT માં, સૌથી વિશ્વસનીય આગાહી ભૂલ એ છે કે પુરવઠાકારો કે વિકલ્પોની સરખામણી ફક્ત પ્રાપ્તિ કિંમત પર થાય, જ્યારે સંચાલન અને જાળવણી સામાન્ય રીતે જીવનકાળના બિલના અડધાથી ચાર-પાંચમા ભાગ વચ્ચે હોય છે.

## તે શા માટે મહત્વનું છે

HM Treasury ની Green Book માગે છે કે કોઈપણ Five Case Model બિઝનેસ કેસમાં નાણાકીય કેસ ફક્ત મૂડી ખર્ચ નહીં પણ સમગ્ર-જીવન ખર્ચને આવરે — છતાં National Audit Office ને વારંવાર જણાયું છે કે વિભાગો અધૂરા કે આશાવાદી ચાલુ-ખર્ચ અનુમાન સામે IT રોકાણો મંજૂર કરે છે, અને સિસ્ટમ જીવંત થઈ જાય અને મૂડી બજેટ રેખા બંધ થઈ જાય પછી સાચો સંચાલન ખર્ચ શોધે છે. Government Digital Service અને Central Digital and Data Office નો Technology Code of Practice (<https://www.gov.uk/guidance/the-technology-code-of-practice>) વિભાગોને ક્લાઉડ અને કોમોડિટી હોસ્ટિંગ તરફ ધકેલે છે, અંશતઃ એટલા માટે કે તે ચાલુ ખર્ચ દૃશ્યમાન અને સરખાવી શકાય તેવો બનાવે છે, એક જ મૂડી પ્રાપ્તિ આંકડામાં દટાયેલો નહીં, જે મંજૂરી વખતે આકર્ષક રીતે નીચો દેખાય અને ત્રણ વર્ષ પછી ખર્ચાળ રીતે ખોટો ઠરે.

## ગણિત

```
TCO = પ્રાપ્તિ ખર્ચ + Σ(t=1..N) વાર્ષિક સંચાલન ખર્ચ_t / (1+r)^t
      − અવશિષ્ટ મૂલ્ય (ડિસ્કાઉન્ટ કરેલ)

r = HM Treasury Green Book નો પ્રમાણભૂત સામાજિક ડિસ્કાઉન્ટ દર, 3.5%/વર્ષ
    (30 વર્ષથી આગળના સમયક્ષિતિજ માટે ઘટતા દરની સૂચિ)

સંચાલન ખર્ચના ઘટકો: હોસ્ટિંગ/લાઇસન્સિંગ, સપોર્ટ અને જાળવણી,
સુરક્ષા પૅચિંગ અને અનુપાલન, સ્ટાફ સમય, આયોજિત રિફ્રેશ/સ્થળાંતર
```

સામાન્ય 5–10 વર્ષના સિસ્ટમ આયુષ્યમાં ડિસ્કાઉન્ટ ગુણક શા માટે મહત્વનો છે તે માટે જુઓ [સામાજિક ડિસ્કાઉન્ટ દર](../સામાજિક-ડિસ્કાઉન્ટ-દર/), અને TCO બનાવવા-વિરુદ્ધ-ખરીદવાના નિર્ણયને કેવી રીતે પોષે છે તે માટે [સરકારમાં બનાવવું વિરુદ્ધ ખરીદવું](../સરકારમાં-બનાવવું-કે-ખરીદવું/).

## ઉદાહરણ સાથે ગણતરી

એક વિભાગ Green Book ના 3.5% ડિસ્કાઉન્ટ દરે 5-વર્ષના સમયક્ષિતિજ પર બે કેસ-મેનેજમેન્ટ સિસ્ટમોની સરખામણી કરે છે.

```
સિસ્ટમ A: capex £3,500,000, opex £250,000/વર્ષ
સિસ્ટમ B: capex £1,800,000 (સસ્તી દેખાય છે), opex £650,000/વર્ષ
          (ભારે વેન્ડર સપોર્ટ અને ઇન્ટિગ્રેશન બોજ)

ફક્ત capex પર ભોળપણભરી સરખામણી: B જીતે છે, £1.8M < £3.5M.

ડિસ્કાઉન્ટ ગુણક સરવાળો, 3.5% એ 5 વર્ષ: 0.966+0.934+0.902+0.871+0.842 ≈ 4.515

TCO_A = 3,500,000 + 250,000 × 4.515 = 3,500,000 + 1,128,750 = £4,628,750
TCO_B = 1,800,000 + 650,000 × 4.515 = 1,800,000 + 2,934,750 = £4,734,750
```

TCO ભોળપણભર્યા નિર્ણયને પલટાવે છે: સંચાલન ખર્ચને ડિસ્કાઉન્ટ કરીને ઉમેરતાં સિસ્ટમ B પાંચ વર્ષમાં સહેજ વધુ ખર્ચાળ બને છે, કારણ કે જીવનકાળ ખર્ચમાં તેનો opex હિસ્સો 62% (2,934,750 / 4,734,750) છે જ્યારે સિસ્ટમ A નો 24% — "જાળવણી બિલનો મોટો ભાગ છે" તારણનું નક્કર ઉદાહરણ, જે સ્ટીકર કિંમતોની સરખામણીમાં સંપૂર્ણપણે છુપાયેલું રહે છે.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

TCO એ આંકડો છે જેણે દરેક [બનાવવું વિરુદ્ધ ખરીદવું](../સરકારમાં-બનાવવું-કે-ખરીદવું/) નિર્ણય અને દરેક [ટેક્નિકલ ડેટ](../જાહેર-મૂલ્યના-ધોવાણ-તરીકે-ટેક્નિકલ-ડેટ/) ચુકવણી કેસને શિસ્ત આપવી જોઈએ, કારણ કે ડેટનું વ્યાજ અને મુલતવી જાળવણી બંને સંચાલન-ખર્ચ રેખાઓ છે જે એ જ ડિસ્કાઉન્ટ કરેલા કુલમાં આવે છે, ભલે કોઈએ તેમને ટ્રૅક કર્યા હોય કે નહીં. પ્લેટફોર્મ કે વેન્ડરની પસંદગી પ્રસ્તાવિત કરતા એન્જિનિયરોએ પ્રાપ્તિ કિંમત નહીં, સંપૂર્ણ TCO કોષ્ટક રજૂ કરવું જોઈએ, કારણ કે પ્રાપ્તિ કિંમત એ જ આંકડો છે જેના પર એકલા આધાર રાખવાથી વિભાગોને રોકવા Green Book નો નાણાકીય કેસ રચાયો હતો. TCO [નાણાં માટે મૂલ્ય](../નાણાં-માટે-મૂલ્ય/) ના નિર્ણયો માટે પણ પ્રામાણિક છેદ છે — VFM લાભની ખર્ચ સાથે સરખામણી કરે છે, અને ઓછો ગણેલી ખર્ચ રેખા બિઝનેસ કેસમાંના દરેક VFM ગુણોત્તરને ફુલાવે છે.

## સામાન્ય ભૂલો

- **ફક્ત capex ની સરખામણી**: સૌથી સામાન્ય ખરીદી ભૂલ — દરેક વિકલ્પ માટે મેળ ખાતા સંચાલન-ખર્ચ અનુમાન વિના પુરવઠાકારોની યાદી કિંમતોની સરખામણી.
- **બહાર નીકળવાના અને સ્થળાંતર ખર્ચ બાકાત રાખવા**: કરારના અંતે ડેટા કાઢવો, ફરીથી પ્લેટફોર્મ બદલવું, અને વેન્ડર લૉક-ઇન દંડ વાસ્તવિક TCO રેખાઓ છે જે મૂળ બિઝનેસ કેસમાં ભાગ્યે જ દેખાય છે.
- **સુરક્ષા અને અનુપાલન ખર્ચ બાકાત રાખવો**: પૅચિંગ ગતિ, માન્યતા નવીનીકરણ અને ઑડિટ ખર્ચ સિસ્ટમની ઉંમર અને જટિલતા સાથે વધે છે — જુઓ [જાહેર ક્ષેત્રની સાયબર સુરક્ષાનું મૂલ્ય](../જાહેર-ક્ષેત્રની-સાયબર-સુરક્ષાનું-મૂલ્ય/) — અને opex અનુમાનમાંથી નિયમિત રીતે છૂટી જાય છે.
- **જુદી ખર્ચ રૂપરેખાવાળા વિકલ્પો વચ્ચે ડિસ્કાઉન્ટ વિનાની સરખામણી**: capex-ભારે વિકલ્પને opex-ભારે વિકલ્પ સાથે ડિસ્કાઉન્ટિંગ વિના સરખાવવાથી જે વિકલ્પ વધુ ખર્ચ પાછળનાં વર્ષોમાં ધકેલે છે તેની વ્યવસ્થિત તરફેણ થાય છે.
