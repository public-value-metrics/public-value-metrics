# સેવા ધોરણો અને વ્યવહાર માપદંડો

GOV.UK Service Standard એ બ્રિટિશ સરકારની જાહેર ડિજિટલ સેવા બનાવવા અને ચલાવવા માટેની 14-મુદ્દાની ચેકલિસ્ટ છે, અને તેની સાથે નાના, ફરજિયાત માત્રાત્મક વ્યવહાર માપદંડોનો સમૂહ જોડાયેલો છે: વ્યવહાર દીઠ ખર્ચ, પૂર્ણતા દર, ડિજિટલ અપનાવણી અને વપરાશકર્તા સંતોષ, જે દરેક લાઇવ કેન્દ્ર-સરકારી સેવા માટે ટીમોએ પ્રકાશિત કરવા ફરજિયાત છે. ધોરણ અને માપદંડો સાથે મળીને આ રિપોઝિટરીના વ્યાપક જાહેર મૂલ્ય અને KPI માળખાઓનું કાર્યસંચાલન-સ્તરનું, રોજિંદું વિશેષીકરણ છે, જેનું લક્ષ્ય સીધું સૉફ્ટવેર ડિલિવરી ટીમો છે.

## તે શા માટે મહત્વનું છે

GOV.UK ના service manual માં જાળવાતું Service Standard સરકારી ડિજિટલ સેવાના દરેક સમય-બિંદુ મૂલ્યાંકન (alpha, beta, live) માટે જરૂરી બનાવે છે કે તેના 14 મુદ્દાઓમાં એ દર્શાવાય કે ટીમ વપરાશકર્તાઓની જરૂરિયાતો સમજે છે, બહુ-શાખાકીય ટીમમાં કામ કરે છે, વારંવાર પુનરાવર્તન અને સુધારો કરે છે, અને *સાધનો, સિસ્ટમો અને કામ કરવાની રીતોનું મૂલ્યાંકન કરે છે*. ઐતિહાસિક રીતે આ જાહેર Performance Platform સાથે ચાલતું હતું જ્યાં દરેક લાઇવ સેવા પોતાનો વ્યવહાર ડેટા ખુલ્લી રીતે પ્રકાશિત કરતી; તે પ્લેટફોર્મ હવે બંધ થયું છે, પણ આ ચાર મુખ્ય માપદંડો માપવા અને પ્રકાશિત કરવાની મૂળ ફરજ service manual ના "measuring success" માર્ગદર્શન મારફતે ટકી છે. સામાન્ય સૉફ્ટવેર KPI ડૅશબોર્ડથી આ અલગ છે કારણ કે આ માપદંડો ચાર સ્વતંત્ર સ્કોર નહીં પણ એક જોડાયેલા આર્થિક મૉડલ તરીકે સ્પષ્ટ રીતે ડિઝાઇન કરાયા હતા: ડિજિટલ સરકાર માટે સમગ્ર બચતનો કેસ (Government Digital Service ના Digital Efficiency Report એ તુલનાત્મક સ્થાનિક-સરકારી સેવાઓ માટે ડિજિટલ વ્યવહારો ફોન કરતાં આશરે 20 ગણા સસ્તા અને રૂબરૂ કરતાં આશરે 50 ગણા સસ્તા શોધ્યા) ત્યારે જ સાકાર થાય છે જ્યારે પૂર્ણતા દર ઊંચો રહે અને ડિજિટલ અપનાવણી ખરેખર વધે, નહીં કે અપરિવર્તિત ખર્ચાળ ચૅનલની બાજુમાં માત્ર સસ્તી ચૅનલ ઉમેરાય.

## ગણિત

```
Cost per transaction = total service running cost / number of completed transactions
Completion rate       = transactions completed / transactions started × 100
Digital take-up       = digital-channel transactions / all-channel transactions × 100
User satisfaction     = % satisfied + very satisfied, in-service 5-point survey

Channel-shift saving = transaction volume × take-up shift × (cost per transaction on
                        the old channel − cost per transaction digitally)

Failure-demand cost = (1 − completion rate) × transactions attempted digitally ×
                        cost of the fallback channel those users then use instead
```

## ઉદાહરણ સાથે ગણતરી

**ઉદાહરણરૂપ કેન્દ્ર-સરકારી લાઇસન્સ-નવીકરણ સેવા**, વર્ષે 20 લાખ વ્યવહારો (2 million), હાલમાં 65% ફોન (£3.00/વ્યવહાર) અને 35% ડિજિટલ (£0.30/વ્યવહાર), પૂર્ણતા દર 80%. 14-મુદ્દાના Service Standard સામે પુનઃડિઝાઇન ડિજિટલ અપનાવણીને 60% અને પૂર્ણતાને 92% સુધી વધારે છે:

```
Take-up shift saving = 2,000,000 × 0.25 × (3.00 − 0.30) = £1,350,000/year

Failure-demand cost, before:
  2,000,000 × 0.35 × (1 − 0.80) × £3.00 = £420,000/year (abandoners fall back to phone)

Failure-demand cost, after:
  2,000,000 × 0.60 × (1 − 0.92) × £3.00 = £288,000/year

Net failure-demand saving = £420,000 − £288,000 = £132,000/year

Total annual saving ≈ £1,350,000 + £132,000 = £1,482,000/year
```

ગણિત સ્પષ્ટ કરે છે કે પૂર્ણતા દર ગૌણ માપદંડ કેમ નથી: 80% થી 92% ના સુધારા વગર, અપનાવણી-શિફ્ટ બચતનો ભાગ નિષ્ફળતા-માગ દ્વારા પાછો ખેંચાઈ જશે, જે નિરાશ ડિજિટલ વપરાશકર્તાઓને સીધા ખર્ચાળ ફોન ચૅનલમાં પાછા મોકલે છે.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

આ ચાર માપદંડો ખર્ચ-પરિણામ ડૅશબોર્ડનું કાર્યરત ઉદાહરણ છે: એક ખર્ચ માપદંડ ત્રણ પરિણામ/ગુણવત્તા માપદંડોથી અલગ રાખેલો છે, ઇરાદાપૂર્વક ક્યારેય એક સ્કોરમાં ન સંકેલાયેલો. આ જ શિસ્તની [જાહેર ક્ષેત્રના KPI](../જાહેર-ક્ષેત્રના-મુખ્ય-કામગીરી-સૂચકો/) માં હિમાયત છે. એન્જિનિયરો માટે આ નક્કર, માલિકી ધરાવી શકાય તેવા કામમાં વહેંચાય છે: પૂર્ણતા દર ફનલ-ઇન્સ્ટ્રુમેન્ટેશનની સમસ્યા છે, અને પ્રવાસમાં દરેક છોડી દેવાનું બિંદુ સિદ્ધાંતમાં શોધી અને સુધારી શકાય છે; વ્યવહાર દીઠ ખર્ચ માટે સાચા એકમ-ખર્ચ હિસાબીકરણની જરૂર છે જેમાં સ્ટાફ-સહાયિત અને કાગળ-ચૅનલ ખર્ચ સામેલ હોય, ફક્ત ક્લાઉડ હોસ્ટિંગ ખર્ચ નહીં (જુઓ [વ્યવહાર દીઠ ખર્ચ](../પ્રતિ-વ્યવહાર-ખર્ચ/) અને [સરકારી IT માં માલિકીનો કુલ ખર્ચ](../સરકારી-it-માં-માલિકીનો-કુલ-ખર્ચ/)); અને ડિજિટલ અપનાવણી એ કાર્યક્ષમતાનો પોશાક પહેરેલો સમાનતા માપદંડ છે, કારણ કે જે નાગરિકો ચૅનલ બદલી શકતા નથી કે બદલવા માગતા નથી તેઓ અપ્રમાણસર રીતે વૃદ્ધ, વિકલાંગ કે ડિજિટલ રીતે બાકાત છે, એટલે આક્રમક ચૅનલ બંધ કરવાથી "બચત" ઍક્સેસ-નુકસાનમાં ફેરવાય છે (જુઓ [ડિજિટલ સમાવેશ](../ડિજિટલ-સમાવેશ/) અને [ચૅનલ શિફ્ટ બચત](../ચૅનલ-શિફ્ટ-બચત/)). 14-મુદ્દાનું ધોરણ પોતે આ આંકડાઓ પાછળનું પ્રક્રિયા સ્પેસિફિકેશન છે. સંપૂર્ણ ધોરણ માટે [ડિજિટલ સેવા ધોરણ](../ડિજિટલ-સેવા-ધોરણ/) જુઓ, અને અહીંનો સંતોષ આંકડો વ્યાપક વિશ્વાસ માપન સાથે કેવી રીતે સંબંધિત છે તે માટે [નાગરિક સંતોષ માપદંડો](../નાગરિક-સંતોષ-મેટ્રિક્સ/) જુઓ.

## સામાન્ય ભૂલો

- **વૈકલ્પિક ચૅનલ બંધ કરીને મેળવેલી અપનાવણી**: ફોન લાઇન બંધ કરવાથી ડિજિટલ અપનાવણીની ટકાવારી ગાણિતિક રીતે વધે છે જ્યારે નિષ્ફળતા-માગ બાકી રહેલી ચૅનલ પર ઢસડાય છે (ઘણી વાર વધુ ખર્ચાળ સહાયિત-ડિજિટલ કે રૂબરૂ માર્ગ); હંમેશાં કુલ-પ્રણાલી ખર્ચ માપો, ફક્ત ગુણોત્તર નહીં.
- **ફનલના બીજા પગથિયાથી પૂર્ણતા દર માપવો**: "શરૂ થયેલા" ની ગણતરી પહેલા સાચા છોડી દેવાના બિંદુ પછી શરૂ કરવાથી પૂર્ણતા દર સારો દેખાય છે અને સૌથી મોટું સુધારી શકાય તેવું નુકસાન છુપાય છે.
- **સહાયિત-ડિજિટલ સહાય બાકાત રાખીને વ્યવહાર દીઠ ખર્ચ**: ફક્ત-ડિજિટલ એકમ ખર્ચ જે સ્વ-સેવા ન કરી શકતા વપરાશકર્તાઓને મદદ કરવામાં ગયેલા સ્ટાફ સમયને અવગણે છે તે ચૅનલનો સાચો ખર્ચ ઓછો આંકે છે.
- **સેવાઓ વચ્ચે વહેંચાયેલી વ્યાખ્યા વગર માપદંડો પ્રકાશિત કરવા**: "વ્યવહાર" અને "પૂર્ણ" અલગ સેવા ટીમોમાં જુદો અર્થ ધરાવે છે સિવાય કે વ્યાખ્યાઓ પ્રમાણિત અને વર્ઝનવાળી હોય, જેથી સેવાઓ વચ્ચેની સરખામણી ભરોસાપાત્ર રહેતી નથી.
