# ખુલ્લા ડેટાનું મૂલ્ય

ખુલ્લા ડેટાનું મૂલ્ય એ અંદાજ કાઢવાની સમસ્યા છે કે સરકારી અને જાહેર ડેટાની કિંમત શું છે જ્યારે તેની કોઈ કિંમત હોતી નથી: તે વેચાતો નથી, એટલે આવકની કોઈ લીટી નથી, છતાં તેને ખુલ્લો મૂકવાથી (હવામાનના રેકૉર્ડ, પરિવહન સમયપત્રક, પોસ્ટકોડની સીમાઓ, કંપની રજિસ્ટર) આગળના તબક્કે આર્થિક અને સામાજિક પ્રવૃત્તિ સ્પષ્ટપણે ઉત્પન્ન થાય છે. તેનું સારું મૂલ્યાંકન મહત્વનું છે કારણ કે "ખુલ્લો મૂકવો મફત છે" અને "તે નિરર્થક છે" બંને ખોટાં છે, અને API કે ડેટાસેટ ખુલ્લો મૂકવો કે નહીં તે નક્કી કરતા સૉફ્ટવેર એન્જિનિયરને બેમાંથી એક કરતાં વધુ સારી દલીલની જરૂર છે.

## તે શા માટે મહત્વનું છે

સૌથી વધુ ટાંકવામાં આવતો ઉપરથી-નીચેનો અંદાજ McKinsey Global Institute ના 2013 ના અહેવાલ "Open data: Unlocking innovation and performance with liquid information" નો છે, જેણે સાત ક્ષેત્રોમાં (શિક્ષણ, પરિવહન, ગ્રાહક ઉત્પાદનો, વીજળી, તેલ અને ગૅસ, આરોગ્ય સંભાળ અને ગ્રાહક નાણાં) ખુલ્લા ડેટાનું સંભવિત વાર્ષિક મૂલ્ય વિશ્વભરમાં વર્ષે $3 ટ્રિલિયન થી $5 ટ્રિલિયન મૂક્યું, જે પારદર્શિતા વધારવી, પુરવઠો અને માગ વધુ કાર્યક્ષમ રીતે મેળવવી, અને ડેટા પર બનેલાં નવાં ઉત્પાદનો અને સેવાઓને સક્ષમ કરવી જેવી પ્રક્રિયાઓ દ્વારા થાય. તે આંકડો પરિદૃશ્યનો અંદાજ છે, માપેલું પરિણામ નથી, અને ઘણી વાર એવી રીતે ખોટો ટાંકાય છે કે જાણે તે સરકાર સીધી મેળવી શકે તેવી આવક હોય, જ્યારે મૂલ્ય મોટે ભાગે ડેટા વાપરનારા ત્રીજા પક્ષોને (વ્યવસાયો, સંશોધકો, નાગરિકો) મળે છે, અને ડેટા વેચવાને બદલે ખુલ્લો મૂકવાનો ખરો હેતુ એ જ છે. બ્રિટનની Open Data Institute, જેની સહ-સ્થાપના 2012 માં Sir Tim Berners-Lee અને Sir Nigel Shadbolt એ કરી હતી, ત્યારથી ક્ષેત્ર દર ક્ષેત્ર, ડેટાસેટ દર ડેટાસેટ વધુ સૂક્ષ્મ, નીચેથી-ઉપરના કેસ સ્ટડીનો ભંડાર બનાવ્યો છે, જે વાસ્તવિક બિઝનેસ કેસ માટે McKinsey ના મથાળાના આંકડા કરતાં ઘણા વધુ ઉપયોગી છે, કારણ કે તે મૂલ્ય સર્જનની પ્રક્રિયા બતાવે છે, ફક્ત તેનું કુલ કદ નહીં.

## ગણિત

ખુલ્લા ડેટાની કોઈ બજાર કિંમત નથી, એટલે મૂલ્યાંકન પદ્ધતિઓ તેનું સ્થાન લે છે; ત્રણ અભિગમો વારંવાર આવે છે, અને એકલો કોઈ પણ પૂરતો નથી:

```
1. ટાળેલો ખર્ચ / પુનઃસ્થાપન-ખર્ચ પદ્ધતિ:
   મૂલ્ય ≈ વપરાશકર્તાઓએ સમકક્ષ ડેટા જાતે બનાવવા કે લાઇસન્સ પર
   લેવા માટે જે ચૂકવ્યું હોત — એ નીચલી સીમા છે, અને મૂળ
   ઉત્પાદકે ક્યારેય ધાર્યા ન હોય તેવા ઉપયોગોથી સર્જાયેલું મૂલ્ય
   તેમાં ગણાતું નથી

2. બજાર-સમાન / આગળની પ્રવૃત્તિ પદ્ધતિ:
   મૂલ્ય ≈ ડેટા પર બનેલા વ્યવસાયો/સેવાઓએ ઉત્પન્ન કરેલી આવક
   કે બચત (દા.ત. ખુલ્લા નકશા અને ટ્રાફિક ડેટા પર બનેલી
   સૅટનૅવ ઍપ) — વાસ્તવિક આર્થિક પ્રવૃત્તિને પકડે છે, પણ તેનો
   શ્રેય ડેટા ખુલ્લો મૂકવાને ચોખ્ખી રીતે આપવો અઘરો છે
   (જુઓ additionality-and-deadweight)

3. શરતી/જાહેર કરેલી-પસંદગી પદ્ધતિ:
   મૂલ્ય ≈ વપરાશકર્તાઓ ચૂકવવા તૈયાર છે એવું કહે તે, અથવા
   તેમનો જેટલો સમય બચે છે એવું તેઓ કહે તે — સામાન્ય
   પદ્ધતિ અને તેના પૂર્વગ્રહો માટે stated-preference-valuation જુઓ

આમાંથી કોઈ પણ બજાર કિંમત જેટલો ચોખ્ખો આંકડો આપતી નથી;
વિશ્વસનીય ખુલ્લા ડેટાના બિઝનેસ કેસ બે કે તેથી વધુ પદ્ધતિઓનો
ત્રિકોણીય મેળ બેસાડે છે, અને કઈ પ્રક્રિયા કામ કરે છે તે
સ્પષ્ટ જણાવે છે.
```

## ઉદાહરણ સાથે ગણતરી

**ઉદાહરણરૂપ રાષ્ટ્રીય નકશા/સરનામા ડેટાનું પ્રકાશન** (પદ્ધતિ ODI-શૈલીના કેસ સ્ટડી પરથી; આંકડા એવા અભ્યાસોમાં સામાન્ય રીતે મળતા કદનું ઉદાહરણ છે):

```
ટાળેલા ખર્ચનો અંદાજ:
  જે વ્યવસાયો અન્યથા સમકક્ષ સરનામા-મેળવણી ડેટા વ્યાવસાયિક
  ધોરણે લાઇસન્સ પર લેત, સરેરાશ લાઇસન્સ ખર્ચ અંદાજે £4,000/
  વર્ષ, અને હવે મફત ખુલ્લો ડેટાસેટ વાપરતા અંદાજે 15,000 SME
  = 15,000 × £4,000 = £60,000,000/વર્ષ ફક્ત ટાળેલા લાઇસન્સ ખર્ચમાં

આગળની પ્રવૃત્તિનો અંદાજ (વધુ અનુમાનાત્મક, પ્રતિતથ્ય જોઈએ):
  ખુલ્લા ડેટા પર બનેલાં નવાં ડિલિવરી-રૂટિંગ અને લૉજિસ્ટિક્સ
  ઉત્પાદનો જે તેના વગર અસ્તિત્વમાં ન હોત, અથવા નોંધપાત્ર રીતે
  નબળાં હોત — ડેટા બંધ કે વ્યાવસાયિક રીતે લાઇસન્સવાળો રહે એ
  પ્રતિતથ્ય સામે સરખામણી જરૂરી છે (counterfactual-analysis),
  કારણ કે તેમાંની કેટલીક પ્રવૃત્તિ ઊંચા ભાવે ચૂકવેલા ડેટા પર
  પણ થઈ જ હોત, જે "ખુલ્લો મૂકવાથી સર્જાયેલા મૂલ્ય"ના અર્થમાં
  ડેડવેઇટ છે

સમર્થનીય બિઝનેસ કેસ ટાળેલા ખર્ચના આંકડાને ઘન નીચલી સીમા
તરીકે જણાવે છે, અને આગળની પ્રવૃત્તિના આંકડાને હકીકત નહીં
પણ ઉપલી-સીમાના પરિદૃશ્ય તરીકે ગણે છે.
```

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

એન્જિનિયરો માટે, ખુલ્લા ડેટાના મૂલ્યનો વ્યવહારુ પ્રશ્ન સામાન્ય રીતે રાષ્ટ્રીય મથાળાના આંકડાઓ કરતાં સાંકડો હોય છે: શું આ ચોક્કસ API કે ડેટાસેટ ખુલ્લો મૂકવાથી (ભાગીદાર કરાર પાછળ રાખવાને બદલે) પુનઃઉપયોગ એટલો વધે છે કે તેને જાહેર ઇન્ટરફેસ તરીકે દસ્તાવેજીકરણ, વર્ઝનિંગ અને સપોર્ટ કરવાના સતત ખર્ચને યોગ્ય ઠેરવી શકાય? એ જાળવણી ખર્ચ વાસ્તવિક છે અને [government-as-a-platform](../પ્લૅટફૉર્મ-તરીકે-સરકાર/) ના એકવાર-બનાવો-વારંવાર-વાપરો અર્થશાસ્ત્રનો સમકક્ષ છે. બંને વિષયો નજીકના સગા છે, એક વહેંચાયેલા કોડ અને માળખા વિશે અને બીજો વહેંચાયેલા ડેટા વિશે. ખુલ્લા ડેટાના મૂલ્યનો કોઈ પણ દાવો બિઝનેસ કેસમાં જાય તે પહેલાં [additionality-and-deadweight](../વધારાપણું-અને-ડેડવેઇટ/) સામે ચકાસવો જોઈએ: જે પ્રવૃત્તિ વ્યાવસાયિક રીતે લાઇસન્સવાળા ડેટા પર પણ થઈ જ હોત તે મૂલ્ય *ખુલ્લો મૂકવાથી* સર્જાયું નથી.

## સામાન્ય ભૂલો

- **McKinsey ના $3–5 ટ્રિલિયનના આંકડાને બ્રિટન-વિશિષ્ટ તરીકે કે આ ડેટાસેટનો હિસ્સો ગણીને ટાંકવો**: તે 2013 નો વૈશ્વિક, સાત-ક્ષેત્રનો પરિદૃશ્ય અંદાજ છે; તેને એક રાષ્ટ્રીય ડેટાસેટ માટે ચોક્કસ ગુણક તરીકે વાપરવાથી આ સંખ્યા શું છે તે ખોટું દર્શાય છે.
- **પ્રતિતથ્ય નહીં**: ખુલ્લા ડેટા પર બનેલી બધી આગળની આર્થિક પ્રવૃત્તિનો શ્રેય લેવો, એ પૂછ્યા વગર કે તેમાંથી કેટલી પ્રવૃત્તિ ઊંચા ભાવે ચૂકવેલા કે લાઇસન્સવાળા ડેટા પર પણ થઈ જ હોત (જુઓ [additionality-and-deadweight](../વધારાપણું-અને-ડેડવેઇટ/) અને [counterfactual-analysis](../પ્રતિતથ્ય-વિશ્લેષણ/)).
- **ઉત્પાદન ખર્ચ અને સર્જાયેલા મૂલ્યને ગૂંચવવા**: જે ડેટાસેટ એકત્ર કરવો ખર્ચાળ હતો તે ખુલ્લો મૂકવા માટે આપોઆપ મૂલ્યવાન નથી, અને સસ્તો ડેટાસેટ આપોઆપ ઓછા મૂલ્યનો નથી. મૂલ્ય આગળના ઉપયોગને અનુસરે છે, પાછળના ખર્ચને નહીં.
- **"ખુલ્લા" ના સતત જાળવણી ખર્ચને અવગણવો**: એકવારનો CSV અર્ક પ્રકાશિત કરવો એ દસ્તાવેજીકૃત, વર્ઝનવાળું, સપોર્ટ કરાતું ખુલ્લું API ચલાવવા જેટલી પ્રતિબદ્ધતા નથી. લૉન્ચની જાહેરાત પછી બાદનું ઓછું ભંડોળ એ સામાન્ય નિષ્ફળતા છે.
