# અનુદાન પરિણામ અહેવાલ (IRIS+)

અનુદાન પરિણામ અહેવાલ (grant outcomes reporting) એ પ્રથા છે જેમાં અનુદાન મેળવનારાઓ ભંડોળદાતાઓને પ્રમાણિત, સરખાવી શકાય તેવા પરિણામ માપદંડો જણાવે છે — દરેક ભંડોળદાતા પોતાનું કસ્ટમ અહેવાલ ટેમ્પલેટ ઘડે તેના બદલે. Global Impact Investing Network (GIIN) દ્વારા જાળવાતું IRIS+ આવા ધોરણોમાં સૌથી વ્યાપક રીતે અપનાવાયેલું છે: પૂર્વવ્યાખ્યાયિત સામાજિક, પર્યાવરણીય અને નાણાકીય કામગીરી માપદંડોની સૂચિ, જે અસર રોકાણકારો અને, વધુને વધુ, અનુદાન આપતાં ફાઉન્ડેશનો અનુદાન મેળવનારાઓ પાસે વાપરવાની માગ કે ભલામણ કરે છે.

## તે શા માટે મહત્વનું છે

પ્રમાણિત અહેવાલ પહેલાં, દરેક ફાઉન્ડેશન અનુદાન મેળવનારાઓ પાસે જુદા ફોર્મેટમાં જુદા સૂચકો માગતું, અને દસ ભંડોળદાતાઓવાળી મધ્યમ કદની ચૅરિટી એકબીજા સાથે ઓવરલૅપ થતા કામ માટે દસ સમાંતર અહેવાલ પ્રક્રિયાઓ ચલાવતી હોઈ શકે — અહેવાલ બોજનું સુદસ્તાવેજી કારણ, જેને ઘટાડવા અનુદાન-પરિણામ પ્રમાણીકરણ અસ્તિત્વમાં છે. IRIS+ ભંડોળદાતાઓ અને અનુદાન મેળવનારાઓને સહિયારી શબ્દભંડોળ આપીને આને સંબોધે છે: વિષય પ્રમાણે જૂથબદ્ધ Core Metrics Sets (દા.ત. પરવડે તેવાં આવાસ, સ્વચ્છ ઊર્જાની પહોંચ, નાણાકીય સમાવેશ), દરેક માપદંડ એટલો ચોક્કસ વ્યાખ્યાયિત કે "સર્જાયેલી નોકરીઓ" કે "સેવા અપાયેલાં પરિવારો" કોઈ પણ અહેવાલ આપે તોય એક જ અર્થ ધરાવે, અને UN Sustainable Development Goals સાથે સંરેખિત, જેથી ભંડોળદાતા અનુદાન મેળવનારના સ્તરનો ડેટા પોર્ટફોલિયો-સ્તરની SDG કથા સુધી એકત્ર કરી શકે. GIIN જણાવે છે કે IRIS માપદંડો આશરે અડધા અસર રોકાણકારો અને આ ક્ષેત્રમાં સક્રિય મોટા ભાગના ફંડ મેનેજરો, બૅન્કો અને વિકાસ નાણાં સંસ્થાઓ વાપરે છે.

પ્રમાણીકરણ સૌથી વધુ ત્યાં મહત્વનું છે જ્યાં તે [પરિણામો વિરુદ્ધ આઉટપુટ](../આઉટકમ-વિરુદ્ધ-આઉટપુટ/) સાથે ભળે છે: IRIS+ અનુદાન મેળવનારની હાલની કેસ-વ્યવસ્થાપન પ્રણાલી જે કંઈ નોંધે તેના બદલે વ્યાખ્યાયિત પરિણામ અને અસર માપદંડો તરફ અહેવાલને દોરે છે, જે બરાબર એ તફાવત છે જે [પરિણામ દીઠ ખર્ચ](../પ્રતિ-પરિણામ-ખર્ચ/) વિરુદ્ધ [લાભાર્થી દીઠ ખર્ચ](../પ્રતિ-લાભાર્થી-ખર્ચ/) વર્ણવે છે.

## ગણિત

અનુદાન પરિણામ અહેવાલ માળખું અને પ્રક્રિયા છે, સૂત્ર નથી:

```
1. Funder selects a Core Metrics Set relevant to the grant's theme
   (e.g. IRIS+ "Financial Inclusion" or "Sustainable Agriculture")
2. Each metric has a fixed definition, unit, and calculation method
   published by GIIN — not invented per-funder
3. Grantee reports against the same metric definitions across all
   its funders using that standard, cutting duplicate reporting effort
4. Funder aggregates grantee-level metrics into portfolio-level reporting,
   comparable year over year and across grantees using the same metric
```

કાર્યક્ષમતા લાભ સંયોજનાત્મક છે: N ભંડોળદાતાઓ × M અનુદાન મેળવનારાઓને એક સહિયારી શબ્દભંડોળ પર પ્રમાણિત કરવાથી N×M કસ્ટમ અહેવાલ સંબંધો એક ધોરણ સામે આશરે N+M મેપિંગમાં ફેરવાય છે.

## ઉદાહરણ સાથે ગણતરી

**પ્રમાણીકરણ પહેલાં ત્રણ ભંડોળદાતાવાળો અનુદાન મેળવનાર**: ભંડોળદાતા 1ને માથાગણતરી વ્યાખ્યા સાથે "સેવા અપાયેલા લોકો", ભંડોળદાતા 2ને પરિવાર વ્યાખ્યા સાથે "પહોંચેલા લાભાર્થીઓ", અને ભંડોળદાતા 3ને સેવા-પ્રસંગ વ્યાખ્યા સાથે "અસર પામેલા વ્યક્તિઓ" જણાવે છે (એટલે બે વાર આવેલી એક વ્યક્તિ બે વાર ગણાય). ત્રણ અહેવાલ, ત્રણ સંખ્યા, કોઈ સરખાવી શકાય નહીં, અને એ જ ભંડોળદાતાના પોર્ટફોલિયોમાં પણ બીજા અનુદાન મેળવનારની સંખ્યાઓ સાથે સરખાવી શકાય નહીં.

**IRIS+ હેઠળ એ જ અનુદાન મેળવનાર**: સંબંધિત Core Metrics Setના વ્યાખ્યાયિત પરિણામ માપદંડ સાથે, વ્યાખ્યાયિત IRIS+ individuals-reached માપદંડ સામે અહેવાલ આપે છે, બંને માટે GIIN ની પ્રકાશિત ગણતરી પદ્ધતિ વાપરીને. ત્રણેય ભંડોળદાતાઓ હવે એ જ સંખ્યા, એ જ રીતે ગણેલી, મેળવે છે, અને આ અનુદાન મેળવનારનો IRIS+-વ્યાખ્યાયિત એકમ દીઠ ખર્ચ પોતાના પોર્ટફોલિયોના અન્ય અનુદાન મેળવનારાઓ સાથે સમાન માપદંડ વાપરીને સરખાવી શકે છે — અહેવાલ-માળખાના સ્કેલ પર, સહિયારા [એકમ ખર્ચ ડેટાબેઝ](../એકમ-ખર્ચ-ડેટાબેઝ/)ની સમકક્ષ.

## સૉફ્ટવેર એન્જિનિયરિંગ સાથે સંબંધ

અનુદાન વ્યવસ્થાપન પ્લૅટફૉર્મે IRIS+ માપદંડ ઓળખકર્તાઓને મુક્ત લખાણ નહીં, ફૉરેન કી ગણવા જોઈએ: અનુદાન મેળવનારના જણાવેલા મૂલ્ય સાથે પ્રકાશિત માપદંડ કોડ સંગ્રહવો ("beneficiaries" નામનું સ્થાનિક રીતે ઘડેલું ફીલ્ડ નહીં) એ જ છે જે પછી ડેટા-સફાઈ પ્રોજેક્ટ વિના ભંડોળદાતાઓ અને પોર્ટફોલિયો વચ્ચે એકત્રીકરણ શક્ય બનાવે છે. જ્યાં પ્લૅટફૉર્મે IRIS+ ન અપનાવેલા ભંડોળદાતાઓને ટેકો આપવો પડે, ત્યાં વ્યવહારુ ડિઝાઇન એ છે કે દરેક ભંડોળદાતાને તરત ધોરણ પર ધકેલવાને બદલે સ્થાનિક માપદંડને નજીકની IRIS+ વ્યાખ્યા સાથે મેપ કરવા દેવો — ગ્રાફનો વધુ ભાગ સહિયારા ઓળખકર્તાઓ પર મેપ થતાં સરખામણીક્ષમતા ક્રમશઃ સુધરે છે. એકત્ર થયા પછી જણાવેલી સંખ્યાઓ શું ગણવા વાપરવી તે માટે સહોદર વિષય [પરિણામ દીઠ ખર્ચ](../પ્રતિ-પરિણામ-ખર્ચ/) જુઓ.

## સામાન્ય ભૂલો

- **IRIS+ અપનાવવાને આપોઆપ સરખામણીક્ષમતા ગણવી.** બે અનુદાન મેળવનારાઓ એક જ IRIS+ માપદંડ સામે અહેવાલ આપે છતાં તેમના અંતર્ગત ડેટા ગુણવત્તા કે પ્રતિતથ્ય ધારણાઓ જુદી હોય તો સરખાવી શકાય નહીં; ધોરણ વ્યાખ્યાઓ નક્કી કરે છે, માપણીની કડકાઈ નહીં.
- **ભંડોળદાતાએ ઘડેલા "IRIS-સંરેખિત" માપદંડો.** જે માપદંડ માત્ર IRIS+ ભાષાથી પ્રેરિત હોય પણ વાસ્તવિક પ્રકાશિત વ્યાખ્યા ન હોય તે એ જ ખંડિતતાને પાછી લાવે છે જેને ઉકેલવા ધોરણ અસ્તિત્વમાં છે.
- **વધુ પડતી પસંદગીથી અહેવાલ થાક.** જ્યારે માત્ર બે-ત્રણ માપદંડ નિર્ણય-સંબંધિત હોય ત્યારે અનુદાન મેળવનાર પાસે આખા Core Metrics Set સામે અહેવાલ માગવો બોજની સમસ્યાને પ્રમાણિત આવરણમાં ફરી સર્જે છે.
- **કોઈ પરિણામ માપદંડ જ નહીં.** IRIS+માં ઘણા શુદ્ધ આઉટપુટ માપદંડો છે (દા.ત. સેવા અપાયેલા લોકોની ગણતરી); માત્ર તે પસંદ કરવા અને પરિણામ-સ્તરનો એક પણ નહીં, તે પરિણામ-અહેવાલના લેબલ હેઠળ [લાભાર્થી દીઠ ખર્ચ](../પ્રતિ-લાભાર્થી-ખર્ચ/)-આકારનો અહેવાલ આપે છે.
