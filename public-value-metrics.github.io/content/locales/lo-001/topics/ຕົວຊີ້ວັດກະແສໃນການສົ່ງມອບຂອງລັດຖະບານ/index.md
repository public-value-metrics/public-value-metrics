# ຕົວຊີ້ວັດກະແສໃນການສົ່ງມອບຂອງລັດຖະບານ

ຕົວຊີ້ວັດກະແສ (flow metrics) — ກົດຂອງ Little (Little's Law), ຂີດຈຳກັດງານທີ່ກຳລັງດຳເນີນ (WIP) ແລະ ປະສິດທິພາບກະແສ (flow efficiency) — ອະທິບາຍວ່າງານເຄື່ອນຜ່ານລະບົບທີ່ມີຄວາມຈຸຈຳກັດໄດ້ໄວປານໃດ. ກະດານ sprint ເປັນລະບົບດັ່ງກ່າວອັນໜຶ່ງ; ຄິວຄຳຮ້ອງຂໍເງິນຊ່ວຍເຫຼືອ, ທະບຽນຄຳຮ້ອງຂໍອະນຸຍາດກໍ່ສ້າງ ຫຼື ງານຄ້າງຂອງການພິຈາລະນາວີຊາ ລ້ວນແຕ່ເປັນຄະນິດສາດດຽວກັນທີ່ນຸ່ງເຄື່ອງແບບຕ່າງກັນ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ງານຄົງຄ້າງຂອງລັດຖະບານແມ່ນລະບົບຄິວ ແລະ ລະບົບຄິວປະຕິບັດຕາມກົດຂອງຄິວບໍ່ວ່າຈະມີໃຜວັດແທກຫຼືບໍ່. ໄລຍະເວລາການຕັດສິນຕາມກົດໝາຍເຮັດໃຫ້ເລື່ອງນີ້ຊັດເຈນ: ພາຍໃຕ້ລະບອບການວາງແຜນເມືອງ ແລະ ຊົນນະບົດ (Town and Country Planning) ຄຳຮ້ອງຂໍອະນຸຍາດກໍ່ສ້າງຂະໜາດນ້ອຍສ່ວນໃຫຍ່ມີເປົ້າໝາຍການຕັດສິນຕາມກົດໝາຍ 8 ອາທິດ ແລະ ຂະໜາດໃຫຍ່ 13 ອາທິດ — ຄຳໝັ້ນສັນຍາດ້ານເວລາວົງຈອນທີ່ຝັງຢູ່ໃນກົດໝາຍໂດຍກົງ. ງານຄົງຄ້າງຂອງກໍລະນີຂໍລີ້ໄພຂອງ Home Office ທີ່ National Audit Office ແລະ Home Affairs Select Committee ກວດກາຊ້ຳແລ້ວຊ້ຳອີກ ເປັນກໍລະນີທີ່ມີເອກະສານບັນທຶກດີຂອງລະບົບສາທາລະນະທີ່ງານທີ່ກຳລັງດຳເນີນເພີ່ມຂຶ້ນໄວກວ່າປະລິມານງານທີ່ສຳເລັດຢ່າງຕໍ່ເນື່ອງ ເຮັດໃຫ້ເວລາວົງຈອນເກີນກວ່າຄວາມຄາດຫວັງຕາມກົດໝາຍ ຫຼື ການບໍລິການຫຼາຍ. ຕົວຊີ້ວັດກະແສໃຫ້ວິສະວະກອນ ແລະ ຜູ້ຈັດການກໍລະນີມີຄຳສັບທີ່ໃຊ້ຮ່ວມກັນເປັນປະລິມານສຳລັບຮູບແບບຄວາມລົ້ມເຫຼວນີ້ພໍດີ ແທນທີ່ຈະປ່ອຍໃຫ້ເປັນ "ບັນຫາງານຄ້າງ" ແບບຄຸນນະພາບ.

## ຄະນິດສາດ

```
Little's Law:  WIP = Throughput × Cycle Time
           →   Cycle Time = WIP / Throughput

Flow efficiency = active (touch) time / total cycle time   (Vacanti)

WIP limit effect: for fixed throughput, halving WIP roughly halves
average cycle time (Little's Law rearranged) — the lever available
without adding headcount.
```

ເບິ່ງ [ຕົວຊີ້ວັດ DORA ສຳລັບຄຸນຄ່າສາທາລະນະ](../ຕົວຊີ້ວັດ-dora-ສຳລັບຄຸນຄ່າສາທາລະນະ/) ສຳລັບຄະນິດສາດທຽບເທົ່າທີ່ນຳໃຊ້ກັບທໍ່ນຳໃຊ້ຊອບແວ ແທນທີ່ຈະເປັນງານກໍລະນີ.

## ຕົວຢ່າງການຄິດໄລ່

**ພະແນກວາງແຜນຂອງອົງການປົກຄອງທ້ອງຖິ່ນ**: ມີ 400 ຄຳຮ້ອງເປີດຢູ່ໃນທຸກເວລາ (WIP) ທີມແກ້ໄຂໄດ້ 50 ຄຳຮ້ອງ/ອາທິດ (throughput).

```
Cycle time = WIP / Throughput = 400 / 50 = 8 weeks
```

ນັ້ນຕົກຢູ່ທີ່ເປົ້າໝາຍຕາມກົດໝາຍ 8 ອາທິດສຳລັບຄຳຮ້ອງຂະໜາດນ້ອຍພໍດີ — ໂດຍບໍ່ມີຊ່ອງຫວ່າງ ໝາຍຄວາມວ່າຄວາມຜັນແປໃດໆໃນຄວາມຕ້ອງການທີ່ເຂົ້າມາ ຫຼື ເວລາຕອບກັບຂອງຜູ້ໃຫ້ຄຳປຶກສາ (consultee) ຈະຜັກດັນການຕັດສິນເກີນກຳນົດຕາມກົດໝາຍ.

**ປະສິດທິພາບກະແສ**: ຈາກ 8 ອາທິດ (56 ວັນຕາມປະຕິທິນ) ນັ້ນ ຄຳຮ້ອງໜຶ່ງມັກມີເວລາປະມວນຜົນຈິງຂອງເຈົ້າໜ້າທີ່ກໍລະນີປະມານ 6 ຊົ່ວໂມງ.

```
Flow efficiency = 6 hours / (56 days × 8 working hours/day)
                = 6 / 448 ≈ 1.3%
```

ມາດຕະຖານອ້າງອີງຂອງ Vacanti ສຳລັບທີມຊອບແວກຳນົດປະສິດທິພາບກະແສປົກກະຕິທີ່ 15–20%; ງານກໍລະນີຂອງລັດຖະບານ ທີ່ມີການສົ່ງຕໍ່ໃຫ້ຜູ້ໃຫ້ຄຳປຶກສາຕາມກົດໝາຍຫຼາຍຄັ້ງ ແລະ ໄລຍະປຶກສາຫາລືສາທາລະນະ ມັກຕ່ຳກວ່າໜຶ່ງລຳດັບຂະໜາດ. 98.7% ຂອງເວລາ "ລໍຖ້າ" ແມ່ນບ່ອນທີ່ແປດອາທິດໃຊ້ໄປຈິງ — ບໍ່ແມ່ນໃນຄວາມສາມາດຂອງເຈົ້າໜ້າທີ່ກໍລະນີ.

**ການແຊກແຊງດ້ວຍຂີດຈຳກັດ WIP**: ການຈຳກັດຄຳຮ້ອງທີ່ເປີດຕໍ່ເຈົ້າໜ້າທີ່ກໍລະນີທີ່ 15 ແທນທີ່ຈະເປັນ 25 ໂດຍບໍ່ຈຳກັດ (ຮັກສາ throughput ຄົງທີ່) ປ່ຽນ WIP ຈາກ 400 ເປັນປະມານ 240 ໃນທີມ 16 ຄົນ:

```
New cycle time = 240 / 50 = 4.8 weeks
```

ເວລາວົງຈອນຫຼຸດລົງເກືອບເຄິ່ງໜຶ່ງຈາກການປ່ຽນນະໂຍບາຍ ບໍ່ແມ່ນການເພີ່ມບຸກຄະລາກອນ — ຄັນໂຍກດຽວກັນທີ່ທີມສົ່ງມອບແບບ DORA ດຶງເມື່ອຈຳກັດ WIP ຂອງ sprint.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ຕົວຊີ້ວັດກະແສເປັນພາສາຮ່ວມລະຫວ່າງກະດານ Kanban ຂອງທີມສົ່ງມອບ ແລະ ພື້ນທີ່ງານກໍລະນີທີ່ຊອບແວນັ້ນຖືກສ້າງຂຶ້ນເພື່ອ: ຄິວຂອງເຈົ້າໜ້າທີ່ກໍລະນີ ແລະ ຄິວ pull request ຖືກຄວບຄຸມດ້ວຍກົດຂອງ Little ທັງສອງ ແລະ ທັງສອງເກີນເປົ້າໝາຍເວລາວົງຈອນດ້ວຍວິທີດຽວກັນ — WIP ຫຼາຍເກີນໄປເມື່ອທຽບກັບ throughput. ສິ່ງນີ້ສຳຄັນໂດຍກົງສຳລັບ [ຕົ້ນທຶນຂອງການຊັກຊ້າໃນໂຄງການສາທາລະນະ](../ຕົ້ນທຶນຂອງການຊ້າໃນໂຄງການສາທາລະນະ/): ເວລາວົງຈອນ × CoD ແມ່ນເງິນປອນທີ່ນັ່ງຢູ່ໃນຄິວໃນທຸກຂະນະ ແລະ ສຳຄັນສຳລັບ [ມາດຕະຖານການບໍລິການ ແລະ ຕົວຊີ້ວັດທຸລະກຳ](../ມາດຕະຖານບໍລິການ-ແລະ-ຕົວຊີ້ວັດທຸລະກຳ/) ບ່ອນທີ່ເປົ້າໝາຍເວລາດຳເນີນງານທີ່ເຜີຍແຜ່ເປັນຄຳໝັ້ນສັນຍາເວລາວົງຈອນ ເຊິ່ງມີແຕ່ຕົວຊີ້ວັດກະແສທີ່ວິນິດໄສໄດ້ເມື່ອພາດ. ຊອບແວຂອງລະບົບງານກໍລະນີຄວນສະແດງ WIP ແລະ ເວລາວົງຈອນເປັນຕົວຊີ້ວັດການດຳເນີນງານຫຼັກ ບໍ່ແມ່ນຝັງໄວ້ໃນລະບົບຈັດການກໍລະນີທີ່ບໍ່ມີໃຜສອບຖາມ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ເພີ່ມຂີດຈຳກັດ WIP ໂດຍບໍ່ແກ້ຄໍຂວດຈິງ**: ຖ້າຂໍ້ຈຳກັດແມ່ນເວລາຕອບກັບຂອງຜູ້ໃຫ້ຄຳປຶກສາຕາມກົດໝາຍພາຍນອກ ການຈຳກັດ WIP ຂອງເຈົ້າໜ້າທີ່ກໍລະນີພຽງແຕ່ຍ້າຍຄິວຂຶ້ນຕົ້ນນ້ຳ ແທນທີ່ຈະເຮັດໃຫ້ສັ້ນລົງ.
- **ຖືປະສິດທິພາບກະແສເປັນເປົ້າໝາຍທີ່ຫຼອກໄດ້**: ການເລັ່ງ 1.3% ຂອງເວລາທີ່ເຮັດວຽກຈິງແທບບໍ່ຂະຫຍັບເວລາວົງຈອນ; ອຳນາດຕໍ່ລອງເກືອບສະເໝີຢູ່ໃນສະຖານະລໍຖ້າ ເຊິ່ງໂດຍທົ່ວໄປໝາຍເຖິງການອອກແບບຂະບວນການໃໝ່ ບໍ່ແມ່ນຄວາມໄວຂອງເຈົ້າໜ້າທີ່ກໍລະນີ.
- **ບໍ່ສົນໃຈຄວາມຜັນແປ**: ກົດຂອງ Little ອະທິບາຍຄ່າສະເລ່ຍ; ງານຄົງຄ້າງທີ່ມີຄວາມຜັນແປຂອງຄວາມຕ້ອງການສູງຕ້ອງການຄວາມຈຸບັຟເຟີ ບໍ່ແມ່ນພຽງຂີດຈຳກັດ WIP ທີ່ແໜ້ນຂຶ້ນ ບໍ່ດັ່ງນັ້ນກຳນົດເວລາຕາມກົດໝາຍກໍຍັງພາດໃນຫາງທີ່ຜັນຜວນ ເຖິງແມ່ນຄ່າສະເລ່ຍຈະດີຂຶ້ນ.
- **ວັດ WIP ບໍ່ສອດຄ່ອງ**: ກໍລະນີທີ່ "ເປີດ" ໃນລະບົບບັນທຶກແຕ່ຕິດຢູ່ລໍຖ້າບຸກຄົນທີສາມຈິງໆ ຍັງເປັນ WIP; ການຍົກເວັ້ນມັນເຮັດໃຫ້ຕົວເລກເບິ່ງດີໂດຍບໍ່ປ່ຽນຄວາມຈິງທີ່ພົນລະເມືອງປະເຊີນ.
