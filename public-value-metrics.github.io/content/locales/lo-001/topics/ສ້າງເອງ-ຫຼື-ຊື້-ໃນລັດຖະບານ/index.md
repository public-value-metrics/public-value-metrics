# ສ້າງເອງ ຫຼື ຊື້ ໃນລັດຖະບານ (Build vs Buy)

ການຕັດສິນໃຈສ້າງເອງ ຫຼື ຊື້ (build-vs-buy) ແມ່ນການປຽບທຽບທີ່ມີໂຄງສ້າງ ແລະ ປັບຄວາມສ່ຽງແລ້ວ ລະຫວ່າງການພັດທະນາເອງກັບການຈັດຫາແບບທາງການຄ້າ ຫຼື ແບບສິນຄ້າທົ່ວໄປ, ປຽບທຽບຕາມ [ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ](../ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ-ໃນ-it-ຂອງລັດຖະບານ/) ທີ່ຫຼຸດມູນຄ່າແລ້ວ, ເວລາຮອດຄຸນຄ່າ ແລະ ຄວາມສ່ຽງ. ລັດຖະບານໂດຍໂຄງສ້າງແລ້ວເປັນຂະແໜງຜູ້ຊື້ — Technology Code of Practice ກຳນົດຂໍ້ສົມມຸດທີ່ເອນໄປຫາທາງແກ້ໄຂແບບສິນຄ້າທົ່ວໄປ ແລະ ຄລາວ — ແຕ່ທີມວິສະວະກຳພາຍໃນກົມຕ່າງໆກໍຍັງເລືອກສ້າງເອງເປັນຄ່າເລີ່ມຕົ້ນ ດ້ວຍເຫດຜົນດຽວກັບຜູ້ສ້າງທົ່ວໂລກ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

Technology Code of Practice ຂອງ Government Digital Service (<https://www.gov.uk/guidance/the-technology-code-of-practice>) ແລະ ຄຳແນະນຳ Service Manual ທີ່ມາຄູ່ກັນກ່ຽວກັບການຕັດສິນໃຈວ່າຈະສ້າງ ຫຼື ຊື້ ຜັກດັນໃຫ້ກົມຕ່າງໆຕ້ອງຢືນຢັນການພັດທະນາສະເພາະ ເມື່ອທຽບກັບຂໍ້ສົມມຸດທີ່ວ່າ ຄວາມສາມາດແບບສິນຄ້າທົ່ວໄປຄວນຊື້, ບໍ່ແມ່ນສ້າງ, ແລະ ມີພຽງຄວາມສາມາດທີ່ໃໝ່ແທ້ ແລະ ເຮັດໃຫ້ພາລະກິດແຕກຕ່າງເທົ່ານັ້ນ ທີ່ຄຸ້ມຄ່າກັບໂຄດສະເພາະ. ຄຳແນະນຳເສີມຂອງ HM Treasury ກ່ຽວກັບອະຄະຕິແງ່ດີ (optimism bias) ຕໍ່ Green Book, ຊຶ່ງມາຈາກການທົບທວນການຈັດຊື້ພາກລັດຂະໜາດໃຫຍ່ຂອງ Mott MacDonald ປີ 2002, ໃຫ້ໂຄງການ IT ມີຊ່ວງການເພີ່ມກວ້າງທີ່ສຸດໃນທຸກປະເພດທີ່ປະເມີນ — ການຄາດຄະເນຕົ້ນທຶນທຶນຖືກແນະນຳໃຫ້ເພີ່ມ 10% ຢູ່ປາຍຕ່ຳ ແລະ ເຖິງ 200% ຢູ່ປາຍສູງ ກ່ອນນຳໃຊ້ໃນການປະເມີນ, ສະທ້ອນວ່າການສ້າງຊອບແວຖືກຄາດຄະເນຕ່ຳເກີນໄປຫຼາຍເທົ່າໃດໃນການຈັດຊື້ພາກລັດທີ່ຜ່ານມາ. ການວິເຄາະສ້າງເອງ ຫຼື ຊື້ ມີຂຶ້ນກໍເພື່ອບັງຄັບໃຫ້ການປັບຄວາມສ່ຽງນັ້ນຂຶ້ນມາເທິງໂຕະກ່ອນການອະນຸມັດ ແທນທີ່ຈະໃຫ້ມັນປະກົດເປັນຄຳຂໍງົບເກີນໃນລະຫວ່າງປີ.

## ຄະນິດສາດ

```
Compare over the same 3–5 year horizon, discounted at the Green Book
social discount rate (see social-discount-rate.md):

NPV_option = PV(benefits, shifted by time-to-value) − PV(TCO)

Risk adjustments (Green Book optimism bias pattern):
  build cost × 1.1–3.0        (IT project uplift range, Mott MacDonald)
  build time-to-value + 40–60% (deployment delay prior)
  buy: add integration reality-check and contract exit costs instead

Decision drivers, in the order they usually decide:
  1. differentiation — is this capability the mission, or plumbing?
  2. time-to-value × cost of delay (see cost-of-delay-in-public-programmes.md)
  3. risk-adjusted total cost of ownership
```

## ຕົວຢ່າງການຄິດໄລ່

ອົງການປົກຄອງທ້ອງຖິ່ນຕ້ອງການລະບົບຈັດການກໍລະນີສຳລັບການດູແລສັງຄົມຜູ້ໃຫຍ່. ຊື້: SaaS ໃນລາຄາ £180,000/ປີ, ເປີດໃຊ້ໃນ 4 ເດືອນ. ສ້າງເອງ: ຄາດຄະເນ £900,000 ບວກຄ່າບຳລຸງຮັກສາ £150,000/ປີ, ເປີດໃຊ້ໃນ 14 ເດືອນ.

```
Risk-adjusted build cost = 900,000 × 1.4 = £1,260,000
5-year TCO:
  buy  = 180,000 × 5 = £900,000
  build = 1,260,000 + 150,000 × 5 = £2,010,000

Delay term: the system avoids £40,000/month in duplicated assessments;
build arrives 10 months later than buy.
CoD = 10 × 40,000 = £400,000

Effective comparison: £900,000 (buy) vs £2,010,000 + £400,000 = £2,410,000 (build)
```

ການຊື້ຊະນະປະມານ £1.5 ລ້ານໃນຫ້າປີ, ແລະ ລາຍການດຽວທີ່ໃຫຍ່ທີ່ສຸດຕໍ່ຈາກການຄາດຄະເນຕົ້ນທຶນສ້າງເອງແມ່ນຕົ້ນທຶນຂອງການຊ້າ ທີ່ການປຽບທຽບແບບທຶນຢ່າງດຽວຈະບໍ່ມີທາງເປີດເຜີຍ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ວິໄນທີ່ຖ່າຍທອດຈາກການວິເຄາະນີ້ໄປສູ່ການປະຕິບັດການສົ່ງມອບໂດຍກົງ: **ການປັບຄວາມສ່ຽງຕາມຄ່າຄາດເດີມ** — ການເພີ່ມຂອງ Mott MacDonald ແມ່ນຊອບແວທຽບເທົ່າຂອງອະຄະຕິແງ່ດີໃນ Green Book ທີ່ນຳໃຊ້ແບບກົນໄກ, ທີມຈຶ່ງຄວນຂໍຍົກເວັ້ນຈາກມັນ ແທນທີ່ຈະສົມມຸດວ່າການຄາດຄະເນຂອງຕົນເປັນຂໍ້ຍົກເວັ້ນ; **ຄວາມຊື່ສັດຂອງຕົວປຽບທຽບ** — ທາງເລືອກແທນການສ້າງແມ່ນທາງເລືອກຊື້ທີ່ດີທີ່ສຸດທີ່ມີ, ບໍ່ແມ່ນ "ບໍ່ມີຫຍັງ", ຊຶ່ງເຊື່ອມໂຍງໂດຍກົງກັບ [ຕົ້ນທຶນໂອກາດໃນການໃຊ້ຈ່າຍສາທາລະນະ](../ຕົ້ນທຶນໂອກາດໃນການໃຊ້ຈ່າຍສາທາລະນະ/); ແລະ **ການປຽບທຽບ TCO ຢ່າງຊື່ສັດ** — ທຸກຂໍ້ສະເໜີສ້າງເອງຄວນຖືກປຽບທຽບກັບ [ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ](../ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ-ໃນ-it-ຂອງລັດຖະບານ/) ເຕັມຂອງທາງເລືອກຊື້, ບໍ່ແມ່ນລາຄາປ້າຍ. ບ່ອນທີ່ການສ້າງເອງຊະນະແທ້ ຄວນໃສ່ລາຄາ[ຕົ້ນທຶນຂອງການຊ້າ](../ຕົ້ນທຶນຂອງການຊ້າໃນໂຄງການສາທາລະນະ/) ຂອງເວລາສ້າງເພີ່ມຢ່າງຊັດເຈນໃນກໍລະນີທຸລະກິດ, ບໍ່ປ່ອຍໄວ້ເປັນສົມມຸດຖານທີ່ບໍ່ໄດ້ກ່າວວ່າເວລາບໍ່ສຳຄັນ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ປຽບທຽບລາຄາປ້າຍຂອງຜູ້ຂາຍກັບການຄາດຄະເນສ້າງເອງທີ່ບໍ່ໄດ້ປັບຄວາມສ່ຽງ**: ນີ້ເຮັດໃຫ້ການສ້າງເອງເບິ່ງດີເກີນຈິງສອງຊັ້ນ, ທັງດ້ານຕົ້ນທຶນ ແລະ ກຳນົດເວລາ.
- **ແຮງງານພາຍໃນທີ່ໃສ່ລາຄາເປັນສູນ**: ເວລາວິສະວະກຳຂອງຂ້າລາຊະການຖືກຖືວ່າ "ຟຣີ" ເພາະຢູ່ໃນງົບບຸກຄະລາກອນຂອງກົມແລ້ວ, ຊຶ່ງປິດບັງຕົ້ນທຶນໂອກາດທີ່ແທ້ຈິງຕໍ່ວຽກອື່ນທີ່ທີມນັ້ນຈະເຮັດໄດ້.
- **ການຜູກມັດ (lock-in) ທີ່ບໍ່ໄດ້ໃສ່ລາຄາທັງສອງທາງ**: ຕົ້ນທຶນການອອກຈາກຜູ້ຂາຍ ແລະ ການຍ້າຍຂໍ້ມູນເປັນຂອງຈິງ, ແຕ່ bus-factor ຂອງການສ້າງເອງ ແລະ ການເພິ່ງພາການຮັກສາທີມພາຍໃນຂະໜາດນ້ອຍທີ່ທົດແທນຍາກຕະຫຼອດອາຍຸໃຊ້ງານ ກໍເປັນຂອງຈິງເຊັ່ນກັນ.
- **ອ້າງຄວາມແຕກຕ່າງຂອງພາລະກິດສຳລັບທໍ່ນ້ຳພື້ນຖານ**: "ອັນນີ້ເປັນຫຼັກຂອງພວກເຮົາ" ທີ່ອ້າງກ່ຽວກັບມິດເດິນແວຮ໌ເຊື່ອມຕໍ່ ຫຼື ບ່ອນເກັບເອກະສານ — ຈົ່ງທົດສອບວ່າພົນລະເມືອງ ຫຼື ເຈົ້າໜ້າທີ່ຈະສັງເກດເຫັນຫຍັງບໍວ່າອັນໃດກຳລັງເຮັດວຽກຢູ່ເບື້ອງລຸ່ມ.
