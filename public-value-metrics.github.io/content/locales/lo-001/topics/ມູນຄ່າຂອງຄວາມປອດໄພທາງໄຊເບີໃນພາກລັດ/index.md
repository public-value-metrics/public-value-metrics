# ມູນຄ່າຂອງຄວາມປອດໄພທາງໄຊເບີໃນພາກລັດ

ມູນຄ່າຂອງຄວາມປອດໄພທາງໄຊເບີໃນພາກລັດແມ່ນວິໄນຂອງການກຳນົດລາຄາການຫຼຸດຄວາມສ່ຽງ: ການເຮັດໃຫ້ການລະເມີດຂໍ້ມູນພົນລະເມືອງມີໂອກາດເກີດໜ້ອຍລົງມີຄ່າເທົ່າໃດ,
ເມື່ອການໃຊ້ຈ່າຍດ້ານຄວາມປອດໄພບໍ່ໃຫ້ຜົນຜະລິດທີ່ເຫັນໄດ້ເມື່ອມັນໄດ້ຜົນ ແຕ່ໃຫ້ຜົນທີ່ເຫັນຊັດເຈນຫຼາຍເມື່ອມັນລົ້ມເຫຼວ? ສຳລັບບໍລິການທີ່ເກັບບັນທຶກສິດຮັບເງິນອຸດໜູນ,
ຂໍ້ມູນສຸຂະພາບ ຫຼື ບັນທຶກພາສີ, ຄຸນສົມບັດ "ເບິ່ງບໍ່ເຫັນເມື່ອເຮັດວຽກໄດ້ດີ" ນັ້ນຄືເຫດຜົນທີ່ມັນຕ້ອງມີເຫດຜົນມູນຄ່າທີ່ຊັດເຈນ, ບໍ່ແມ່ນພຽງການໝາຍຖືກຕາມລະບຽບ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

Cyber Assessment Framework (CAF) ຂອງສູນຄວາມປອດໄພທາງໄຊເບີແຫ່ງຊາດຂອງ UK (NCSC) ໃຫ້ອົງກອນພາກລັດມີວິທີທີ່ມີໂຄງສ້າງເພື່ອເຮັດໃຫ້ຄວາມປອດໄພເປັນວິໄນທີ່ປະເມີນໄດ້
ແລະ ອີງໃສ່ຜົນລັບ ແທນບັນຊີລາຍການກວດ: ມັນກຳນົດສີ່ວັດຖຸປະສົງລະດັບສູງ (ການຈັດການຄວາມສ່ຽງດ້ານຄວາມປອດໄພ, ການປ້ອງກັນການໂຈມຕີທາງໄຊເບີ, ການກວດພົບເຫດການຄວາມປອດໄພທາງໄຊເບີ,
ແລະ ການຫຼຸດຜົນກະທົບຂອງເຫດການ) ທີ່ແບ່ງເປັນຜົນລັບຍ່ອຍທີ່ເຈົ້າຂອງລະບົບສາມາດຖືກປະເມີນ, ໃນເຈດຕະນາດຽວກັນກັບຂໍ້ 9 ຂອງ
[digital-service-standard](../ມາດຕະຖານການບໍລິການດິຈິຕອນ/) ("ສ້າງບໍລິການທີ່ປອດໄພທີ່ປົກປ້ອງຄວາມເປັນສ່ວນຕົວຂອງຜູ້ໃຊ້"). ສິ່ງທີ່ການປະເມີນ CAF ປົກປ້ອງຕໍ່ຕ້ານມີປ້າຍລາຄາທີ່ບັນທຶກໄວ້:
ລາຍງານ Cost of a Data Breach ຂອງ IBM ຕິດຕາມຕົ້ນທຶນສະເລ່ຍຂອງການລະເມີດຕາມຂະແໜງ, ແລະ ພົບຢ່າງສອດຄ່ອງວ່າພາກລັດຢູ່ໃກ້ປາຍຕ່ຳຂອງຊ່ວງເມື່ອທຽບກັບການເງິນ ຫຼື ສຸຂະພາບ —
ສະບັບຫຼ້າສຸດກຳນົດສະເລ່ຍພາກລັດປະມານ $2.6–2.9 ລ້ານຕໍ່ການລະເມີດ — ແຕ່ "ຕ່ຳກວ່າການເງິນ" ບໍ່ແມ່ນ "ຕ່ຳ", ແລະ ການລະເມີດຂອງລັດຖະບານມີຕົ້ນທຶນທີ່ຕົວເລກຂອງລາຍງານຈັບບໍ່ໄດ້ເຕັມທີ່:
ການສູນເສຍຄວາມໄວ້ວາງໃຈຂອງພົນລະເມືອງຕໍ່ຊ່ອງທາງດິຈິຕອນ, ເຊິ່ງກົດ[ການນຳໃຊ້ຊ່ອງທາງດິຈິຕອນ](../ການປະຢັດຈາກການຍ້າຍຊ່ອງທາງ/)ທີ່ກໍລະນີທຸລະກິດການຍ້າຍຊ່ອງທາງຂຶ້ນກັບ, ແລະ ຕົ້ນທຶນທາງການເມືອງ ແລະ ກົດໝາຍຂອງການເປີດເຜີຍຂໍ້ມູນທີ່ລັດບັງຄັບໃຫ້ພົນລະເມືອງມອບໃຫ້ແຕ່ທຳອິດ.

## ຄະນິດສາດ

ການລົງທຶນດ້ານຄວາມປອດໄພຖືກປະເມີນມູນຄ່າແບບດຽວກັບການໃຊ້ຈ່າຍຫຼຸດຄວາມສ່ຽງທັງໝົດ: ເປັນການຫຼຸດຄວາມສູນເສຍທີ່ຄາດໄວ້, ໂດຍໃຊ້ເອກະລັກການຈັດການຄວາມສ່ຽງແບບຄລາສສິກ.

```
ຄວາມສູນເສຍທີ່ຄາດໄວ້ຕໍ່ປີ (ALE) = ຄວາມສູນເສຍທີ່ຄາດໄວ້ຕໍ່ເຫດການ (SLE)
                                  × ອັດຕາການເກີດຕໍ່ປີ (ARO)

ມູນຄ່າຂອງມາດຕະການຄວບຄຸມຄວາມປອດໄພ =
  ALE_ກ່ອນມາດຕະການ − ALE_ຫຼັງມາດຕະການ − ຕົ້ນທຶນຕໍ່ປີຂອງມາດຕະການ

ມາດຕະການຄຸ້ມຄ່າທີ່ຈະໃຫ້ທຶນເມື່ອ:
  (ALE_ກ່ອນ − ALE_ຫຼັງ) > ຕົ້ນທຶນຕໍ່ປີຂອງມາດຕະການ

ການປະເມີນ CAF ບໍ່ໄດ້ອອກຄວາມນ່າຈະເປັນໂດຍກົງ, ແຕ່ໂປຣໄຟລ໌ຜົນລັບ CAF ຂອງບໍລິການ
(ຜົນລັບຍ່ອຍໃດ "ບັນລຸແລ້ວ", "ບັນລຸບາງສ່ວນ", ຫຼື "ຍັງບໍ່ບັນລຸ") ເປັນຂໍ້ມູນນຳເຂົ້າຕົວແທນທີ່ສົມເຫດສົມຜົນ
ເພື່ອຄາດຄະເນ ARO — ລະບົບທີ່ມີການເຂົ້າເຖິງສິດພິເສດທີ່ບໍ່ໄດ້ຈັດການ ຫຼື ບໍ່ມີແຜນຕອບໂຕ້ເຫດການທີ່ໄດ້ທົດສອບ
ມີ ARO ທີ່ແທ້ຈິງສູງກວ່າຢ່າງມີນັຍສຳຄັນເມື່ອທຽບກັບລະບົບທີ່ມີທັງສອງຢ່າງ.
```

## ຕົວຢ່າງການຄິດໄລ່

**ລະບົບຈັດການກໍລະນີຂອງສະພາເຄົາຕີທີ່ເກັບບັນທຶກການດູແລສັງຄົມຂອງຜູ້ອາໄສ 40,000 ຄົນ**:

```
ຄວາມສູນເສຍທີ່ຄາດໄວ້ຕໍ່ເຫດການ (ຕົ້ນທຶນການລະເມີດ), ໃຊ້ສະເລ່ຍພາກລັດ
ຈາກລາຍງານ Cost of a Data Breach ຂອງ IBM ຫຼ້າສຸດ ≈ £2.1m
(ແປງແລ້ວ, ຕົວເລກຂະໜາດຄາດຄະເນ — ຄິດໄລ່ໃໝ່ຈາກ
ລາຍງານສະບັບປັດຈຸບັນສະເໝີ ແທນການນຳຕົວເລກຄົງທີ່ມາໃຊ້ຊ້ຳ)

ARO ປັດຈຸບັນ (ການເຂົ້າເຖິງສິດພິເສດທີ່ບໍ່ໄດ້ຈັດການ, ບໍ່ມີການຕອບໂຕ້ເຫດການ
ທີ່ໄດ້ທົດສອບ, ຕາມການປະເມີນຕົນເອງດ້ວຍ CAF ພາຍໃນທີ່ສະແດງຜົນລັບ
"ຍັງບໍ່ບັນລຸ" ຫຼາຍອັນ) ≈ ຄາດຄະເນ 8% ຕໍ່ປີ
  ALE_ກ່ອນ = £2.1m × 0.08 = £168,000/ປີ

ມາດຕະການທີ່ສະເໜີ: ການຈັດການການເຂົ້າເຖິງສິດພິເສດ + ແຜນຕອບໂຕ້ເຫດການທີ່ໄດ້ທົດສອບ,
ຍ້າຍຜົນລັບ CAF ທີ່ກ່ຽວຂ້ອງໄປສູ່ "ບັນລຸແລ້ວ", ຄາດວ່າຈະຫຼຸດ ARO ເປັນ 3%/ປີ
  ALE_ຫຼັງ = £2.1m × 0.03 = £63,000/ປີ

ຕົ້ນທຶນຕໍ່ປີຂອງມາດຕະການ (ເຄື່ອງມື + ຂະບວນການ + ການທົດສອບ) = £45,000

ມູນຄ່າຂອງມາດຕະການ = (168,000 − 63,000) − 45,000 = £60,000/ປີ
  ສຸດທິເປັນບວກ — ໃຫ້ທຶນມັນ. ເລກຄະນິດຍັງສະແດງວ່າມາດຕະການ
  ຍັງຄຸ້ມຄ່າທີ່ຈະໃຫ້ທຶນເຖິງແມ່ນຕົ້ນທຶນເກືອບສາມເທົ່າ, ເຊິ່ງເປັນ
  ການກວດສອບຄວາມອ່ອນໄຫວປະເພດທີ່ຄວນມາພ້ອມກັບຕົວເລກ ALE ໃດໆ
  ທີ່ສ້າງຈາກຄວາມນ່າຈະເປັນທີ່ຄາດຄະເນ.
```

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ວິສະວະກອນເປັນເຈົ້າຂອງຄັນຍົກສ່ວນໃຫຍ່ໃນສົມຜົນ ALE: ການອອກແບບການຄວບຄຸມການເຂົ້າເຖິງ, ສຸຂະອະນາໄມຂອງ dependency ແລະ patch, ການຄຸ້ມຄອງບັນທຶກ ແລະ ການກວດພົບ,
ແລະ ເຄື່ອງມືຕອບໂຕ້ເຫດການ ທັງໝົດເຄື່ອນ ARO ໂດຍກົງ, ເຊິ່ງເປັນເຫດຜົນທີ່ການປະເມີນ CAF ອ່ານຄືການທົບທວນສະຖາປັດຕະຍະກຳດ້ານເຕັກນິກຫຼາຍເທົ່າກັບການກວດສອບນະໂຍບາຍ.
ນີ້ແມ່ນ [technical-debt-as-public-value-erosion](../ໜີ້ທາງເທັກນິກໃນຖານະການກັດກ່ອນຄຸນຄ່າສາທາລະນະ/) ໃນຮູບແບບແຫຼມທີ່ສຸດ — ລະບົບທີ່ບໍ່ໄດ້ patch, ບໍ່ມີການເຝົ້າລະວັງ, ແລະ ຄວບຄຸມການເຂົ້າເຖິງບໍ່ດີ
ແມ່ນໜີ້ທີ່ດອກເບ້ຍເປັນຄວາມສ່ຽງຫາງ, ບໍ່ແມ່ນການຖ່ວງຢ່າງຄົງທີ່ — ແລະ ຄວນຖືກປຽບທຽບກັບ [total-cost-of-ownership-in-government-it](../ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ-ໃນ-it-ຂອງລັດຖະບານ/)
ເພື່ອບໍ່ໃຫ້ການໃຊ້ຈ່າຍດ້ານຄວາມປອດໄພຖືກຖືວ່າແຍກຈາກຕົ້ນທຶນການດຳເນີນງານແທ້ຈິງຂອງລະບົບ. ມັນຍັງເປັນຂໍ້ມູນນຳເຂົ້າໂດຍກົງຂອງການປະເມີນ [ຄວາມຄຸ້ມຄ່າເງິນ](../ຄວາມຄຸ້ມຄ່າເງິນ/)
ພາຍໃຕ້ Green Book: ຕົ້ນທຶນທີ່ປັບຕາມຄວາມສ່ຽງແມ່ນສ່ວນໜຶ່ງຂອງດ້ານ "ຕົ້ນທຶນ" ຂອງການປະເມີນທາງເລືອກໃດໆ, ບໍ່ແມ່ນສິ່ງທີ່ຄິດພາຍຫຼັງແລ້ວຕິດທ້າຍ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ຖືການປະເມີນຕົນເອງດ້ວຍ CAF ວ່າເປັນຄວາມປອດໄພເອງ**: ການປະເມີນທີ່ສຳເລັດພຽງອະທິບາຍທ່າທີຄວາມປອດໄພ; ມັນບໍ່ໄດ້ສ້າງມັນຂຶ້ນ — ມູນຄ່າຢູ່ທີ່ຜົນລັບທີ່ບັນລຸ, ບໍ່ແມ່ນເອກະສານ.
- **ໃຊ້ຕົ້ນທຶນການລະເມີດສະເລ່ຍທົ່ວໂລກເປັນຄ່າຄາດຄະເນທ້ອງຖິ່ນໂດຍບໍ່ປັບ**: ຕົວເລກຂອງ IBM ເປັນຄ່າສະເລ່ຍຂ້າມຕົວຢ່າງຂະໜາດໃຫຍ່ທີ່ຫຼາກຫຼາຍ;
  ຄວາມສູນເສຍທີ່ຄາດໄວ້ຕໍ່ເຫດການທີ່ແທ້ຈິງຂອງອົງການປົກຄອງທ້ອງຖິ່ນຂະໜາດນ້ອຍແທບບໍ່ເຄີຍເທົ່າກັບກະຊວງລັດຖະບານແຫ່ງຊາດ.
- **ເມີນເສີຍຈິດຕະສາດຄວາມສ່ຽງຫາງໃນການຕັດສິນໃຈລົງທຶນ**: ຄວາມນ່າຈະເປັນປະຈຳປີຕ່ຳເຮັດໃຫ້ການໃຊ້ຈ່າຍດ້ານຄວາມປອດໄພຖືກເລື່ອນໄດ້ງ່າຍບໍ່ມີກຳນົດ, ຈົນເຖິງປີທີ່ມັນບໍ່ເປັນແບບນັ້ນ —
  ການທົດສອບຄວາມອ່ອນໄຫວຂອງການຄິດໄລ່ ALE ຕໍ່ຊ່ວງ ARO, ດັ່ງໃນຕົວຢ່າງການຄິດໄລ່, ຕ້ານສິ່ງນີ້.
- **ນັບແຕ່ຕົ້ນທຶນການລະເມີດແບບ IBM, ບໍ່ນັບຕົ້ນທຶນຄວາມໄວ້ວາງໃຈ**: ການລະເມີດທີ່ກົດຄວາມເຕັມໃຈຂອງພົນລະເມືອງໃນການໃຊ້ຊ່ອງທາງດິຈິຕອນກັດກ່ອນກໍລະນີ
  [channel-shift-savings](../ການປະຢັດຈາກການຍ້າຍຊ່ອງທາງ/) ເປັນເວລາຫຼາຍປີ, ເປັນຕົ້ນທຶນທີ່ແທບບໍ່ຖືກລວມໃນການຄາດຄະເນຕົ້ນທຶນການລະເມີດ.
