# அரசின் சேவை வழங்கலில் பாய்வு அளவீடுகள்

பாய்வு அளவீடுகள் (flow metrics) (லிட்டில் விதி, நடப்புப் பணி (WIP) வரம்புகள், பாய்வுத் திறன்) வரம்புக்குட்பட்ட திறனுள்ள அமைப்பு வழியாகப் பணி எவ்வளவு விரைவாக நகர்கிறது என்பதை விவரிக்கின்றன. ஸ்பிரிண்ட் பலகை அத்தகைய ஓர் அமைப்பு; நலத்திட்டக் கோரிக்கை வரிசை, திட்டமிடல் விண்ணப்பப் பதிவேடு, விசா வழக்குப் பணிக் குவியல் ஆகியவையும் வேறு சீருடை அணிந்த அதே கணிதமே.

## ஏன் இது முக்கியம்

அரசின் வழக்குச் சுமைகள் வரிசை அமைப்புகள்; யாரேனும் அளந்தாலும் அளக்காவிட்டாலும் வரிசை அமைப்புகள் வரிசை விதிகளுக்குக் கட்டுப்படுகின்றன. சட்டப்பூர்வத் தீர்மான காலங்கள் இதை வெளிப்படையாக்குகின்றன: நகர மற்றும் ஊரகத் திட்டமிடல் (Town and Country Planning) ஆட்சியின் கீழ், பெரும்பாலான சிறு திட்டமிடல் விண்ணப்பங்களுக்கு 8 வார சட்டப்பூர்வத் தீர்மான இலக்கும், பெரிய விண்ணப்பங்களுக்கு 13 வாரங்களும் உள்ளன: சுழற்சி-நேர (cycle-time) கடப்பாடு நேரடியாகச் சட்டத்திலேயே பதிக்கப்பட்டுள்ளது. தேசியத் தணிக்கை அலுவலகமும் (National Audit Office) உள்துறை விவகாரத் தேர்வுக் குழுவும் (Home Affairs Select Committee) பலமுறை ஆய்வு செய்த உள்துறை அலுவலகத்தின் புகலிட வழக்குப் பணிக் குவியல், நடப்புப் பணி நீண்டகாலமாகத் திறனை விட வேகமாக வளர்ந்த பொது அமைப்பின் நன்கு ஆவணப்படுத்தப்பட்ட எடுத்துக்காட்டு; சுழற்சி நேரங்கள் எந்தச் சட்டப்பூர்வ அல்லது சேவை எதிர்பார்ப்பையும் விட மிக அதிகமாகின. இந்தத் தோல்வி வடிவத்துக்கு, பொறியாளர்களுக்கும் வழக்குப் பணி மேலாளர்களுக்கும் பாய்வு அளவீடுகள் பொதுவான, அளவுசார் சொற்களஞ்சியத்தை அளிக்கின்றன; அதைத் தரமான "பணிக் குவியல் சிக்கலாக" விட்டுவிடுவதில்லை.

## கணிதம்

```
Little's Law:  WIP = Throughput × Cycle Time
           →   Cycle Time = WIP / Throughput

Flow efficiency = active (touch) time / total cycle time   (Vacanti)

WIP limit effect: for fixed throughput, halving WIP roughly halves
average cycle time (Little's Law rearranged) — the lever available
without adding headcount.
```

வழக்குப் பணியில் அல்ல, மென்பொருள் வெளியீட்டுக் குழாய்களில் பயன்படுத்தப்படும் இதே கணிதத்துக்கு [DORA metrics for public value](../பொது-மதிப்புக்கான-dora-அளவீடுகள்/) பாருங்கள்.

## செயல்முறை எடுத்துக்காட்டு

**உள்ளாட்சித் திட்டமிடல் துறை**: எப்போதும் 400 விண்ணப்பங்கள் திறந்துள்ளன (WIP), குழு வாரத்துக்கு 50 விண்ணப்பங்களைத் தீர்க்கிறது (செயல்திறன்).

```
Cycle time = WIP / Throughput = 400 / 50 = 8 weeks
```

இது சிறு விண்ணப்பங்களுக்கான சட்டப்பூர்வ 8 வார இலக்கில் சரியாக விழுகிறது; மிச்சம் இல்லை: உள்வரும் தேவையிலோ ஆலோசிக்கப்படுவோரின் பதில் நேரத்திலோ ஏற்படும் எந்த ஏற்ற இறக்கமும் தீர்மானங்களைச் சட்டக் கெடுவுக்கு அப்பால் தள்ளும்.

**பாய்வுத் திறன்**: அந்த 8 வாரங்களில் (56 நாட்காட்டி நாட்கள்), ஒரு விண்ணப்பம் வழக்கமாக ஏறத்தாழ 6 மணி நேரம் உண்மையான வழக்குப் பணியாளர் செயலாக்க நேரத்தைப் பெறுகிறது.

```
Flow efficiency = 6 hours / (56 days × 8 working hours/day)
                = 6 / 448 ≈ 1.3%
```

மென்பொருள் குழுக்களுக்கான Vacanti-இன் அளவுகோல் வழக்கமான பாய்வுத் திறனை 15–20% எனக் கொள்கிறது; பல சட்டப்பூர்வ ஆலோசனைக் கைமாற்றங்களும் பொது ஆலோசனைக் காலங்களும் கொண்ட அரசு வழக்குப் பணி பெரும்பாலும் ஒரு மடங்குக் கணக்கு அளவு குறைவாக இயங்குகிறது. எட்டு வாரங்கள் உண்மையில் செல்வது "காத்திருப்பு" நேரத்தின் 98.7%-இல்தான்; வழக்குப் பணியாளர் திறனில் அல்ல.

**WIP-வரம்புத் தலையீடு**: ஒரு வழக்குப் பணியாளருக்குத் திறந்த விண்ணப்பங்களை வரம்பற்ற 25-க்குப் பதிலாக 15 ஆகத் தடை செய்வது (செயல்திறனை மாறாமல் வைத்து), 16 பேர் கொண்ட குழு முழுவதும் WIP-ஐ 400-இலிருந்து ஏறத்தாழ 240-க்கு மாற்றுகிறது:

```
New cycle time = 240 / 50 = 4.8 weeks
```

பணியாளர் அதிகரிப்பால் அல்ல, கொள்கை மாற்றத்தால் சுழற்சி நேரம் ஏறத்தாழ பாதியாகிறது: DORA பாணி வழங்கல் குழுக்கள் ஸ்பிரிண்ட் WIP-ஐ வரம்பிடும்போது இழுக்கும் அதே நெம்புகோல்.

## மென்பொருள் பொறியியல் தொடர்பு

பாய்வு அளவீடுகள் வழங்கல் குழுவின் Kanban பலகைக்கும், அது மென்பொருள் உருவாக்கும் வழக்குப் பணித் தளத்துக்கும் இடையிலான பொது மொழி: வழக்குப் பணியாளரின் வரிசையும் pull-request வரிசையும் இரண்டுமே லிட்டில் விதியால் ஆளப்படுகின்றன; இரண்டுமே ஒரே வகையில் சுழற்சி-நேர இலக்குகளை மீறுகின்றன: செயல்திறனுடன் ஒப்பிடும்போது மிக அதிக WIP. இது [cost of delay in public programmes](../பொதுத்-திட்டங்களில்-தாமதச்-செலவு/)-க்கு நேரடியாக முக்கியம்: சுழற்சி நேரம் × CoD என்பது எந்த நேரத்திலும் வரிசையில் கிடக்கும் பவுண்டுகள்; மேலும் [service standards and transaction metrics](../சேவைத்-தரநிலைகளும்-பரிவர்த்தனை-அளவீடுகளும்/)-க்கும் முக்கியம்: வெளியிடப்பட்ட முடிக்கும் கால இலக்கு ஒரு சுழற்சி-நேரக் கடப்பாடு, அது தவறும்போது பாய்வு அளவீடுகளால் மட்டுமே கண்டறிய முடியும். வழக்குப் பணி அமைப்பின் மென்பொருள் WIP-ஐயும் சுழற்சி நேரத்தையும் எவரும் வினவாத வழக்கு-மேலாண்மை அமைப்புக்குள் புதைக்காமல், முதல்தர செயல்பாட்டு அளவீடுகளாக வெளிப்படுத்த வேண்டும்.

## பொதுவான தவறுகள்

- **உண்மையான இடையூறைச் சரிசெய்யாமல் WIP வரம்புகளைச் சேர்த்தல்**: கட்டுப்பாடு வெளிப்புறச் சட்டப்பூர்வ ஆலோசிக்கப்படுவோரின் பதில் நேரம் என்றால், வழக்குப் பணியாளர் WIP-ஐ வரம்பிடுவது வரிசையைக் குறைக்காமல் மேலேயே நகர்த்துகிறது.
- **பாய்வுத் திறனை முறைகேடு செய்யக்கூடிய இலக்காகக் கருதுதல்**: 1.3% செயலில் நேரத்தை விரைவுபடுத்துவது சுழற்சி நேரத்தை அரிதாகவே நகர்த்துகிறது; நெம்புகோல் கிட்டத்தட்ட எப்போதும் காத்திருப்பு நிலைகளில் உள்ளது; அதாவது வழக்குப் பணியாளர் வேகம் அல்ல, செயல்முறை மறுவடிவமைப்பு.
- **மாறுபாட்டைப் புறக்கணித்தல்**: லிட்டில் விதி சராசரிகளை விவரிக்கிறது; தேவையில் அதிக மாறுபாடு உள்ள வழக்குச் சுமைக்கு இறுக்கமான WIP வரம்பு மட்டுமல்ல, இடைநிலைத் திறனும் தேவை; இல்லையெனில் சராசரி மேம்பட்டாலும் ஏற்ற இறக்கமான வால்பகுதியில் சட்டப்பூர்வக் கெடுக்கள் தவறவிடப்படும்.
- **WIP-ஐ ஒழுங்கற்ற முறையில் அளத்தல்**: பதிவு அமைப்பில் "திறந்துள்ள", ஆனால் உண்மையில் மூன்றாம் தரப்புக்காகக் காத்திருந்து நின்றுபோன வழக்கும் WIP-தான்; அதை விலக்குவது குடிமக்கள் எதிர்கொள்ளும் உண்மையை மாற்றாமல் எண்களைப் புகழ்கிறது.
