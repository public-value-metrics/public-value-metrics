# ការរាយការណ៍លទ្ធផលជំនួយ (IRIS+)

ការរាយការណ៍លទ្ធផលជំនួយគឺជាការអនុវត្តដែលអ្នកទទួលជំនួយរាយការណ៍រង្វាស់លទ្ធផលដែលមានស្តង់ដារ និងអាចប្រៀបធៀបបាន ត្រឡប់ទៅអ្នកផ្តល់មូលនិធិវិញ — ផ្ទុយពីការដែលអ្នកផ្តល់មូលនិធិម្នាក់ៗបង្កើតទម្រង់រាយការណ៍តាមតម្រូវរបស់ខ្លួន។ IRIS+ ដែលថែទាំដោយ Global Impact Investing Network (GIIN) គឺជាស្តង់ដារបែបនេះដែលត្រូវបានទទួលយកយ៉ាងទូលំទូលាយបំផុត៖ កាតាឡុកនៃរង្វាស់សមត្ថភាពសង្គម បរិស្ថាន និងហិរញ្ញវត្ថុដែលបានកំណត់ជាមុន ដែលអ្នកវិនិយោគផលប៉ះពាល់ និងកាន់តែច្រើនឡើងមូលនិធិផ្តល់ជំនួយតម្រូវ ឬណែនាំឱ្យអ្នកទទួលជំនួយប្រើ។

## ហេតុអ្វីបានជាសំខាន់

មុនពេលមានការរាយការណ៍តាមស្តង់ដារ មូលនិធិនីមួយៗសួរអ្នកទទួលជំនួយនូវសំណុំសូចនាករផ្សេងគ្នា ក្នុងទម្រង់ផ្សេងគ្នា ហើយអង្គការសប្បុរសធម៌ទំហំមធ្យមដែលមានអ្នកផ្តល់មូលនិធិដប់អាចដំណើរការដំណើរការរាយការណ៍ប៉ារ៉ាឡែលដប់សម្រាប់ការងារត្រួតស៊ីគ្នា — ជាកត្តាបង្កបន្ទុករាយការណ៍ដែលមានឯកសារច្បាស់ ដែលស្តង់ដារលទ្ធផលជំនួយមានដើម្បីកាត់បន្ថយ។ IRIS+ ដោះស្រាយរឿងនេះដោយផ្តល់ដល់អ្នកផ្តល់មូលនិធិ និងអ្នកទទួលជំនួយនូវវាក្យសព្ទរួម៖ សំណុំរង្វាស់ស្នូល (Core Metrics Sets) ដែលដាក់ជាក្រុមតាមប្រធានបទ (ឧទាហរណ៍ លំនៅដ្ឋានមានតម្លៃសមរម្យ ការទទួលបានថាមពលស្អាត ការរួមបញ្ចូលហិរញ្ញវត្ថុ) រង្វាស់នីមួយៗត្រូវបានកំណត់ឱ្យច្បាស់គ្រប់គ្រាន់ ដើម្បីឱ្យ "ការងារដែលបានបង្កើត" ឬ "គ្រួសារដែលបានបម្រើ" មានន័យដូចគ្នាមិនថានរណារាយការណ៍ ហើយតម្រឹមទៅនឹងគោលដៅអភិវឌ្ឍន៍ប្រកបដោយនិរន្តរភាពរបស់អង្គការសហប្រជាជាតិ (SDG) ដើម្បីឱ្យអ្នកផ្តល់មូលនិធិអាចបូកទិន្នន័យកម្រិតអ្នកទទួលជំនួយឡើងទៅជារឿងរ៉ាវ SDG កម្រិតផលប័ត្រ។ GIIN រាយការណ៍ថារង្វាស់ IRIS ត្រូវបានប្រើដោយប្រហែលពាក់កណ្តាលនៃអ្នកវិនិយោគផលប៉ះពាល់ និងភាគច្រើនលើសលប់នៃអ្នកគ្រប់គ្រងមូលនិធិ ធនាគារ និងស្ថាប័នហិរញ្ញវត្ថុអភិវឌ្ឍន៍ដែលសកម្មក្នុងវិស័យ។

ស្តង់ដារមានសារៈសំខាន់បំផុតនៅកន្លែងដែលវាទាក់ទងនឹង [លទ្ធផល ធៀបនឹងលទ្ធផលផ្ទាល់](../លទ្ធផល-ធៀបនឹង-ទិន្នផល/)៖ IRIS+ ជំរុញការរាយការណ៍ឆ្ពោះទៅរករង្វាស់លទ្ធផល និងផលប៉ះពាល់ដែលបានកំណត់ ជាជាងអ្វីក៏ដោយដែលប្រព័ន្ធគ្រប់គ្រងករណីដែលមានស្រាប់របស់អ្នកទទួលជំនួយកត់ត្រា ដែលជាគម្លាតដូចដែល [តម្លៃក្នុងមួយលទ្ធផល](../ថ្លៃចំណាយក្នុងមួយលទ្ធផល/) ធៀបនឹង [តម្លៃក្នុងមួយអ្នកទទួលផល](../ថ្លៃចំណាយក្នុងមួយអ្នកទទួលផល/) ពណ៌នា។

## គណិតវិទ្យា

ការរាយការណ៍លទ្ធផលជំនួយគឺជាក្របខ័ណ្ឌ និងដំណើរការ មិនមែនរូបមន្តទេ៖

```
1. Funder selects a Core Metrics Set relevant to the grant's theme
   (e.g. IRIS+ "Financial Inclusion" or "Sustainable Agriculture")
2. Each metric has a fixed definition, unit, and calculation method
   published by GIIN — not invented per-funder
3. Grantee reports against the same metric definitions across all
   its funders using that standard, cutting duplicate reporting effort
4. Funder aggregates grantee-level metrics into portfolio-level reporting,
   comparable year over year and across grantees using the same metric
```

ផលចំណេញប្រសិទ្ធភាពគឺជាបន្សំ៖ ការធ្វើស្តង់ដារ N អ្នកផ្តល់មូលនិធិ × M អ្នកទទួលជំនួយ ទៅលើវាក្យសព្ទរួមតែមួយ ប្តូរទំនាក់ទំនងរាយការណ៍តាមតម្រូវ N×M ទៅជាការផ្គូផ្គងប្រហែល N+M ធៀបនឹងស្តង់ដារតែមួយ។

## ឧទាហរណ៍គណនា

**អ្នកទទួលជំនួយដែលមានអ្នកផ្តល់មូលនិធិបីនាក់ មុនការធ្វើស្តង់ដារ**៖ រាយការណ៍ "មនុស្សដែលបានបម្រើ" ទៅអ្នកផ្តល់មូលនិធិទី 1 ដោយប្រើនិយមន័យរាប់ក្បាល "អ្នកទទួលផលដែលបានទៅដល់" ទៅអ្នកផ្តល់មូលនិធិទី 2 ដោយប្រើនិយមន័យគ្រួសារ និង "បុគ្គលដែលរងផលប៉ះពាល់" ទៅអ្នកផ្តល់មូលនិធិទី 3 ដោយប្រើនិយមន័យវគ្គសេវា (ដូច្នេះបុគ្គលម្នាក់មកពីរដងរាប់ពីរដង)។ របាយការណ៍បី លេខបី គ្មានលេខណាប្រៀបធៀបបាន ហើយក៏មិនអាចប្រៀបធៀបជាមួយលេខរបស់អ្នកទទួលជំនួយផ្សេងបានដែរ សូម្បីក្នុងផលប័ត្ររបស់អ្នកផ្តល់មូលនិធិតែមួយ។

**អ្នកទទួលជំនួយដដែលក្រោម IRIS+**៖ រាយការណ៍តាមរង្វាស់ IRIS+ បុគ្គលដែលបានទៅដល់ដែលបានកំណត់ រួមជាមួយរង្វាស់លទ្ធផលដែលបានកំណត់ពីសំណុំរង្វាស់ស្នូលដែលពាក់ព័ន្ធ ដោយប្រើវិធីសាស្ត្រគណនាដែលបានបោះពុម្ពផ្សាយរបស់ GIIN សម្រាប់ទាំងពីរ។ អ្នកផ្តល់មូលនិធិទាំងបីឥឡូវទទួលបានលេខដូចគ្នា គណនាតាមរបៀបដូចគ្នា ហើយអាចប្រៀបធៀបតម្លៃក្នុងមួយឯកតា IRIS+ របស់អ្នកទទួលជំនួយនេះជាមួយអ្នកទទួលជំនួយផ្សេងក្នុងផលប័ត្ររបស់ខ្លួន ដោយប្រើរង្វាស់ដូចគ្នា — ស្មើនឹង នៅកម្រិតហេដ្ឋារចនាសម្ព័ន្ធរាយការណ៍ ការមាន [មូលដ្ឋានទិន្នន័យតម្លៃឯកតា](../មូលដ្ឋានទិន្នន័យថ្លៃចំណាយឯកតា/) រួម។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

វេទិកាគ្រប់គ្រងជំនួយគួរចាត់ទុកអត្តសញ្ញាណរង្វាស់ IRIS+ ជាកូនសោបរទេស មិនមែនអត្ថបទសេរីទេ៖ ការរក្សាទុកកូដរង្វាស់ដែលបានបោះពុម្ពផ្សាយ ជាមួយតម្លៃដែលអ្នកទទួលជំនួយរាយការណ៍ (ជាជាងវាលដែលបង្កើតក្នុងស្រុកឈ្មោះ "beneficiaries") គឺជាអ្វីដែលធ្វើឱ្យការបូកសរុបឆ្លងអ្នកផ្តល់មូលនិធិ និងឆ្លងផលប័ត្រអាចធ្វើទៅបានក្រោយមក ដោយគ្មានគម្រោងសម្អាតទិន្នន័យ។ នៅកន្លែងដែលវេទិកាត្រូវគាំទ្រអ្នកផ្តល់មូលនិធិដែលមិនទាន់ប្រើ IRIS+ ការរចនាជាក់ស្តែងគឺអនុញ្ញាតឱ្យផ្គូផ្គងរង្វាស់ក្នុងស្រុកទៅនិយមន័យ IRIS+ ដែលជិតបំផុត ជាជាងបង្ខំអ្នកផ្តល់មូលនិធិគ្រប់រូបទៅស្តង់ដារភ្លាមៗ — ភាពអាចប្រៀបធៀបបានប្រសើរឡើងបន្តិចម្តងៗ នៅពេលដែលក្រាហ្វកាន់តែច្រើនផ្គូផ្គងទៅអត្តសញ្ញាណរួម។ សូមមើលប្រធានបទបងប្អូន [តម្លៃក្នុងមួយលទ្ធផល](../ថ្លៃចំណាយក្នុងមួយលទ្ធផល/) ស្តីពីអ្វីដែលលេខដែលបានរាយការណ៍គួរប្រើដើម្បីគណនា បន្ទាប់ពីប្រមូលបាន។

## កំហុសដែលតែងកើតមាន

- **ចាត់ទុកការទទួលយក IRIS+ ជាភាពអាចប្រៀបធៀបដោយស្វ័យប្រវត្តិ។** អ្នកទទួលជំនួយពីរអាចរាយការណ៍តាមរង្វាស់ IRIS+ ដូចគ្នា ហើយនៅតែមិនអាចប្រៀបធៀបបាន ប្រសិនបើគុណភាពទិន្នន័យមូលដ្ឋាន ឬសម្មតិកម្មស្ថានភាពប្រៀបធៀបខុសគ្នា។ ស្តង់ដារកំណត់និយមន័យ មិនមែនភាពតឹងរ៉ឹងនៃការវាស់ទេ។
- **រង្វាស់ "ស្របតាម IRIS" ដែលអ្នកផ្តល់មូលនិធិបង្កើតខ្លួនឯង។** រង្វាស់ដែលគ្រាន់តែបំផុសគំនិតដោយភាសា IRIS+ ប៉ុន្តែមិនមែននិយមន័យដែលបានបោះពុម្ពផ្សាយពិតប្រាកដ នាំចូលឡើងវិញនូវការបែកបាក់ដែលស្តង់ដារមានដើម្បីដោះស្រាយ។
- **ភាពនឿយហត់ពីការរាយការណ៍ដោយសារជ្រើសរើសច្រើនពេក។** ការតម្រូវឱ្យអ្នកទទួលជំនួយរាយការណ៍តាមសំណុំរង្វាស់ស្នូលទាំងមូល នៅពេលដែលមានតែរង្វាស់ពីរ ឬបីទេដែលពាក់ព័ន្ធនឹងការសម្រេចចិត្ត បង្កើតបញ្ហាបន្ទុកឡើងវិញក្នុងរុំស្តង់ដារ។
- **គ្មានរង្វាស់លទ្ធផលសោះ។** IRIS+ រួមមានរង្វាស់លទ្ធផលផ្ទាល់សុទ្ធជាច្រើន (ឧទាហរណ៍ ចំនួនមនុស្សដែលបានបម្រើ)។ ការជ្រើសរើសតែទាំងនោះ ហើយគ្មានរង្វាស់កម្រិតលទ្ធផលសោះ បង្កើតការរាយការណ៍ដែលមានរូបរាងជា [តម្លៃក្នុងមួយអ្នកទទួលផល](../ថ្លៃចំណាយក្នុងមួយអ្នកទទួលផល/) ក្រោមស្លាកការរាយការណ៍លទ្ធផល។
