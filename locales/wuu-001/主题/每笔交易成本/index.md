# 每笔交易成本

每笔交易成本(cost per transaction)是政府数字服务个标题单位经济指标:交付一个渠道个总成本,除以通过该渠道完成个交易数。伊是老 GOV.UK 绩效平台上个旗舰数字,也是资助仔十年“数字优先”投资个数字——正因如此,伊也是最容易被玩弄个指标。

## 为啥重要

内阁办公室(Cabinet Office)2012 年个《数字效率报告》拿渠道成本比较讲得让人印象深刻:数字交易个成本发现比电话便宜大约 20 倍,比当面便宜大约 50 倍,地方政府个示意数字大约是每笔网上交易 £0.15,电话 £2.83,当面 £8.62。搿个单一比较成为重新设计《政府数字战略》里点名个 25 项示范服务个理由,也成为从此以后每份引用渠道转移节省个部门业务案例个理由。搿个数字作为数量级信号真个有用,但是比率完全取决于两边各算进去啥:一个公道个电话渠道成本包括呼叫中心个员工、电话合同、培训搭场地;一个公道个数字成本包括托管、持续个产品团队薪资、为失败流程配个支持台辰光,以及[数字服务标准](../数字服务标准/)第 5 条要求个辅助数字渠道。拿数字一边个搿些去脱足够多,任何服务看上去侪便宜。

## 数学

```
每笔交易成本 = 分摊个渠道总成本 / 完成个交易

分摊个渠道总成本应该包括:
  + 托管搭基础设施
  + 产品/工程/支持团队成本(摊销)
  + 内容搭服务设计成本(摊销)
  + 辅助数字/无障碍支持成本
  + 失败需求成本(数字失败、退回电话个用户)
  − 一次性建设成本按预期服务寿命摊销,
    勿是全部一次性记勒第一年

常见个会计把戏:
  “边际每笔交易成本”(建好以后只算托管)被当作
  “平均每笔交易成本”(包括继续建设搭运行伊个
  团队个总成本)来引用。对一个有庞大、活跃交付团队
  个服务,两者可以相差 10 倍以上。
```

## 实例演算

**车辆税续期服务**:每年 400 万笔交易。

```
只算边际个数字(把戏):
  只有托管 + 支付处理 = £180,000/年
  每笔交易成本 = 180,000 / 4,000,000 = £0.045
  → 业务案例里引用个标题数字

全部成本都算进去个数字(老实个):
  托管 + 支付                          £180,000
  产品/工程团队(8 FTE)               £720,000
  支持台(失败/有疑问个交易)          £310,000
  辅助数字电话专线                     £140,000
  合计                                 £1,350,000
  每笔交易成本 = 1,350,000 / 4,000,000 = £0.3375

全部成本算进去个数字,还是比《数字效率报告》里
£2.83 个电话渠道对照便宜大约 8 倍 —— 是真个、
站得牢个节省 —— 但是比捷径版本里引用个只算边际
个数字高 7.5 倍。两个数字侪是“真个”;只有一个
搭伊被拿来对照个电话渠道成本是可比个。
```

## 搭软件工程个关联

每笔交易成本是架构决策变成财务数字个地方:一个自动伸缩顺畅、勿大需要人工干预个服务,会让搿个数字随辰光下降;一个因为令人困惑个错误状态产生大量支持工单个服务,勿管托管效率哪能,侪会让伊上升。伊是[数字服务标准](../数字服务标准/)第 10 条(“定义成功是啥样,并且公布绩效数据”)个天然配套指标,也是[服务标准搭交易指标](../服务标准搭交易指标/)个配套指标,后者列出搿个数字所处个更完整个 KPI 集。伊也直接喂给[渠道转移节省](../渠道转移节省/)个计算,并且应该搭[政府 IT 个总拥有成本](../政府-it-里个总拥有成本/)对账,免得平台搭共享服务个间接费用被悄悄漏脱。

## 容易踏个坑

- **拿边际成本打扮成平均成本**:服务建好以后引用只有托管个成本,漏脱持续维护、迭代搭支持个团队——参见上面个实例演算。
- **排除辅助数字成本**:如果[数字包容](../数字包容/)要求个电话/纸质兜底个成本单独算或者忽略,搿个渠道就勿算符合“数字优先”,伊个真实成本也捉勿到。
- **忽略失败需求**:从数字开始但是失败、最后还是产生一个电话或者纸质表格个交易,是数字渠道个成本,勿是接住失败个渠道个成本。
- **跨渠道比较复杂度勿同个交易**:电话勿成比例地处理难个个案(多个受抚养人、错误更正、脆弱个申请人);拿电话个平均成本搭数字个平均成本比,除非交易组合匹配,否则会夸大比率。
