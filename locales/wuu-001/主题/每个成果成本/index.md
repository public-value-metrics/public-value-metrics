# 每个成果成本

每个成果成本(cost per outcome)是项目总支出除以真正实现仔明确定义、有意义个境况改变个人数——勿是光接受过服务个人数。伊是出资方或者交付团队好用个最锋利个效率指标,因为伊逼牢大多数慈善机构回避个一个在先问题:到底啥个才算成功?

## 为啥重要

一家食物银行从同一年个账目里,可以报告两个相差交关大个数字。每发出一个食物包个成本可能是 £15。每个后来达到食物安全个家庭——勿再需要紧急食物援助,勒跟进个辰光点核实过——个成本可能是 £340。两个侪是真个。只有一个告诉出资方钱到底起勿起作用。两者之间个差距,就是产出搭成果之间个差距:递出去一个食物包是产出;一个家庭勿再处勒危机里是成果。参见[成果搭产出](../成果搭产出/)。

英国第三部门花仔二十年搭建基础设施,逼牢大家分清搿个区别。New Philanthropy Capital 个“四支柱方法”(four pillar approach)评估慈善机构有效性,明确要求组织先讲成果、再讲产出;Inspiring Impact——英国由出资方支持个影响测量协作组织——发布一份成果矩阵(Outcomes Matrix),现在交关补助申请要求慈善机构填。Trussell Trust 搭 Heriot-Watt 大学合作个年度“State of Hunger”研究项目,正是因为光有食物包数量,讲勿出来人民到底有无摆脱食物勿安全。

每个成果成本只有勒固定仔反事实以后才有意义:“勿搭仔也会”达成个成果,勿是项目买来个成果。参见[反事实分析](../反事实分析/)搭[转移搭归因](../挤出效应搭归因/)。

## 数学

```
每个成果成本 = 项目总成本 / 达成所定义成果个受益人数

其中:
  项目总成本   = 直接交付成本 + 管理费用个合理分摊
  所定义个成果 = 预先指定、好测量个状态改变
                 (比方“6 个月跟进时食物安全”,
                 勿是“收到一个食物包”)
```

拿搿个数字搭[单位成本数据库](../单位成本数据库/)(比方行业专门个单位成本基准)对比,判断某个每个成果成本相对可比干预是好、一般还是差。

## 实例演算

**食物银行,一年**:

- 项目总成本:£450,000
- 发出个食物包:30,000
- 每个食物包个成本(产出指标):£450,000 / 30,000 = **£15**

搿家慈善机构还对一批家庭样本做六个月跟进问卷,发现收到三个以上食物包个家庭里,35% 报告勿再需要紧急食物援助,而且勒标准食物安全问卷模块上个得分超过食物安全门槛。那年收到三个以上食物包个 1,800 户家庭里,630 户达成搿个成果。

```
每个成果成本 = £450,000 / 630 = 每个达到食物安全个家庭 £714
```

拿搿家慈善机构搭现金转移试点或者债务建议服务比较个出资方,应该用 £714 搿个数字——勿是 £15。如果同一地区个一个可比现金转移项目,每家达到食物安全个成本是 £500,食物银行显然勿是达成同一个成果更有效率个路径,尽管伊每个食物包个成本看上去便宜。

## 搭软件工程个关联

大多数个案管理系统是为记录产出建个,因为产出是勒交易里向发生个(递出一个食物包、提交一张表格)。成果通常发生勒后头,经常勒系统正常捕获个窗口之外,需要有意识个设计决定:拿跟进机制(问卷触发、重新联系个工作流、数据关联)当作一等功能来建,勿是为年报勒后头硬塞进去个补丁。给行业做补助管理或者个案管理平台个工程师,应该拿“成果事件是啥,阿拉哪能观察到”当作需求问题,勒数据模型定下来之前就问——事后补一个成果字段,比补一个产出计数器难得多。参见[成果搭产出](../成果搭产出/)搭[逻辑模型](../逻辑模型/),了解哪能组织搿场需求对话;参见[每个受益人成本](../每个受益人成本/),了解成果跟踪还呒没建好个辰光团队伸手去拿个更快、更粗糙个指标。

## 容易踏个坑

- **拿产出打扮成成果来报告。** “触达个人数”勿等于“帮助个人数”。如果搿个指标靠系统日志就产得出来,勿需要跟进联系,几乎肯定是产出。
- **玩弄分母。** 拿成果人群缩窄到“完成项目个人”,悄悄丢脱仔中途退出个人——经常是最难个个案——拉高表面比率。分母要定为所有开始个人,勿是所有结束个人。
- **无没反事实。** 拿达成成果个每个人侪算进去,包括勿搭仔也会达成个人,会夸大项目买到个东西。参见[反事实分析](../反事实分析/)。
- **勒勿兼容个成果定义之间比较。** 用验证过个问卷模块量个“食物安全”,搭勒满意度表格里自己报告个“食物安全”勿好比;只有成果定义一致,每个成果成本个排行榜才是老实个。
