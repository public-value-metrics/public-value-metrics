# 渠道转移节省

渠道转移节省(channel shift savings)是指拿交易量从昂贵个渠道——电话、当面柜台、纸质邮寄——搬到便宜个数字自助服务以后,预计减少个成本。伊是“数字优先”背后个财务引擎,也是业务案例里最容易算错个一项,因为伊依赖个假设——数字使用率上升,线下渠道就跟牢缩小——只有有辰光才成立。

## 为啥重要

用《数字效率报告》(Digital Efficiency Report)里个[每笔交易成本](../每笔交易成本/)数字来算,算术看上去无可辩驳:拿一百万笔交易从每次 £8.62 个当面到访,搬到每次 £0.15 个数字渠道,节省超过 800 万镑。但是一笔节省只有当搿个收缩渠道个*固定产能*真个被撤销——呼叫中心个席位、柜台人员、电话合同分钟数——才会变成可以重新调配个现金;地方政府个数字项目一再发现,总联系量勿会跟牢数字使用率一道下降。地方政府数字转型项目,搭 Socitm、地方政府协会(Local Government Association)之类机构个研究,记录仔一个反复出现个规律:数字渠道会吸引真正新增个联系(本来勿会打电话或者上门个市民,因为方便仔现在会了),而且“数字”交易里有相当一部分勒半路失败,还是会产生一个电话——所以电话量下降个幅度,比数字使用率个百分比所暗示个小得多,有辰光绝对数上根本勿降,只是伊勒总联系量里个*占比*下降。

## 数学

```
渠道转移总节省 = 转移量 × (旧渠道成本 − 数字渠道成本)

净(兑现)节省 = 总节省
               − 更容易个渠道创造个新增/影子需求
               − 失败需求成本(数字渠道失败,
                 但还是产生一个电话或者柜台到访)
               − 未撤销固定产能个成本(呼叫中心
                 只好按整档减人;业务量降 15%,
                 勿大可能刚好裁 15% 个人头)

兑现门槛:只有业务量降到旧渠道可以配置个、
下一个更小个整档产能台阶以下,节省才好入账
(比方少一个整班、一个整桌、一个合同人头档)
```

## 实例演算

**郡议会个蓝徽章(blue badge)续期服务**:每年 60,000 笔续期,以前 100% 电话/纸质,每笔 £6.40。一个新个数字服务上线,一年内达到 65% 个数字使用率,每笔数字交易 £0.30。

```
天真(总额)个节省计算:
  39,000 转移 × (£6.40 − £0.30) = £237,900/年

按议会联络中心数据,实际发生个情况:
  电话量从 60,000/年 降到 46,000/年(−23%,勿是 −65%)
  原因:9,000 个数字流程失败,产生仔后续电话
        (失败需求外溢),还有 4,000 个本来根本勿续期
        个人,发现线上容易就续了
        (影子需求 —— 是真正个可及性改善,但勿是节省)

  电话联络中心按每 FTE 8,000 通电话个档位配置;
  减少 14,000 通(60,000 → 46,000)释放 1.75 个 FTE,
  实际向下取整,真个重新调配个是 1 个 FTE = £34,000/年

兑现节省 = £34,000/年,加上 39,000 笔交易避免个数字渠道
  建设/运行成本 ≈ £34,000 + (39,000 × £0.30
  数字成本已经算过)—— 只是 £237,900 标题数字个一小部分,
  但是搿个服务对用户来讲还是明明白白变好仔。
```

## 搭软件工程个关联

工程上个教训是:渠道转移节省是靠*运营*决策(排班、撤销、合同重新谈判)兑现个,勿是靠软件发布——一个团队可以满足每一条[数字服务标准](../数字服务标准/),如果无人撤销旧渠道个固定产能,净节省照样是零。拿失败需求仪表化(用户勒数字流程个哪搭放弃、之后又去做啥),是一个可以解决个漏斗分析问题,也是工程团队保护节省案例杠杆最大个一桩事体;伊也是搭[每笔交易成本](../每笔交易成本/)直接相连个环节,失败需求会悄悄拿伊推高。参见[收益兑现](../收益兑现/),了解检查业务案例节省是否真个落地个更大范围个方法;参见[数字包容](../数字包容/),了解为啥线下渠道通常无法、也勿应该完全退役。

## 容易踏个坑

- **假设渠道 1:1 替代**:拿数字使用率直接当作电话/柜台量个减法来建模,忽略地方政府渠道转移研究里记录个影子需求搭失败需求外溢。
- **撤销之前就入账总节省**:勒使用率上升个搿一年就勒业务案例里计入节省,勿是勒旧渠道产能真个被削减个搿一年(如果有个话)。
- **忽略人员成本个阶梯函数性质**:业务量降 20%,成本罕见刚好降 20%,因为联络中心搭柜台是按整档配置个,勿是连续个。
- **拿影子需求当浪费**:来自以前被排除或者被劝退个用户个新增联系,是[公共价值](../公共价值/)真个增加,勿是建模错误——应该作为可及性成果报告,勿要当噪音抵销脱。
