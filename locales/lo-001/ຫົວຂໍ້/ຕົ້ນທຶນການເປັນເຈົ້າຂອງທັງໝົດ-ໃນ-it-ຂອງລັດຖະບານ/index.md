# ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ (TCO) ໃນ IT ຂອງລັດຖະບານ

ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ (total cost of ownership) ແມ່ນຕົ້ນທຶນຕະຫຼອດວົງຈອນຊີວິດຂອງລະບົບ — ຕົ້ນທຶນການຈັດຫາບວກທຸກປີຂອງການດຳເນີນງານ — ຄິດຫຼຸດມາເປັນວັນທີດຽວກັນ. ໃນ IT ຂອງລັດຖະບານ, ຄວາມຜິດພາດໃນການຄາດການທີ່ເຊື່ອຖືໄດ້ທີ່ສຸດຢ່າງດຽວແມ່ນການປຽບທຽບຜູ້ສະໜອງ ຫຼື ທາງເລືອກດ້ວຍລາຄາການຈັດຫາພຽງຢ່າງດຽວ, ທັງທີ່ການດຳເນີນງານ ແລະ ການບຳລຸງຮັກສາໂດຍທົ່ວໄປກວມປະມານເຄິ່ງໜຶ່ງເຖິງສີ່ໃນຫ້າຂອງໃບບິນຕະຫຼອດອາຍຸ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

Green Book ຂອງ HM Treasury ກຳນົດໃຫ້ກໍລະນີການເງິນໃນແຜນທຸລະກິດແບບຫ້າກໍລະນີ (Five Case Model) ທຸກສະບັບຄອບຄຸມຕົ້ນທຶນຕະຫຼອດອາຍຸ, ບໍ່ແມ່ນພຽງລາຍຈ່າຍທຶນ — ແຕ່ສຳນັກງານກວດສອບແຫ່ງຊາດ (National Audit Office) ໄດ້ພົບຊ້ຳແລ້ວຊ້ຳອີກວ່າ ກະຊວງອະນຸມັດການລົງທຶນ IT ໂດຍອີງໃສ່ການຄາດການຄ່າໃຊ້ຈ່າຍດຳເນີນງານທີ່ບໍ່ຄົບຖ້ວນ ຫຼື ມອງໃນແງ່ດີເກີນໄປ, ແລ້ວຈຶ່ງຄົ້ນພົບຕົ້ນທຶນການດຳເນີນງານທີ່ແທ້ຈິງເມື່ອລະບົບເປີດໃຊ້ແລ້ວ ແລະ ແຖວງົບປະມານທຶນປິດໄປແລ້ວ. Technology Code of Practice (<https://www.gov.uk/guidance/the-technology-code-of-practice>) ຂອງ Government Digital Service ແລະ Central Digital and Data Office ຊຸກຍູ້ກະຊວງໄປສູ່ຄລາວ ແລະ ການໂຮດແບບສິນຄ້າທົ່ວໄປ ສ່ວນໜຶ່ງກໍເພາະມັນເຮັດໃຫ້ຕົ້ນທຶນຕໍ່ເນື່ອງເຫັນໄດ້ ແລະ ປຽບທຽບໄດ້, ແທນທີ່ຈະຝັງຢູ່ໃນຕົວເລກຈັດຊື້ທຶນດຽວທີ່ເບິ່ງຕ່ຳໜ້າດຶງດູດຕອນອະນຸມັດ ແລະ ຜິດແພງຫຼັງຈາກສາມປີ.

## ຄະນິດສາດ

```
TCO = Acquisition cost + Σ(t=1..N) Annual operating cost_t / (1+r)^t
      − residual value (discounted)

r = HM Treasury Green Book standard social discount rate, 3.5%/year
    (declining rate schedule for horizons beyond 30 years)

Operating cost components: hosting/licensing, support and maintenance,
security patching and compliance, staff time, planned refresh/migration
```

ເບິ່ງ [ອັດຕາຄິດຫຼຸດທາງສັງຄົມ](../ອັດຕາຄິດຫຼຸດທາງສັງຄົມ/) ສຳລັບເຫດຜົນທີ່ປັດໄຈຄິດຫຼຸດສຳຄັນຕະຫຼອດອາຍຸລະບົບທົ່ວໄປ 5–10 ປີ, ແລະ [ການສ້າງເອງ ທຽບກັບ ການຊື້ ໃນລັດຖະບານ](../ສ້າງເອງ-ຫຼື-ຊື້-ໃນລັດຖະບານ/) ສຳລັບວິທີທີ່ TCO ປ້ອນເຂົ້າການຕັດສິນໃຈສ້າງ/ຊື້.

## ຕົວຢ່າງການຄິດໄລ່

ກະຊວງແຫ່ງໜຶ່ງປຽບທຽບສອງລະບົບຄຸ້ມຄອງກໍລະນີໃນຂອບເຂດ 5 ປີ ທີ່ອັດຕາຄິດຫຼຸດ 3.5% ຂອງ Green Book.

```
System A: capex £3,500,000, opex £250,000/year
System B: capex £1,800,000 (looks cheaper), opex £650,000/year
          (heavier vendor support and integration burden)

Naive comparison on capex alone: B wins, £1.8M < £3.5M.

Discount factor sum, 5 years at 3.5%: 0.966+0.934+0.902+0.871+0.842 ≈ 4.515

TCO_A = 3,500,000 + 250,000 × 4.515 = 3,500,000 + 1,128,750 = £4,628,750
TCO_B = 1,800,000 + 650,000 × 4.515 = 1,800,000 + 2,934,750 = £4,734,750
```

TCO ພລິກການຕັດສິນໃຈແບບໜ້າຕາ: ລະບົບ B ແພງກວ່າເລັກນ້ອຍຕະຫຼອດຫ້າປີ ເມື່ອຄິດຫຼຸດ ແລະ ລວມຕົ້ນທຶນດຳເນີນງານ, ເພາະສັດສ່ວນ opex ຂອງມັນຕໍ່ຕົ້ນທຶນຕະຫຼອດອາຍຸແມ່ນ 62% (2,934,750 / 4,734,750) ທຽບກັບ 24% ຂອງລະບົບ A — ຕົວຢ່າງຮູບປະທຳຂອງຂໍ້ຄົ້ນພົບ "ການບຳລຸງຮັກສາເປັນສ່ວນໃຫຍ່ຂອງໃບບິນ" ທີ່ຖືກປິດບັງຢ່າງສິ້ນເຊີງໂດຍການປຽບທຽບລາຄາທີ່ຕິດຢູ່ໜ້າສິນຄ້າ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

TCO ແມ່ນຕົວເລກທີ່ຄວນເປັນລະບຽບວິໄນຂອງທຸກການຕັດສິນໃຈ[ສ້າງເອງ ທຽບກັບ ຊື້](../ສ້າງເອງ-ຫຼື-ຊື້-ໃນລັດຖະບານ/) ແລະ ທຸກກໍລະນີການຊຳລະ[ໜີ້ທາງເທັກນິກ](../ໜີ້ທາງເທັກນິກໃນຖານະການກັດກ່ອນຄຸນຄ່າສາທາລະນະ/), ເພາະດອກເບ້ຍໜີ້ ແລະ ການບຳລຸງຮັກສາທີ່ເລື່ອນອອກໄປ ເປັນແຖວຕົ້ນທຶນດຳເນີນງານທີ່ຢູ່ໃນຍອດລວມທີ່ຄິດຫຼຸດດຽວກັນ, ບໍ່ວ່າໃຜຈະເຄີຍຕິດຕາມພວກມັນຫຼືບໍ່. ວິສະວະກອນທີ່ສະເໜີການເລືອກແພລດຟອມ ຫຼື ຜູ້ຂາຍຄວນນຳສະເໜີຕາຕະລາງ TCO ເຕັມ, ບໍ່ແມ່ນລາຄາຈັດຊື້, ເພາະລາຄາຈັດຊື້ແມ່ນຕົວເລກທີ່ກໍລະນີການເງິນຂອງ Green Book ຖືກອອກແບບເພື່ອຢຸດບໍ່ໃຫ້ກະຊວງອີງໃສ່ຢ່າງດຽວ. TCO ຍັງເປັນຕົວຫານທີ່ຊື່ສັດສຳລັບການຕັດສິນ[ຄວາມຄຸ້ມຄ່າເງິນ](../ຄວາມຄຸ້ມຄ່າເງິນ/) — VFM ປຽບທຽບຜົນປະໂຫຍດກັບຕົ້ນທຶນ, ແລະ ແຖວຕົ້ນທຶນທີ່ນັບຕ່ຳເກີນໄປເຮັດໃຫ້ອັດຕາສ່ວນ VFM ທຸກອັນໃນແຜນທຸລະກິດພອງຕົວ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ການປຽບທຽບສະເພາະ capex**: ຄວາມຜິດພາດໃນການຈັດຊື້ຈັດຈ້າງທີ່ພົບເລື້ອຍທີ່ສຸດ — ການປຽບທຽບລາຄາຂາຍຂອງຜູ້ສະໜອງໂດຍບໍ່ມີການຄາດການຕົ້ນທຶນດຳເນີນງານທີ່ຈັບຄູ່ກັນສຳລັບແຕ່ລະທາງເລືອກ.
- **ການຍົກເວັ້ນຕົ້ນທຶນການອອກ ແລະ ການຍ້າຍ**: ການສະກັດຂໍ້ມູນເມື່ອສັນຍາສິ້ນສຸດ, ການປ່ຽນແພລດຟອມ, ແລະ ຄ່າປັບຈາກການຖືກລັອກກັບຜູ້ຂາຍ ເປັນແຖວ TCO ຕົວຈິງທີ່ແທບບໍ່ປາກົດໃນແຜນທຸລະກິດຕົ້ນສະບັບ.
- **ການຍົກເວັ້ນຕົ້ນທຶນຄວາມປອດໄພ ແລະ ການປະຕິບັດຕາມກົດລະບຽບ**: ຈັງຫວະການແພັດຊ໌, ການຕໍ່ໃບຮັບຮອງ, ແລະ ຄ່າກວດສອບເພີ່ມຕາມອາຍຸ ແລະ ຄວາມຊັບຊ້ອນຂອງລະບົບ — ເບິ່ງ [ມູນຄ່າຄວາມປອດໄພທາງໄຊເບີໃນພາກລັດ](../ມູນຄ່າຂອງຄວາມປອດໄພທາງໄຊເບີໃນພາກລັດ/) — ແລະ ຖືກຕັດອອກຈາກການຄາດການ opex ເປັນປະຈຳ.
- **ການປຽບທຽບທີ່ບໍ່ຄິດຫຼຸດລະຫວ່າງທາງເລືອກທີ່ມີໂປຣໄຟລ໌ຕົ້ນທຶນຕ່າງກັນ**: ການປຽບທຽບທາງເລືອກທີ່ໜັກ capex ກັບທາງເລືອກທີ່ໜັກ opex ໂດຍບໍ່ຄິດຫຼຸດ ເອື້ອປະໂຫຍດຢ່າງເປັນລະບົບຕໍ່ທາງເລືອກໃດກໍຕາມທີ່ເລື່ອນຕົ້ນທຶນໄປປີຫຼັງໆຫຼາຍກວ່າ.
