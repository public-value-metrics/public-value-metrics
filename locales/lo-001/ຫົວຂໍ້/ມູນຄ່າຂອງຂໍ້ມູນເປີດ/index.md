# ມູນຄ່າຂອງຂໍ້ມູນເປີດ

ມູນຄ່າຂອງຂໍ້ມູນເປີດແມ່ນບັນຫາການຄາດຄະເນວ່າຂໍ້ມູນຂອງລັດຖະບານ ແລະ ຂໍ້ມູນສາທາລະນະມີຄຸນຄ່າເທົ່າໃດ ເມື່ອມັນບໍ່ມີລາຄາ: ມັນບໍ່ໄດ້ຖືກຂາຍ, ຈຶ່ງບໍ່ມີລາຍຮັບ, ແຕ່ການປ່ອຍມັນອອກ (ບັນທຶກສະພາບອາກາດ, ຕາຕະລາງການເດີນທາງ, ຂອບເຂດລະຫັດໄປສະນີ, ທະບຽນບໍລິສັດ) ສ້າງກິດຈະກຳທາງເສດຖະກິດ ແລະ ສັງຄົມຢູ່ປາຍນ້ຳຢ່າງເຫັນໄດ້ຊັດ. ການປະເມີນມູນຄ່າມັນໃຫ້ດີສຳຄັນ ເພາະທັງ "ປ່ອຍອອກໄດ້ໂດຍບໍ່ເສຍຄ່າ" ແລະ "ບໍ່ມີຄ່າຫຍັງເລີຍ" ລ້ວນຜິດ, ແລະ ວິສະວະກອນຊອບແວທີ່ຕັດສິນໃຈວ່າຈະເປີດ API ຫຼື ຊຸດຂໍ້ມູນຫຼືບໍ່ ຕ້ອງການເຫດຜົນທີ່ດີກວ່າທັງສອງຢ່າງນັ້ນ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ການຄາດຄະເນແບບເທິງລົງລຸ່ມທີ່ຖືກອ້າງເຖິງຫຼາຍທີ່ສຸດມາຈາກລາຍງານປີ 2013 ຂອງ McKinsey Global Institute ຊື່ "Open data: Unlocking innovation and performance with liquid information", ເຊິ່ງກຳນົດມູນຄ່າທີ່ເປັນໄປໄດ້ປະຈຳປີຂອງຂໍ້ມູນເປີດໃນເຈັດຂະແໜງ — ການສຶກສາ, ການຂົນສົ່ງ, ຜະລິດຕະພັນຜູ້ບໍລິໂພກ, ໄຟຟ້າ, ນ້ຳມັນ ແລະ ອາຍແກັສ, ສຸຂະພາບ, ແລະ ການເງິນຜູ້ບໍລິໂພກ — ໄວ້ທີ່ $3 ລ້ານລ້ານ ຫາ $5 ລ້ານລ້ານຕໍ່ປີທົ່ວໂລກ, ຜ່ານກົນໄກຕ່າງໆ ລວມທັງຄວາມໂປ່ງໃສທີ່ເພີ່ມຂຶ້ນ, ການຈັບຄູ່ອຸປະທານກັບອຸປະສົງຢ່າງມີປະສິດທິພາບກວ່າ, ແລະ ການເປີດໂອກາດໃຫ້ຜະລິດຕະພັນ ແລະ ບໍລິການໃໝ່ທີ່ສ້າງຢູ່ເທິງຂໍ້ມູນ. ຕົວເລກນັ້ນເປັນການຄາດຄະເນຕາມສະຖານະການ, ບໍ່ແມ່ນຜົນທີ່ວັດແທກໄດ້ຈິງ, ແລະ ມັກຖືກອ້າງຜິດຄືກັບວ່າເປັນລາຍຮັບທີ່ລັດຖະບານສາມາດເກັບໄດ້ໂດຍກົງ, ທັງທີ່ມູນຄ່າສ່ວນໃຫຍ່ຕົກຢູ່ກັບບຸກຄົນທີສາມ — ທຸລະກິດ, ນັກຄົ້ນຄວ້າ, ພົນລະເມືອງ — ທີ່ໃຊ້ຂໍ້ມູນ, ເຊິ່ງເປັນຈຸດປະສົງຂອງການເປີດແທນການຂາຍພໍດີ. Open Data Institute ຂອງ UK, ກໍ່ຕັ້ງຮ່ວມໂດຍ Sir Tim Berners-Lee ແລະ Sir Nigel Shadbolt ໃນປີ 2012, ໄດ້ສ້າງກຸ່ມກໍລະນີສຶກສາແບບລຸ່ມຂຶ້ນເທິງທີ່ລະອຽດກວ່າ — ແຕ່ລະຂະແໜງ, ແຕ່ລະຊຸດຂໍ້ມູນ — ທີ່ມີປະໂຫຍດຫຼາຍກວ່າຕົວເລກຫົວຂໍ້ຂອງ McKinsey ສຳລັບກໍລະນີທຸລະກິດຈິງ, ເພາະມັນສະແດງກົນໄກການສ້າງມູນຄ່າ, ບໍ່ແມ່ນພຽງຂະໜາດລວມຂອງມັນ.

## ຄະນິດສາດ

ຂໍ້ມູນເປີດບໍ່ມີລາຄາຕະຫຼາດ, ດັ່ງນັ້ນວິທີການປະເມີນມູນຄ່າຈຶ່ງມາທົດແທນ; ມີສາມວິທີທີ່ພົບຊ້ຳ, ແລະ ບໍ່ມີວິທີໃດພຽງພໍດ້ວຍຕົນເອງ:

```
1. ວິທີຕົ້ນທຶນທີ່ຫຼີກລ່ຽງໄດ້ / ຕົ້ນທຶນທົດແທນ:
   ມູນຄ່າ ≈ ສິ່ງທີ່ຜູ້ໃຊ້ຈະຕ້ອງຈ່າຍເພື່ອຜະລິດ ຫຼື ຂໍອະນຸຍາດໃຊ້ຂໍ້ມູນ
   ທຽບເທົ່າດ້ວຍຕົນເອງ — ເປັນຂອບລຸ່ມ, ບໍ່ນັບມູນຄ່າທີ່ເກີດຈາກການນຳໃຊ້
   ທີ່ຜູ້ຜະລິດຕົ້ນສະບັບບໍ່ເຄີຍຄາດໄວ້

2. ວິທີທຽບເທົ່າຕະຫຼາດ / ກິດຈະກຳປາຍນ້ຳ:
   ມູນຄ່າ ≈ ລາຍຮັບ ຫຼື ເງິນປະຢັດທີ່ທຸລະກິດ/ບໍລິການທີ່ສ້າງເທິງຂໍ້ມູນສ້າງຂຶ້ນ
   (ເຊັ່ນ ແອັບນຳທາງທີ່ສ້າງເທິງຂໍ້ມູນແຜນທີ່ ແລະ ການຈະລາຈອນແບບເປີດ) —
   ຈັບກິດຈະກຳເສດຖະກິດຕົວຈິງ ແຕ່ຍາກທີ່ຈະຖືວ່າເປັນຜົນຂອງການປ່ອຍຂໍ້ມູນ
   ໄດ້ຢ່າງສະອາດ (ເບິ່ງ additionality-and-deadweight)

3. ວິທີສົມມຸດ/ຄວາມມັກທີ່ລະບຸ:
   ມູນຄ່າ ≈ ສິ່ງທີ່ຜູ້ໃຊ້ບອກວ່າຈະເຕັມໃຈຈ່າຍ, ຫຼື ເວລາທີ່ພວກເຂົາບອກວ່າມັນປະຢັດໃຫ້ —
   ເບິ່ງ stated-preference-valuation ສຳລັບວິທີທົ່ວໄປ ແລະ ຄວາມລຳອຽງຂອງມັນ

ບໍ່ມີວິທີໃດໃຫ້ຕົວເລກທີ່ສະອາດເທົ່າລາຄາຕະຫຼາດ; ກໍລະນີທຸລະກິດຂໍ້ມູນເປີດທີ່ໜ້າເຊື່ອຖື
ຈະໃຊ້ສອງວິທີຂຶ້ນໄປປຽບທຽບຢັນກັນ, ແລະ ຊີ້ແຈງວ່າກົນໄກໃດເປັນຕົວຂັບເຄື່ອນຫຼັກ.
```

## ຕົວຢ່າງການຄິດໄລ່

**ການປ່ອຍຂໍ້ມູນແຜນທີ່/ທີ່ຢູ່ແຫ່ງຊາດ (ຕົວຢ່າງ)** (ວິທີການຕາມກໍລະນີສຶກສາແບບ ODI, ຕົວເລກເປັນຕົວຢ່າງຂອງຂະໜາດທີ່ການສຶກສາແບບນີ້ມັກພົບ):

```
ການຄາດຄະເນຕົ້ນທຶນທີ່ຫຼີກລ່ຽງໄດ້:
  ທຸລະກິດທີ່ຖ້າບໍ່ດັ່ງນັ້ນຈະຂໍອະນຸຍາດໃຊ້ຂໍ້ມູນຈັບຄູ່ທີ່ຢູ່
  ທຽບເທົ່າທາງການຄ້າ, ທີ່ຄ່າໃບອະນຸຍາດສະເລ່ຍປະມານ £4,000/
  ປີ, ໃນບັນດາ SME ປະມານ 15,000 ແຫ່ງທີ່ຕອນນີ້ໃຊ້ຊຸດຂໍ້ມູນເປີດຟຣີ
  = 15,000 × £4,000 = £60,000,000/ປີ ໃນຕົ້ນທຶນໃບອະນຸຍາດທີ່ຫຼີກລ່ຽງໄດ້ເທົ່ານັ້ນ

ການຄາດຄະເນກິດຈະກຳປາຍນ້ຳ (ຄາດເດາຫຼາຍກວ່າ, ຕ້ອງມີສະຖານະການສົມມຸດທຽບ):
  ຜະລິດຕະພັນນຳສົ່ງ ແລະ ໂລຈິສຕິກທີ່ສ້າງເທິງຂໍ້ມູນເປີດ
  ທີ່ຈະບໍ່ມີ, ຫຼື ຈະຮ້າຍກວ່າຢ່າງມີນັຍສຳຄັນ, ຖ້າບໍ່ມີມັນ —
  ຕ້ອງປຽບທຽບກັບສະຖານະການສົມມຸດທຽບທີ່ຂໍ້ມູນຍັງປິດ ຫຼື ມີໃບອະນຸຍາດທາງການຄ້າ
  (counterfactual-analysis), ເພາະບາງກິດຈະກຳນັ້ນຈະເກີດຂຶ້ນຢູ່ແລ້ວ
  ເທິງຂໍ້ມູນເສຍເງິນໃນລາຄາທີ່ສູງກວ່າ, ເຊິ່ງເປັນ deadweight ໃນຄວາມໝາຍຂອງ
  "ມູນຄ່າທີ່ສ້າງຂຶ້ນຈາກການເປີດ"

ກໍລະນີທຸລະກິດທີ່ປ້ອງກັນໄດ້ລາຍງານຕົວເລກຕົ້ນທຶນທີ່ຫຼີກລ່ຽງໄດ້ເປັນຂອບລຸ່ມທີ່ໝັ້ນຄົງ,
ແລະ ຖືຕົວເລກກິດຈະກຳປາຍນ້ຳເປັນສະຖານະການຂອບເທິງ, ບໍ່ແມ່ນຄວາມຈິງ.
```

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ສຳລັບວິສະວະກອນ, ຄຳຖາມມູນຄ່າຂໍ້ມູນເປີດໃນທາງປະຕິບັດມັກແຄບກວ່າຕົວເລກຫົວຂໍ້ແຫ່ງຊາດ: ການເປີດ API ຫຼື ຊຸດຂໍ້ມູນສະເພາະນີ້ (ແທນທີ່ຈະເກັບໄວ້ຫຼັງຂໍ້ຕົກລົງກັບຄູ່ຮ່ວມມື) ເພີ່ມການນຳກັບມາໃຊ້ໃຫ້ພຽງພໍທີ່ຈະຄຸ້ມຄ່າຕົ້ນທຶນຕໍ່ເນື່ອງຂອງການຂຽນເອກະສານ, ຄວບຄຸມເວີຊັນ ແລະ ຮອງຮັບໃນຖານະສ່ວນຕິດຕໍ່ສາທາລະນະຫຼືບໍ່? ຕົ້ນທຶນການບຳລຸງຮັກສານັ້ນເປັນຈິງ ແລະ ເປັນຄູ່ຂອງເສດຖະກິດແບບສ້າງຄັ້ງດຽວນຳໃຊ້ຫຼາຍຄັ້ງຂອງ[ລັດຖະບານໃນຖານະແພລດຟອມ](../ລັດຖະບານໃນຖານະແພລດຟອມ/) — ສອງຫົວຂໍ້ນີ້ເປັນເຊື້ອສາຍໃກ້ຊິດກັນ, ໜຶ່ງກ່ຽວກັບໂຄດ ແລະ ໂຄງລ່າງພື້ນຖານທີ່ໃຊ້ຮ່ວມກັນ, ອີກອັນກ່ຽວກັບຂໍ້ມູນທີ່ໃຊ້ຮ່ວມກັນ. ການອ້າງມູນຄ່າຂໍ້ມູນເປີດໃດໆຄວນຖືກກວດສອບກັບ [ຜົນເພີ່ມເຕີມ ແລະ deadweight](../ຜົນເພີ່ມເຕີມ-ແລະ-ຜົນທີ່ຈະເກີດຂຶ້ນຢູ່ແລ້ວ/) ກ່ອນຈະເຂົ້າກໍລະນີທຸລະກິດ: ກິດຈະກຳທີ່ຈະເກີດຂຶ້ນຢູ່ແລ້ວ, ເທິງຂໍ້ມູນທີ່ມີໃບອະນຸຍາດທາງການຄ້າ, ບໍ່ແມ່ນມູນຄ່າທີ່ *ການເປີດ* ສ້າງຂຶ້ນ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ອ້າງຕົວເລກ $3–5 ລ້ານລ້ານຂອງ McKinsey ວ່າສະເພາະ UK ຫຼື ເປັນສ່ວນແບ່ງຂອງຊຸດຂໍ້ມູນນີ້**: ມັນເປັນການຄາດຄະເນຕາມສະຖານະການທົ່ວໂລກໃນເຈັດຂະແໜງຈາກປີ 2013 — ການໃຊ້ມັນເປັນຕົວຄູນທີ່ແມ່ນຍຳສຳລັບຊຸດຂໍ້ມູນແຫ່ງຊາດດຽວເປັນການເຂົ້າໃຈຜິດວ່າຕົວເລກນັ້ນແມ່ນຫຍັງ.
- **ບໍ່ມີສະຖານະການສົມມຸດທຽບ**: ອ້າງເອົາເຄຣດິດຂອງກິດຈະກຳເສດຖະກິດປາຍນ້ຳທັງໝົດທີ່ສ້າງເທິງຂໍ້ມູນເປີດ, ໂດຍບໍ່ຖາມວ່າມີຫຼາຍປານໃດທີ່ຈະເກີດຂຶ້ນຢູ່ແລ້ວເທິງຂໍ້ມູນເສຍເງິນ ຫຼື ມີໃບອະນຸຍາດໃນລາຄາທີ່ສູງກວ່າ (ເບິ່ງ [ຜົນເພີ່ມເຕີມ ແລະ deadweight](../ຜົນເພີ່ມເຕີມ-ແລະ-ຜົນທີ່ຈະເກີດຂຶ້ນຢູ່ແລ້ວ/) ແລະ [ການວິເຄາະສະຖານະການສົມມຸດທຽບ](../ການວິເຄາະສະຖານະການສົມມຸດ/)).
- **ສັບສົນລະຫວ່າງຕົ້ນທຶນການຜະລິດກັບມູນຄ່າທີ່ສ້າງຂຶ້ນ**: ຊຸດຂໍ້ມູນທີ່ເກັບແພງບໍ່ໄດ້ມີຄຸນຄ່າໃນການປ່ອຍໂດຍອັດຕະໂນມັດ, ແລະ ຊຸດທີ່ເກັບງ່າຍລາຄາຖືກບໍ່ໄດ້ມີມູນຄ່າຕ່ຳໂດຍອັດຕະໂນມັດ — ມູນຄ່າຕິດຕາມການນຳໃຊ້ປາຍນ້ຳ, ບໍ່ແມ່ນຕົ້ນທຶນຕົ້ນນ້ຳ.
- **ເມີນເສີຍຕົ້ນທຶນການບຳລຸງຮັກສາຕໍ່ເນື່ອງຂອງ "ການເປີດ"**: ການເຜີຍແຜ່ການສະກັດ CSV ຄັ້ງດຽວບໍ່ແມ່ນຄຳໝັ້ນສັນຍາດຽວກັນກັບການດຳເນີນ API ເປີດທີ່ມີເອກະສານ, ຄວບຄຸມເວີຊັນ ແລະ ຮອງຮັບ — ການໃຫ້ທຶນຢ່າງຫຼັງບໍ່ພຽງພໍຫຼັງການປະກາດເປີດໂຕເປັນຮູບແບບຄວາມລົ້ມເຫຼວທີ່ພົບທົ່ວໄປ.
