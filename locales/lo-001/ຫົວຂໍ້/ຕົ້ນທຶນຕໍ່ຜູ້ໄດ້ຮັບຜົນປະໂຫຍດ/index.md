# ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດ (Cost per Beneficiary)

ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດ (cost per beneficiary) ແມ່ນຕົ້ນທຶນໂຄງການທັງໝົດຫານດ້ວຍຈຳນວນຄົນທີ່ບໍ່ຊ້ຳກັນທີ່ໄດ້ຮັບບໍລິການ — ທຸກຄົນທີ່ຖືກແຕະຕ້ອງ, ບໍ່ວ່າສະຖານະການຂອງເຂົາຈະປ່ຽນແທ້ຫຼືບໍ່. ມັນເປັນຕົວເລກປະສິດທິພາບທີ່ໄວທີ່ສຸດທີ່ອົງກອນຜະລິດໄດ້ ເພາະ "ພວກເຮົາໃຫ້ບໍລິການໃຜ" ເກືອບສະເໝີຢູ່ໃນລະບົບຈັດການກໍລະນີແລ້ວ, ໃນຂະນະທີ່ "ໃຜໄດ້ຮັບຄວາມຊ່ວຍເຫຼືອ" ມັກຈະບໍ່ມີ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ຜູ້ໃຫ້ທຶນຖາມຫາຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດຢູ່ສະເໝີ, ດ້ວຍເຫດຜົນທີ່ປ້ອງກັນໄດ້: ມີທັນທີ, ປຽບທຽບໄດ້ທົ່ວພອດໂຟລິໂອຂອງໂຄງການທີ່ແຕກຕ່າງກັນຫຼາຍ, ແລະ ຊື່ສັດກ່ຽວກັບການເຖິງໃນແບບທີ່ຄຳອ້າງຜົນໄດ້ຮັບ — ທີ່ໃຊ້ເວລານານກວ່າໃນການກວດສອບ ແລະ ເວົ້າເກີນຈິງງ່າຍກວ່າ — ບໍ່ເປັນ. UK Charities SORP (Statement of Recommended Practice) ທີ່ກຳກັບວິທີທີ່ອົງການການກຸສົນລາຍງານພາຍໃຕ້ FRS 102 ກຳນົດໃຫ້ລາຍງານປະຈຳປີຂອງຜູ້ຮັບຜິດຊອບ (trustees) ອະທິບາຍຜົນສຳເລັດເມື່ອທຽບກັບຈຸດປະສົງ, ແຕ່ບັນຊີບໍລິຫານຂອງອົງການການກຸສົນຂະໜາດນ້ອຍສ່ວນໃຫຍ່ຍັງໃຊ້ຕົ້ນທຶນຕໍ່ໜ່ວຍແບບອີງການເຖິງເປັນຄ່າເລີ່ມຕົ້ນ ເພາະຜະລິດຖືກ ແລະ ເໝາະກັບການກວດສອບບັນຊີ.

ອັນຕະລາຍແມ່ນການຖືຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດຄືກັບວ່າມັນຕອບຄຳຖາມທີ່ມັນຕອບບໍ່ໄດ້: ເງິນໄດ້ຜົນຫຼືບໍ່. ເບິ່ງ [ຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບ](../ຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບ/) ສຳລັບຕົວຊີ້ວັດທີ່ຕອບຄຳຖາມນັ້ນແທ້, ແລະ [ຜົນໄດ້ຮັບ ທຽບກັບ ຜົນຜະລິດ](../ຜົນລັບ-ທຽບ-ຜົນຜະລິດ/) ສຳລັບຄວາມແຕກຕ່າງພື້ນຖານ. ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດເປັນຕົວຊີ້ວັດການຄັດແຍກ ແລະ ການເຖິງທີ່ຊອບທຳ — ມັນບອກຜູ້ໃຫ້ທຶນວ່າເງິນຍືດໄປໄດ້ໄກເທົ່າໃດ — ແຕ່ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດຕ່ຳອາດໝາຍເຖິງປະສິດທິພາບແທ້ ຫຼື ການບໍລິການທີ່ບາງຈົນບໍ່ປ່ຽນຫຍັງ.

## ຄະນິດສາດ

```
Cost per beneficiary = Total programme cost / Number of unique people served

Contrast:
Cost per outcome      = Total programme cost / Number of people achieving the defined outcome

Cost per beneficiary is always ≤ cost per outcome, because the outcome population is a subset
(often a small one) of the beneficiary population.
```

## ຕົວຢ່າງການຄິດໄລ່

**ທະນາຄານອາຫານ, ປີດຽວກັບຕົວຢ່າງຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບ**:

- ຕົ້ນທຶນໂຄງການທັງໝົດ: £450,000
- ຄົວເຮືອນທີ່ບໍ່ຊ້ຳກັນທີ່ໄດ້ຮັບບໍລິການ (ສາມຖົງຂຶ້ນໄປ): 1,800

```
Cost per beneficiary = £450,000 / 1,800 = £250 per household served
```

ປຽບທຽບສອງຕົວຊີ້ວັດຂ້າງກັນ:

| ຕົວຊີ້ວັດ | ຕົວຫານ | ຜົນ |
|---|---|---|
| ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດ | 1,800 ຄົວເຮືອນທີ່ໄດ້ຮັບບໍລິການ | £250 |
| ຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບ | 630 ຄົວເຮືອນທີ່ບັນລຸຄວາມໝັ້ນຄົງດ້ານອາຫານ | £714 |

ຜູ້ໃຫ້ທຶນທີ່ເຫັນພຽງ £250 ອາດສະຫຼຸບວ່ານີ້ແມ່ນອົງການການກຸສົນທີ່ມີປະສິດທິພາບສູງ. ຜູ້ໃຫ້ທຶນທີ່ເຫັນທັງສອງຕົວເລກສາມາດຖາມຄຳຖາມທີ່ມີປະໂຫຍດກວ່າ: ຊ່ອງຫວ່າງລະຫວ່າງການເຖິງ (1,800) ກັບຜົນໄດ້ຮັບ (630) ແມ່ນຊ່ອງຫວ່າງການເກັບຂໍ້ມູນ, ຊ່ອງຫວ່າງການອອກແບບ, ຫຼື ການສະທ້ອນຢ່າງຊື່ສັດຂອງຄວາມຍາກໃນການບັນລຸຄວາມໝັ້ນຄົງດ້ານອາຫານດ້ວຍຄວາມຊ່ວຍເຫຼືອດ້ານອາຫານຢ່າງດຽວ?

**ອົງການການກຸສົນຝຶກອາຊີບ, ຕົວຢ່າງປະກອບ**: ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດ (ລົງທະບຽນ) = £2,000; ຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບ (ການຈ້າງງານທີ່ຍືນຍົງ ຢູ່ທີ່ 6 ເດືອນ) = £11,000, ເພາະມີພຽງ 18% ຂອງຜູ້ລົງທະບຽນທີ່ຮຽນຈົບໂຄງການ ແລະ ຫາງານທີ່ຍືນຍົງໄດ້. ສອງຕົວເລກທີ່ຕ່າງກັນຫ້າເທົ່າເປັນເລື່ອງທຳມະດາທຸກບ່ອນທີ່ອັດຕາການສຳເລັດ ຫຼື ຄວາມທົນທານຕ່ຳ — ອົງການຝຶກອາຊີບ ແລະ ທະນາຄານອາຫານມີໂຄງສ້າງຄືກັນໃນເລື່ອງນີ້.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດເປັນຕົວຊີ້ວັດຄ່າເລີ່ມຕົ້ນໃນຊອບແວຂອງອົງກອນບໍ່ຫວັງກຳໄລ ເພາະເປັນຕົວຊີ້ວັດທີ່ອອກມາຈາກບັນທຶກຜູ້ໄດ້ຮັບຜົນປະໂຫຍດໂດຍບໍ່ຕ້ອງເຮັດຫຍັງເພີ່ມ: ສ້າງກໍລະນີ, ບັນທຶກບໍລິການ, ນັບແຖວ. ການສ້າງລະບົບທີ່ຮອງຮັບຕົ້ນທຶນຕໍ່ຜົນໄດ້ຮັບດ້ວຍ ໝາຍເຖິງການເພີ່ມເອັນທິຕີຊັ້ນໜຶ່ງທີສອງຢ່າງຕັ້ງໃຈ — ເຫດການຜົນໄດ້ຮັບ ທີ່ມີວັນທີ ແລະ ນິຍາມແຍກຈາກການສົ່ງມອບບໍລິການ — ແລະ ຕ້ານຄວາມຢາກທີ່ຈະໃຫ້ "ປິດກໍລະນີ" ແທນ "ບັນລຸຜົນໄດ້ຮັບ". ເມື່ອກຳນົດຂອບເຂດແພລດຟອມຈັດການເງິນອຸດໜູນ ຫຼື CRM ໃຫ້ຖາມວ່າແຕ່ລະແດຊບອດສະແດງຕົວຊີ້ວັດໃດໃນສອງຢ່າງແທ້, ແລະ ຕິດປ້າຍຕາມນັ້ນ; ການປົນສອງຢ່າງໃນແຜ່ນ "ຜົນກະທົບ" ດຽວເປັນໜຶ່ງໃນສາເຫດລະດັບຊອບແວທີ່ພົບເລື້ອຍທີ່ສຸດຂອງຂໍ້ຜິດພາດຂ້າງລຸ່ມ. ເບິ່ງ [ຖານຂໍ້ມູນຕົ້ນທຶນຕໍ່ໜ່ວຍ](../ຖານຂໍ້ມູນຕົ້ນທຶນຕໍ່ໜ່ວຍ/) ສຳລັບການປຽບທຽບມາດຕະຖານຕົວຊີ້ວັດທັງສອງເມື່ອຕິດປ້າຍຖືກຕ້ອງແລ້ວ.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ນຳສະເໜີຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດເປັນຜົນກະທົບ.** ມັນວັດການເຖິງ, ບໍ່ແມ່ນການປ່ຽນແປງ. ຕິດປ້າຍແດຊບອດ ແລະ ລາຍງານວ່າ "ຕົ້ນທຶນຕໍ່ຄົນທີ່ໄດ້ຮັບບໍລິການ", ບໍ່ແມ່ນ "ຕົ້ນທຶນຕໍ່ຄົນທີ່ໄດ້ຮັບຄວາມຊ່ວຍເຫຼືອ".
- **ນັບຊ້ຳທົ່ວໂຄງການ.** ຄົນທີ່ໄດ້ຮັບທັງຖົງອາຫານ ແລະ ຄຳປຶກສາເລື່ອງໜີ້ຈາກອົງການການກຸສົນດຽວກັນ ແມ່ນຜູ້ໄດ້ຮັບຜົນປະໂຫຍດຄົນດຽວ, ບໍ່ແມ່ນສອງຄົນ, ຖ້າຕົວຫານມີໄວ້ອະທິບາຍການເຖິງທີ່ບໍ່ຊ້ຳກັນ; ຕັດສິນໃຈ ແລະ ບັນທຶກວ່າໃຊ້ຂໍ້ຕົກລົງໃດ.
- **ຖືວ່າຕົວເລກຕ່ຳກວ່າດີກວ່າສະເໝີ.** ສະໂມສອນອາຫານທ່ຽງແບບຄົນເຂົ້າອອກຈະຊະນະບໍລິການຈັດການກໍລະນີແບບເຂັ້ມຂຸ້ນໃນຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດສະເໝີ ເພາະຖືກກວ່າໃນການແຕະຕ້ອງຄົນແບບເບົາໆ. ນັ້ນບອກຫຍັງບໍ່ໄດ້ກ່ຽວກັບອັນໃດສ້າງການປ່ຽນແປງທີ່ທົນທານກວ່າຕໍ່ປອນ.
- **ປ່ຽນຕົວຫານລະຫວ່າງລາຍງານຢ່າງງຽບໆ.** ຕົວເລກຕົ້ນທຶນຕໍ່ຜູ້ໄດ້ຮັບຜົນປະໂຫຍດທີ່ອ້າງໃນລາຍງານປະຈຳປີໜຶ່ງກັບ "ລົງທະບຽນ" ແລະ ໃນປີຖັດໄປກັບ "ສຳເລັດ" ປຽບທຽບປີຕໍ່ປີບໍ່ໄດ້; ລະບຸຕົວຫານທຸກຄັ້ງ.
