# 每名受益人成本

每名受益人成本係計劃總成本，除以接受過服務嘅獨立人數——任何接觸過嘅人，不論佢哋嘅處境有冇真正改變。佢係機構最快計出嘅效率數字，因為「我哋服務咗邊個」幾乎一定已經喺個案管理系統入面，而「邊個得到幫助」通常就冇。

## 點解重要

資助者不斷索取每名受益人成本，亦有充分理由：佢即時可得、可以喺一組截然不同嘅計劃之間作比較，而且對服務覆蓋面嘅講法誠實——成果聲稱需要較長時間核實，亦較易誇大，就做不到咁。英國 Charities SORP(Statement of Recommended Practice，建議實務聲明)規管慈善機構如何按 FRS 102 匯報，要求受託人年報描述對照目標嘅成就，但大部分較小型慈善機構嘅管理賬目，仍然預設以覆蓋人數為基礎嘅單位成本，因為製作成本低，而且便於審計。

危險在於，將每名受益人成本當作可以回答佢回答唔到嘅問題：資金有冇發揮作用。真正回答呢個問題嘅指標，見[每個成果成本](../每個成果成本/)；背後嘅區別，見[成果與產出](../成果與產出/)。每名受益人成本係一個正當嘅分流同覆蓋面指標——佢話畀資助者知資金可以攤到幾遠——但低嘅每名受益人成本，可能代表真正嘅效率，亦可能代表服務單薄到冇改變任何嘢。

## 數學原理

```
Cost per beneficiary = Total programme cost / Number of unique people served

Contrast:
Cost per outcome      = Total programme cost / Number of people achieving the defined outcome

Cost per beneficiary is always ≤ cost per outcome, because the outcome population is a subset
(often a small one) of the beneficiary population.
```

## 實例演算

**食物銀行，同每個成果成本例子同一年**：

- 計劃總成本：£450,000
- 獲服務嘅獨立住戶(三個或以上食物包)：1,800

```
Cost per beneficiary = £450,000 / 1,800 = £250 per household served
```

將兩個指標並排比較：

| 指標 | 分母 | 結果 |
|---|---|---|
| 每名受益人成本 | 1,800 個獲服務住戶 | £250 |
| 每個成果成本 | 630 個達到糧食安全嘅住戶 | £714 |

只睇到 £250 嘅資助者，可能會斷定呢間係效率極高嘅慈善機構。睇到兩個數字嘅資助者，就可以問一個更有用嘅問題：覆蓋面(1,800)同成果(630)之間嘅差距，係數據收集嘅缺口、設計嘅缺口，還是老實反映單靠食物援助達到糧食安全有幾困難？

**職業培訓慈善機構，示意性**：每名受益人(已報名)成本 = £2,000；每個成果(6 個月持續就業)成本 = £11,000，因為只有 18% 嘅報名者完成計劃並找到持續工作。凡完成率或持久率偏低之處，兩個數字相差五倍都好常見——培訓慈善機構同食物銀行喺呢方面結構上完全相同。

## 與軟件工程嘅關係

每名受益人成本係非牟利軟件中嘅預設指標，因為佢係受益人記錄毋須額外工作就可以計出嘅指標：建立個案、記錄服務、數行數。要建構一個同時支援每個成果成本嘅系統，就需要刻意加入第二個一等實體——一個獨立於服務提供而獨立註明日期同定義嘅成果事件——並抗拒讓「個案已結」代替「成果已達成」嘅誘惑。為資助管理或者 CRM 平台界定範圍時，要問每個儀表板實際上展示緊兩個指標中嘅邊一個，並相應標示；喺單一個「影響力」圖塊中混淆兩者，係下面幾個陷阱最常見嘅軟件層面成因。指標標示正確之後，如何對任何一個作基準比較，見[單位成本數據庫](../單位成本數據庫/)。

## 常見陷阱

- **將每名受益人成本當作影響力呈現。** 佢量度嘅係覆蓋面，唔係改變。儀表板同報告應標示為「每名獲服務人士成本」，而唔係「每名獲幫助人士成本」。
- **跨計劃重複計算。** 如果分母旨在描述獨立覆蓋面，一個同時接受同一慈善機構食物包同債務諮詢嘅人，只算一名受益人，唔係兩名；要決定並記錄用咗邊個慣例。
- **視較低數字永遠較好。** 一個免費午餐聚會，每名受益人成本永遠勝過密集個案管理服務，因為輕輕接觸一個人成本較低。呢個完全唔能夠說明邊個每鎊產生更持久嘅改變。
- **喺不同報告之間靜靜雞更換分母。** 一份年報按「已報名」引用，下一份按「已完成」引用嘅每名受益人成本，年與年之間並不可比；每次都要註明分母。
