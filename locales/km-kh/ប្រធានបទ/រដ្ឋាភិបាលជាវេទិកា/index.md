# រដ្ឋាភិបាលជាវេទិកា (GaaP)

រដ្ឋាភិបាលជាវេទិកា (Government as a Platform) គឺជាយុទ្ធសាស្ត្រនៃការសាងសង់សមាសភាគរួម និងអាចប្រើឡើងវិញបាន — សេវាជូនដំណឹង សេវាទូទាត់ប្រាក់ សេវាអត្តសញ្ញាណ — ម្តងតែមួយនៅកណ្តាល ដើម្បីឱ្យសេវារដ្ឋាភិបាលរាប់រយប្រើប្រាស់វា ជាជាងម្នាក់ៗសាងសង់ដោយខ្លួនឯង។ វាបកស្រាយឡើងវិញនូវហេដ្ឋារចនាសម្ព័ន្ធឌីជីថលសាធារណៈជាបញ្ហាសេដ្ឋកិច្ចវេទិកា៖ តម្លៃមិនស្ថិតក្នុងការរួមបញ្ចូលតែមួយទេ ប៉ុន្តែស្ថិតក្នុងការដែលតម្លៃទីបំផុតរបស់ក្រុមការងារ*បន្ទាប់*ដែលប្រើវា ខិតជិតសូន្យ។

## ហេតុអ្វីបានជាសំខាន់

GDS បានកំណត់យុទ្ធសាស្ត្រជាផ្លូវការក្នុងការបោះពុម្ពផ្សាយ "Government as a Platform" ឆ្នាំ 2015 របស់ខ្លួន ដោយប្រកែកថារដ្ឋាភិបាលបានសាងសង់សមត្ថភាពដូចគ្នា — ការទទួលការបង់ប្រាក់ ការជូនដំណឹងអ្នកប្រើប្រាស់ ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ការស្វែងរកអាសយដ្ឋាន — ដោយឡែកពីគ្នាក្នុងសេវាម្តងហើយម្តងទៀត ដែលនីមួយៗមានបន្ទុកលទ្ធកម្ម ការវាយតម្លៃសន្តិសុខ និងការគាំទ្របន្តរបស់ខ្លួន។ ជម្រើសជំនួសគឺវេទិការួមមួយចំនួនតិច សាងសង់តាមស្តង់ដារខ្ពស់ម្តងតែមួយ ហើយប្រើឡើងវិញគ្រប់ទីកន្លែង៖ GOV.UK Notify សម្រាប់ផ្ញើអ៊ីមែល សារអត្ថបទ និងសំបុត្រ GOV.UK Pay សម្រាប់ទទួលការទូទាត់អនឡាញ និង GOV.UK One Login (អ្នកស្នងតំណែងកម្មវិធីអត្តសញ្ញាណ GOV.UK Verify មុន) សម្រាប់ផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។ មាត្រដ្ឋានដែលវេទិកាទាំងនេះបានឈានដល់ គឺជាភស្តុតាងច្បាស់បំផុតថាយុទ្ធសាស្ត្រដំណើរការ៖ GOV.UK Pay បានដំណើរការប្រតិបត្តិការជាង £10 billion ឆ្លងសេវាបុគ្គលប្រហែល 1,800 — ហើយកន្លែងដែលវាចំណាយពេលប្រហែលបួនឆ្នាំដើម្បីដំណើរការ £1 billion ដំបូង ឥឡូវវាដំណើរការចំនួនដូចគ្នាក្នុងរយៈពេលប្រហែលប្រាំខែ — ខណៈ GOV.UK Notify បានផ្ញើសារជាង 9 billion ជំនួសអង្គការរដ្ឋាភិបាលជាង 1,500។ សេវាដែលប្រើទាំងនោះម្នាក់ៗបានជៀសវាងការសាងសង់ សុវត្ថិភាព និងថែទាំច្រកទូទាត់ ឬបំពង់សារផ្ទាល់ខ្លួន។

## គណិតវិទ្យា

```
Build cost per service (no platform) = N services × cost to build,
  secure-assess, and run one payment/notification/identity system

Platform cost = fixed platform build cost
              + marginal cost per adopting service (integration,
                configuration, ongoing platform-team support)

Reuse breaks even once:
  platform build cost < N × (per-service build cost − marginal
  integration cost)

For a mature platform, marginal cost per additional adopter approaches
the transaction/message fee alone — the fixed cost is amortized across
the whole government estate, not one department's budget, which is
why GaaP components are usually funded centrally rather than charged
at full cost-recovery to early adopters.
```

## ឧទាហរណ៍គណនា

**អាជ្ញាធរមូលដ្ឋានប្រើ GOV.UK Pay ជំនួសឱ្យការសាងសង់ច្រកទូទាត់ផ្ទាល់ខ្លួន**៖

```
Build-your-own estimate:
  PCI-DSS compliance work + integration + ongoing maintenance
  ≈ £85,000 build + £22,000/year maintenance

GOV.UK Pay adoption:
  Integration effort ≈ £12,000 (developer time)
  Transaction fees: government-to-citizen card payments typically
  charged at a small percentage + fixed fee per transaction, no
  separate PCI-DSS burden carried by the council
  ≈ £12,000 one-off, ongoing cost variable with volume, not fixed

First-year saving ≈ £85,000 − £12,000 = £73,000, before counting the
avoided £22,000/year maintenance and the avoided compliance risk of
holding card data in a council-run system at all — this second
category is the security value covered in
public-sector-cybersecurity-value.
```

ពង្រីក £73,000 នោះទៅសេវាប្រហែល 1,800 ដែលឥឡូវប្រើ GOV.UK Pay ហើយតម្លៃសាងសង់ដែលបានជៀសវាងសរុបទូទាំងរដ្ឋាភិបាលមានរាប់រយលាន — គឺសេដ្ឋកិច្ចវេទិកា មិនមែនការរួមបញ្ចូលតែមួយណាទេ ដែលតម្លៃពិតនៃយុទ្ធសាស្ត្រស្ថិតនៅ។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

រដ្ឋាភិបាលជាវេទិកាគឺជាអំណះអំណាងផ្ទាល់សម្រាប់ [សាងសង់ ឬទិញក្នុងរដ្ឋាភិបាល](../ការសម្រេចចិត្តសាងសង់-ឬទិញក្នុងរដ្ឋាភិបាល/)៖ នៅពេលមានសមាសភាគរួម ដែលបានវាយតម្លៃ និងដំណើរការល្អ ការសាងសង់ដែលស្មើគ្នាតាមតម្រូវកម្រជាជម្រើស [តម្លៃសមស្របនឹងប្រាក់ចំណាយ](../តម្លៃសមស្របនឹងថ្លៃចំណាយ/) ល្អជាងទេ ហើយវាធ្លាក់ចំណុចទី 13 នៃ [ស្តង់ដារសេវាឌីជីថល](../ស្តង់ដារសេវាឌីជីថល/) ("ប្រើ និងរួមចំណែកដល់ស្តង់ដារបើកចំហ សមាសភាគរួម និងគំរូទូទៅ") ស្ទើរតែតាមនិយមន័យ។ វាក៏ផ្លាស់ប្តូររូបរាងនៃ [ថ្លៃសរុបនៃភាពជាម្ចាស់ក្នុងព័ត៌មានវិទ្យារដ្ឋាភិបាល](../ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ក្នុង-it-របស់រដ្ឋាភិបាល/)៖ ការប្រើវេទិកាដោះដូរបន្ទាត់ដើមទុន និងថែទាំធំ ទៅជាតម្លៃប្រតិបត្តិការតូចជាងដែលភ្ជាប់នឹងការប្រើប្រាស់ ដែលងាយព្យាករណ៍ជាង និងងាយឈប់ផ្តល់មូលនិធិជាង ប្រសិនបើសេវាត្រូវបានបិទ។ ការប្រើសមាសភាគឡើងវិញដោយបើកចំហមានញាតិមួយក្នុង [តម្លៃទិន្នន័យបើកចំហ](../តម្លៃនៃទិន្នន័យបើកចំហ/) — ទាំងពីរជាយុទ្ធសាស្ត្រសម្រាប់ចាត់ទុកអ្វីដែលរដ្ឋាភិបាលផលិតម្តងតែមួយជាហេដ្ឋារចនាសម្ព័ន្ធរួម ជាជាងទ្រព្យសម្បត្តិរបស់ក្រសួង។

## កំហុសដែលតែងកើតមាន

- **សាងសង់ឡើងវិញដោយសម្ងាត់**៖ ក្រុមការងារស្ងាត់ៗសាងសង់ការរួមបញ្ចូលការទូទាត់ ឬការជូនដំណឹងផ្ទាល់ខ្លួន ពីព្រោះដំណើរការចូលរួមរបស់វេទិកាយឺតជាងធ្វើដោយខ្លួនឯង — ជាបញ្ហាកកិតអភិបាលកិច្ច មិនមែនបច្ចេកវិទ្យាទេ ហើយវាបំផ្លាញដោយស្ងាត់ៗនូវសេដ្ឋកិច្ចប្រើឡើងវិញដែលយុទ្ធសាស្ត្រទាំងមូលពឹងលើ។
- **ផ្តល់មូលនិធិមិនគ្រប់គ្រាន់ដល់ក្រុមវេទិកាធៀបនឹងតម្លៃដែលវាបង្កើត**៖ តម្លៃធ្លាក់ដល់ក្រសួងដែលប្រើ ខណៈតម្លៃចំណាយស្ថិតនៅក្រុមវេទិកា បង្កើតហានិភ័យវិនិយោគមិនគ្រប់គ្រាន់រ៉ាំរ៉ៃ លុះត្រាតែមូលនិធិត្រូវបានប្រមូលផ្តុំ និងការពារ — ជាទម្រង់មួយនៃសោកនាដកម្មនៃទ្រព្យរួម។
- **វាស់ភាពជោគជ័យរបស់វេទិកាដោយការប្រើប្រាស់តែប៉ុណ្ណោះ**៖ លេខការប្រើប្រាស់ (សេវាដែលចូលរួម សារដែលបានផ្ញើ) គឺជាសូចនាករនាំមុខ មិនមែនភស្តុតាងនៃតម្លៃទេ។ ការសាកល្បងពិតគឺការគណនាតម្លៃសាងសង់ដែលបានជៀសវាង និងហានិភ័យដែលបានជៀសវាងខាងលើ។
- **ចាត់ទុក "វេទិកា" ជាពាក្យដូចគ្នានឹង "ម៉ូណូលីត"**៖ សមាសភាគ GaaP ជោគជ័យ ពីព្រោះនីមួយៗធ្វើរឿងមួយបានល្អជាមួយចំណុចប្រទាក់តូចចង្អៀត និងស្ថិរភាព — ការបញ្ចូលសមត្ថភាពមិនទាក់ទងគ្នាទៅក្នុង "វេទិកា" តែមួយបង្កើតបញ្ហាសាងសង់តាមតម្រូវឡើងវិញនៅមាត្រដ្ឋានផ្សេង។
