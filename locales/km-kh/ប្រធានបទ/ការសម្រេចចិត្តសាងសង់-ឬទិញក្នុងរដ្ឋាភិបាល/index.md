# ការសម្រេចចិត្តសាងសង់ ឬទិញក្នុងរដ្ឋាភិបាល

ការសម្រេចចិត្តសាងសង់ ឬទិញ (build-vs-buy) គឺជាការប្រៀបធៀបមានរចនាសម្ព័ន្ធ និងកែតម្រូវតាមហានិភ័យ រវាងការអភិវឌ្ឍផ្ទាល់ខ្លួន និងការទិញពាណិជ្ជកម្ម ឬទំនិញទូទៅ ប្រៀបធៀបលើ [ថ្លៃចំណាយសរុបនៃភាពជាម្ចាស់](../ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ក្នុង-it-របស់រដ្ឋាភិបាល/) ដែលបានបញ្ចុះតម្លៃ ពេលវេលាទៅរកតម្លៃ និងហានិភ័យ។ រដ្ឋាភិបាលគឺជាវិស័យអ្នកទិញតាមរចនាសម្ព័ន្ធ ដោយ Technology Code of Practice កំណត់ការសន្មតទៅរកដំណោះស្រាយទូទៅ និងពពក ប៉ុន្តែក្រុមវិស្វកម្មក្នុងនាយកដ្ឋានមួយចំនួននៅតែលំនាំដើមទៅសាងសង់ ដោយហេតុផលដូចអ្នកសាងសង់គ្រប់ទីកន្លែង។

## ហេតុអ្វីបានជាសំខាន់

Technology Code of Practice របស់ Government Digital Service (<https://www.gov.uk/guidance/the-technology-code-of-practice>) និងការណែនាំ Service Manual ដែលភ្ជាប់មកអំពីការសម្រេចចិត្តសាងសង់ ឬទិញ ជំរុញនាយកដ្ឋានឱ្យបញ្ជាក់ការអភិវឌ្ឍផ្ទាល់ខ្លួន ធៀបនឹងការសន្មតថាសមត្ថភាពទូទៅគួរទិញ មិនមែនសាងសង់ ហើយមានតែសមត្ថភាពថ្មីថ្មោងពិតប្រាកដ ដែលធ្វើឱ្យបេសកកម្មខុសគេប៉ុណ្ណោះ ទើបសមនឹងកូដផ្ទាល់ខ្លួន។ ការណែនាំបន្ថែមស្តីពីភាពលំអៀងសុទិដ្ឋិនិយម (optimism bias) របស់ HM Treasury ចំពោះ Green Book ដែលដកស្រង់ពីការពិនិត្យ Mott MacDonald ឆ្នាំ 2002 លើលទ្ធកម្មសាធារណៈធំៗ ផ្តល់ដល់គម្រោង IT នូវចន្លោះបន្ថែមទូលំទូលាយបំផុតក្នុងចំណោមប្រភេទដែលបានវាយតម្លៃ គឺការប៉ាន់ស្មានថ្លៃដើមមូលធនត្រូវបានណែនាំឱ្យបន្ថែម 10% នៅចុងទាប និងរហូតដល់ 200% នៅចុងខ្ពស់ មុនពេលប្រើក្នុងការវាយតម្លៃ ដែលឆ្លុះបញ្ចាំងពីការមើលស្រាលយ៉ាងធ្ងន់ធ្ងរនៃការសាងសង់កម្មវិធីតាមប្រវត្តិសាស្ត្រក្នុងលទ្ធកម្មសាធារណៈ។ ការវិភាគសាងសង់ ឬទិញមានជាពិសេសដើម្បីបង្ខំឱ្យការកែតម្រូវហានិភ័យនោះលើតុមុនពេលអនុម័ត ជាជាងអនុញ្ញាតឱ្យវាលេចឡើងជាសំណើចំណាយលើសក្នុងឆ្នាំ។

## គណិតវិទ្យា

```
Compare over the same 3–5 year horizon, discounted at the Green Book
social discount rate (see social-discount-rate.md):

NPV_option = PV(benefits, shifted by time-to-value) − PV(TCO)

Risk adjustments (Green Book optimism bias pattern):
  build cost × 1.1–3.0        (IT project uplift range, Mott MacDonald)
  build time-to-value + 40–60% (deployment delay prior)
  buy: add integration reality-check and contract exit costs instead

Decision drivers, in the order they usually decide:
  1. differentiation — is this capability the mission, or plumbing?
  2. time-to-value × cost of delay (see cost-of-delay-in-public-programmes.md)
  3. risk-adjusted total cost of ownership
```

## ឧទាហរណ៍គណនា

អាជ្ញាធរមូលដ្ឋានមួយត្រូវការប្រព័ន្ធគ្រប់គ្រងករណីសម្រាប់ការថែទាំសង្គមមនុស្សពេញវ័យ។ ទិញ៖ SaaS ក្នុងតម្លៃ £180,000/ឆ្នាំ ដំណើរការក្នុង 4 ខែ។ សាងសង់៖ ប៉ាន់ស្មាន £900,000 បូកថ្លៃថែទាំ £150,000/ឆ្នាំ ដំណើរការក្នុង 14 ខែ។

```
Risk-adjusted build cost = 900,000 × 1.4 = £1,260,000
5-year TCO:
  buy  = 180,000 × 5 = £900,000
  build = 1,260,000 + 150,000 × 5 = £2,010,000

Delay term: the system avoids £40,000/month in duplicated assessments;
build arrives 10 months later than buy.
CoD = 10 × 40,000 = £400,000

Effective comparison: £900,000 (buy) vs £2,010,000 + £400,000 = £2,410,000 (build)
```

ការទិញឈ្នះប្រហែល £1.5 លានក្នុងរយៈពេលប្រាំឆ្នាំ ហើយបន្ទាត់តែមួយធំបំផុតបន្ទាប់ពីការប៉ាន់ស្មានសាងសង់ខ្លួនឯង គឺថ្លៃនៃការយឺតយ៉ាវ ដែលការប្រៀបធៀបមូលធនសុទ្ធនឹងមិនដែលលើកឡើងឡើយ។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

វិន័យដែលផ្ទេរដោយផ្ទាល់ពីការវិភាគនេះទៅការអនុវត្តផ្តល់សេវា៖ **ការកែតម្រូវហានិភ័យផ្អែកលើទិន្នន័យមុន** ដោយការបន្ថែម Mott MacDonald គឺស្មើនឹងភាពលំអៀងសុទិដ្ឋិនិយមរបស់ Green Book ក្នុងវិស័យកម្មវិធី អនុវត្តដោយស្វ័យប្រវត្តិ ដូច្នេះក្រុមគួរតវ៉ាសុំការលើកលែង ជាជាងសន្មតថាការប៉ាន់ស្មានរបស់ខ្លួនជាករណីលើកលែង៖ **ភាពស្មោះត្រង់នៃអ្នកប្រៀបធៀប** ជម្រើសជំនួសការសាងសង់គឺជម្រើសទិញដែលល្អបំផុតដែលមាន មិនមែន «គ្មានអ្វី» ទេ ដែលភ្ជាប់ដោយផ្ទាល់ទៅ [ថ្លៃចំណាយឱកាសក្នុងការចំណាយសាធារណៈ](../ថ្លៃចំណាយឱកាសក្នុងការចំណាយសាធារណៈ/)៖ និង **ការប្រៀបធៀប TCO ដោយស្មោះត្រង់** សំណើសាងសង់នីមួយៗគួរត្រូវបានប្រៀបធៀបជាមួយ [ថ្លៃចំណាយសរុបនៃភាពជាម្ចាស់](../ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ក្នុង-it-របស់រដ្ឋាភិបាល/) ពេញលេញនៃជម្រើសទិញ មិនមែនតម្លៃបញ្ជីរបស់វាទេ។ ពេលដែលការសាងសង់ឈ្នះពិតប្រាកដ [ថ្លៃនៃការយឺតយ៉ាវ](../ថ្លៃចំណាយនៃការយឺតយ៉ាវក្នុងកម្មវិធីសាធារណៈ/) នៃពេលវេលាសាងសង់បន្ថែមគួរត្រូវបានកំណត់តម្លៃច្បាស់លាស់ក្នុងករណីអាជីវកម្ម មិនត្រូវទុកជាការសន្មតដែលមិនបានបញ្ជាក់ថាពេលវេលាមិនសំខាន់នោះទេ។

## កំហុសដែលតែងកើតមាន

- **ការប្រៀបធៀបតម្លៃបញ្ជីរបស់អ្នកលក់ ជាមួយការប៉ាន់ស្មានសាងសង់ដែលមិនទាន់កែតម្រូវហានិភ័យ**៖ នេះលើកទឹកចិត្តការសាងសង់ពីរដង ម្តងលើថ្លៃ ម្តងលើកាលវិភាគ។
- **កម្លាំងពលកម្មផ្ទៃក្នុងកំណត់តម្លៃសូន្យ**៖ ពេលវេលាវិស្វករក្នុងមុខងារសាធារណៈត្រូវបានចាត់ទុកថា «ឥតគិតថ្លៃ» ព្រោះវាស្ថិតក្នុងថវិកាបុគ្គលិកនាយកដ្ឋានរួចហើយ ដែលលាក់ថ្លៃចំណាយឱកាសពិតរបស់វាធៀបនឹងការងារផ្សេងដែលក្រុមនោះអាចធ្វើបាន។
- **ការជាប់គាំងដែលមិនបានកំណត់តម្លៃទាំងសងខាង**៖ ថ្លៃចេញពីអ្នកលក់ និងថ្លៃផ្ទេរទិន្នន័យគឺជាការពិត ប៉ុន្តែក៏ដូច្នោះដែរ bus-factor នៃការសាងសង់ផ្ទាល់ខ្លួន និងការពឹងផ្អែករបស់វាលើការរក្សាក្រុមផ្ទៃក្នុងតូចៗ ដែលពិបាកជំនួស ក្នុងអំឡុងអាយុកាលរបស់វា។
- **ការអះអាងភាពខុសគេនៃបេសកកម្មសម្រាប់ហេដ្ឋារចនាសម្ព័ន្ធ (plumbing)**៖ «នេះជាស្នូលរបស់យើង» ដែលអះអាងអំពី middleware ការតភ្ជាប់ ឬឃ្លាំងឯកសារ ដូច្នេះត្រូវសាកល្បងថាតើពលរដ្ឋ ឬអ្នកចាត់ការករណីនឹងសម្គាល់ឃើញដែរឬទេថាមួយណាកំពុងដំណើរការនៅខាងក្រោម។
