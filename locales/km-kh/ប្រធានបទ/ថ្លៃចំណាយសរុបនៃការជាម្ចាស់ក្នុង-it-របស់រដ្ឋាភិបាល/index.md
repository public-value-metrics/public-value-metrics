# ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ក្នុង IT របស់រដ្ឋាភិបាល

ថ្លៃចំណាយសរុបនៃការជាម្ចាស់ (Total Cost of Ownership, TCO) គឺជាថ្លៃចំណាយពេញមួយវដ្តជីវិតនៃប្រព័ន្ធមួយ គឺថ្លៃទិញបូកនឹងរាល់ឆ្នាំនៃការដំណើរការវា ដែលបានបញ្ចុះតម្លៃមកកាលបរិច្ឆេទរួម។ ក្នុង IT របស់រដ្ឋាភិបាល កំហុសព្យាករណ៍ដែលអាចទុកចិត្តបានបំផុតតែមួយគត់ គឺការប្រៀបធៀបអ្នកផ្គត់ផ្គង់ ឬជម្រើសលើតម្លៃទិញតែប៉ុណ្ណោះ ខណៈដែលប្រតិបត្តិការ និងការថែទាំជាទូទៅមានចំណែកពីពាក់កណ្តាលដល់បួនភាគប្រាំនៃវិក្កយបត្រពេញមួយអាយុកាល។

## ហេតុអ្វីបានជាសំខាន់

Green Book របស់ក្រសួងរតនាគារអង់គ្លេស (HM Treasury) តម្រូវឱ្យករណីហិរញ្ញវត្ថុក្នុងករណីអាជីវកម្មគំរូប្រាំករណីណាមួយ គ្របដណ្តប់ថ្លៃចំណាយពេញមួយអាយុកាល មិនមែនគ្រាន់តែការចំណាយលើដើមទុនទេ ប៉ុន្តែការិយាល័យសវនកម្មជាតិ (National Audit Office) បានរកឃើញម្តងហើយម្តងទៀតថា ក្រសួងអនុម័តការវិនិយោគ IT ធៀបនឹងការព្យាករថ្លៃចំណាយដំណើរការមិនពេញលេញ ឬសុទិដ្ឋិនិយម ហើយបន្ទាប់មកទើបរកឃើញថ្លៃចំណាយប្រតិបត្តិការពិតនៅពេលប្រព័ន្ធចាប់ផ្តើមដំណើរការ ហើយបន្ទាត់ថវិកាដើមទុនបានបិទ។ Technology Code of Practice របស់ Government Digital Service និង Central Digital and Data Office (<https://www.gov.uk/guidance/the-technology-code-of-practice>) ជំរុញក្រសួងឆ្ពោះទៅរកពពក (cloud) និងការបង្ហោះទំនិញសាមញ្ញ មួយផ្នែកដោយសារវាធ្វើឱ្យថ្លៃចំណាយជាបន្តបន្ទាប់អាចមើលឃើញ និងប្រៀបធៀបបាន ជាជាងលាក់ក្នុងតួលេខលទ្ធកម្មដើមទុនតែមួយ ដែលមើលទៅទាបគួរឱ្យទាក់ទាញនៅពេលអនុម័ត ហើយខុសថ្លៃនៅបីឆ្នាំក្រោយ។

## គណិតវិទ្យា

```
TCO = ថ្លៃចំណាយទិញ + Σ(t=1..N) ថ្លៃចំណាយប្រតិបត្តិការប្រចាំឆ្នាំ_t / (1+r)^t
      − តម្លៃសំណល់ (បញ្ចុះតម្លៃ)

r = អត្រាបញ្ចុះតម្លៃសង្គមស្តង់ដាររបស់ HM Treasury Green Book 3.5%/ឆ្នាំ
    (តារាងអត្រាថយចុះសម្រាប់ផ្តេកពេលវេលាលើស 30 ឆ្នាំ)

សមាសធាតុថ្លៃចំណាយប្រតិបត្តិការ៖ ការបង្ហោះ/អាជ្ញាប័ណ្ណ ការគាំទ្រ និងថែទាំ
សុវត្ថិភាព ការជួសជុល (patching) និងការអនុលោម ម៉ោងបុគ្គលិក ការធ្វើបច្ចុប្បន្នភាព/ការផ្លាស់ប្តូរដែលបានគ្រោងទុក
```

សូមមើល [អត្រាបញ្ចុះតម្លៃសង្គម](../អត្រាបញ្ចុះតម្លៃសង្គម/) ពីមូលហេតុដែលកត្តាបញ្ចុះតម្លៃមានសារៈសំខាន់ក្នុងអាយុកាលប្រព័ន្ធធម្មតា 5–10 ឆ្នាំ និង [ការសាងសង់ ធៀបនឹងការទិញក្នុងរដ្ឋាភិបាល](../ការសម្រេចចិត្តសាងសង់-ឬទិញក្នុងរដ្ឋាភិបាល/) ពីរបៀបដែល TCO បញ្ចូលទៅការសម្រេចចិត្តសាងសង់/ទិញ។

## ឧទាហរណ៍គណនា

ក្រសួងមួយប្រៀបធៀបប្រព័ន្ធគ្រប់គ្រងករណីពីរ ក្នុងផ្តេកពេលវេលា 5 ឆ្នាំ ក្នុងអត្រាបញ្ចុះតម្លៃ 3.5% របស់ Green Book។

```
ប្រព័ន្ធ A: capex £3,500,000, opex £250,000/ឆ្នាំ
ប្រព័ន្ធ B: capex £1,800,000 (មើលទៅថោកជាង), opex £650,000/ឆ្នាំ
          (បន្ទុកគាំទ្រអ្នកលក់ និងការរួមបញ្ចូលធ្ងន់ជាង)

ការប្រៀបធៀបឆោតល្ងង់លើ capex តែមួយ៖ B ឈ្នះ £1.8M < £3.5M។

ផលបូកកត្តាបញ្ចុះតម្លៃ 5 ឆ្នាំ ក្នុង 3.5%: 0.966+0.934+0.902+0.871+0.842 ≈ 4.515

TCO_A = 3,500,000 + 250,000 × 4.515 = 3,500,000 + 1,128,750 = £4,628,750
TCO_B = 1,800,000 + 650,000 × 4.515 = 1,800,000 + 2,934,750 = £4,734,750
```

TCO បង្វិលការសម្រេចចិត្តឆោតល្ងង់៖ ប្រព័ន្ធ B ថ្លៃជាងបន្តិចក្នុងរយៈពេលប្រាំឆ្នាំ នៅពេលថ្លៃចំណាយប្រតិបត្តិការត្រូវបានបញ្ចុះតម្លៃ និងបូកសរុប ពីព្រោះចំណែក opex នៃថ្លៃចំណាយពេញអាយុកាលរបស់វាគឺ 62% (2,934,750 / 4,734,750) ធៀបនឹង 24% របស់ប្រព័ន្ធ A ជាឧទាហរណ៍ជាក់ស្តែងនៃការរកឃើញ "ការថែទាំគឺជាភាគច្រើននៃវិក្កយបត្រ" ដែលលាក់ទាំងស្រុងដោយការប្រៀបធៀបតម្លៃស្ទីគ័រ។

## ទំនាក់ទំនងជាមួយវិស្វកម្មកម្មវិធី

TCO គឺជាលេខដែលគួរដាក់វិន័យលើរាល់ការសម្រេចចិត្ត[សាងសង់ ធៀបនឹងទិញ](../ការសម្រេចចិត្តសាងសង់-ឬទិញក្នុងរដ្ឋាភិបាល/) និងរាល់ករណីសង[បំណុលបច្ចេកទេស](../បំណុលបច្ចេកទេសជាការកាត់បន្ថយតម្លៃសាធារណៈ/) ពីព្រោះការប្រាក់បំណុល និងការថែទាំដែលពន្យារ គឺជាបន្ទាត់ថ្លៃចំណាយប្រតិបត្តិការទាំងពីរ ដែលជាកម្មសិទ្ធិនៃផលបូកបញ្ចុះតម្លៃដូចគ្នា ទោះបីជាគ្មាននរណាតាមដានវាក៏ដោយ។ វិស្វករដែលស្នើជម្រើសវេទិកា ឬអ្នកលក់គួរបង្ហាញតារាង TCO ពេញលេញ មិនមែនតម្លៃលទ្ធកម្មទេ ពីព្រោះតម្លៃលទ្ធកម្មគឺជាលេខដែលករណីហិរញ្ញវត្ថុរបស់ Green Book ត្រូវបានរចនាឡើងដើម្បីបញ្ឈប់ក្រសួងពីការពឹងផ្អែកតែមួយ។ TCO ក៏ជាភាគបែងស្មោះត្រង់សម្រាប់ការវិនិច្ឆ័យ[តម្លៃសមស្រប](../តម្លៃសមស្របនឹងថ្លៃចំណាយ/) ដែរ VFM ប្រៀបធៀបអត្ថប្រយោជន៍នឹងថ្លៃចំណាយ ហើយបន្ទាត់ថ្លៃចំណាយដែលរាប់តិចហួសបំផ្លើសរាល់សមាមាត្រ VFM ក្នុងករណីអាជីវកម្ម។

## កំហុសដែលតែងកើតមាន

- **ការប្រៀបធៀបតែ capex**៖ កំហុសលទ្ធកម្មទូទៅបំផុត គឺការប្រៀបធៀបតម្លៃបញ្ជីអ្នកផ្គត់ផ្គង់ ដោយគ្មានការព្យាករថ្លៃចំណាយប្រតិបត្តិការត្រូវគ្នាសម្រាប់ជម្រើសនីមួយៗ។
- **ការមិនរាប់ថ្លៃចំណាយចេញ និងផ្លាស់ប្តូរ**៖ ការទាញទិន្នន័យចេញនៅចុងកិច្ចសន្យា ការផ្លាស់ប្តូរវេទិកា និងការពិន័យចាក់សោអ្នកលក់ គឺជាបន្ទាត់ TCO ពិតប្រាកដ ដែលកម្រលេចក្នុងករណីអាជីវកម្មដើម។
- **ការមិនរាប់ថ្លៃចំណាយសុវត្ថិភាព និងអនុលោម**៖ ភាពញឹកញាប់នៃការជួសជុល ការបន្តការទទួលស្គាល់ និងថ្លៃសវនកម្មកើនឡើងតាមអាយុ និងភាពស្មុគស្មាញនៃប្រព័ន្ធ សូមមើល [តម្លៃនៃសន្តិសុខអ៊ីនធឺណិតក្នុងវិស័យសាធារណៈ](../តម្លៃនៃសន្តិសុខអ៊ីនធឺណិតក្នុងវិស័យសាធារណៈ/) ហើយត្រូវបានទុកចោលជាប្រចាំពីការព្យាករ opex។
- **ការប្រៀបធៀបដោយមិនបញ្ចុះតម្លៃឆ្លងកាត់ជម្រើសដែលមានទម្រង់ថ្លៃចំណាយខុសគ្នា**៖ ការប្រៀបធៀបជម្រើសដែលធ្ងន់ capex ជាមួយជម្រើសដែលធ្ងន់ opex ដោយគ្មានការបញ្ចុះតម្លៃ ពេញចិត្តជាប្រព័ន្ធចំពោះជម្រើសណាដែលអូសថ្លៃចំណាយទៅឆ្នាំក្រោយៗច្រើនជាង។
