# ໜີ້ທາງເທັກນິກໃນຖານະການກັດກ່ອນຄຸນຄ່າສາທາລະນະ

ໜີ້ທາງເທັກນິກ (technical debt) ແມ່ນຄຳອຸປະມາປີ 1992 ຂອງ Ward Cunningham ກ່ຽວກັບຕົ້ນທຶນໃນອະນາຄົດທີ່ແຝງຢູ່ຈາກການຕັດສິນໃຈຂຽນໂຄ້ດແບບທາງລັດໃນອະດີດ: **ເງິນຕົ້ນ** (principal — ງານແກ້ໄຂທີ່ຕິດໜີ້) ແລະ **ດອກເບ້ຍ** (interest — ແຮງຕ້ານຕໍ່ເນື່ອງທີ່ມັນສົ່ງຜົນຕໍ່ການສົ່ງມອບ). ໃນລະບົບ IT ເກົ່າຂອງລັດຖະບານ, ດອກເບ້ຍນັ້ນຖືກຈ່າຍອອກຈາກຄຸນຄ່າສາທາລະນະໂດຍກົງ — ການສົ່ງມອບການປ່ຽນແປງຕາມກົດໝາຍຊ້າລົງ, ອັດຕາຄວາມລົ້ມເຫຼວສູງຂຶ້ນໃນບໍລິການທີ່ປະເຊີນໜ້າກັບພົນລະເມືອງ, ແລະ ກຸ່ມຄົນທີ່ສາມາດແຕະຕ້ອງລະບົບຢ່າງປອດໄພຫຼຸດລົງ.

## ເປັນຫຍັງຈຶ່ງສຳຄັນ

ລະບົບ mainframe ແລະ ຍຸກ COBOL ເກົ່າໃນກະຊວງຕ່າງໆຂອງລັດຖະບານອັງກິດ — HMRC ແລະ DWP ເປັນສອງກໍລະນີທີ່ຖືກອ້າງເຖິງຫຼາຍທີ່ສຸດ — ມີຄວາມສ່ຽງທີ່ບັນທຶກໄວ້ດີ ແລະ ເພີ່ມຂຶ້ນ ເຊິ່ງສຳນັກງານກວດສອບແຫ່ງຊາດ (National Audit Office) ໄດ້ເຕືອນຊ້ຳແລ້ວຊ້ຳອີກ ລວມທັງໃນລາຍງານ *Digital Transformation in Government* (<https://www.nao.org.uk/>): ແພລດຟອມເກົ່າທີ່ແພງໃນການປ່ຽນແປງ, ຮັກສາຄວາມປອດໄພຍາກຂຶ້ນເລື້ອຍໆ, ແລະ ຂຶ້ນກັບບຸກຄະລາກອນຜູ້ຊ່ຽວຊານທີ່ກຳລັງອອກບຳນານໄວກວ່າທີ່ມີຄົນມາແທນ. ບໍ່ຄືກັບ backlog ໃນພາກເອກະຊົນ, ໜີ້ນີ້ຢູ່ລະຫວ່າງພົນລະເມືອງ ແລະ ສິດທິຕາມກົດໝາຍຂອງພວກເຂົາໂດຍກົງ — ເຄື່ອງຄິດໄລ່ເງິນສະຫວັດດີການທີ່ປ່ຽນແປງຢ່າງປອດໄພບໍ່ໄດ້ເປັນຂໍ້ຈຳກັດຂອງການສົ່ງມອບນະໂຍບາຍ, ບໍ່ແມ່ນພຽງຄວາມບໍ່ສະດວກທາງວິສະວະກຳ. ການເລີ່ມໃໝ່ໂຄງການ IT ຂອງ Universal Credit ປີ 2013, ເມື່ອສຳນັກງານກວດສອບແຫ່ງຊາດພົບວ່າການສ້າງຕົ້ນສະບັບຈະບໍ່ສົ່ງມອບຄວາມຄຸ້ມຄ່າເງິນ ແລະ ຊັບສິນຊອບແວສ່ວນໃຫຍ່ຕ້ອງຖືກຕັດບັນຊີ, ແມ່ນຕົວຢ່າງແບບຄລາດສິກຂອງໜີ້ທາງເທັກນິກທີ່ບໍ່ໄດ້ຕີລາຄາ ມາຕາມທວງໃນໂຄງການສາທາລະນະທີ່ດຳເນີນຢູ່ ແລະ ເຫັນໄດ້ຊັດຕໍ່ລັດຖະມົນຕີ.

## ຄະນິດສາດ

```
SQALE principal = Σ over violations (remediation time) × developer cost rate
Technical debt ratio (TDR) = remediation cost / redevelopment cost × 100
                    (SonarQube grades: A ≤5%, B ≤10%, C ≤20%, D ≤50%)

Interest (the number that justifies paydown):
  interest/year = Δ delivery velocity × value per unit velocity
                + Δ citizen-facing incident rate × cost per incident
                + specialist-skills premium × affected headcount
Paydown case = PV(interest avoided over horizon) − remediation cost
               (discounted at the Green Book social discount rate, see
               social-discount-rate.md)
```

ເງິນຕົ້ນລະບຸພາລະໜີ້ສິນ; ດອກເບ້ຍແມ່ນສິ່ງທີ່ສ້າງກໍລະນີການລົງທຶນຕໍ່ຄະນະກຳມະການບັນຊີສາທາລະນະ.

## ຕົວຢ່າງການຄິດໄລ່

ເຄື່ອງຈັກປະມວນຜົນການເຄລມ 250,000 ແຖວ ທີ່ຂຽນດ້ວຍ 4GL ເກົ່າ. ໃຊ້ມາດຕະຖານ CAST Appmarq ທີ່ປະມານ $3.61 ຂອງເງິນຕົ້ນໜີ້ທາງເທັກນິກຕໍ່ໜຶ່ງແຖວໂຄ້ດ (≈£2.85 ທີ່ອັດຕາແລກປ່ຽນທົ່ວໄປ):

```
Principal ≈ 250,000 × £2.85 ≈ £712,500
TDR ≈ 16% (grade C)
```

ດອກເບ້ຍທີ່ວັດໄດ້: ກະຊວງຈ້າງຜູ້ຮັບເໝົາຊ່ຽວຊານສາມຄົນໃນຄ່າຈ້າງລາຍວັນທີ່ສູງກວ່າອັດຕາວິສະວະກອນອາວຸໂສມາດຕະຖານ 40% ເພາະທັກສະພາຍໃນຫຼຸດຫາຍ — ເພີ່ມ £180,000/ປີ ໃນທີມຫົກຄົນ. ລະບົບຍັງເຮັດໃຫ້ເກີດການລະບົບຢຸດເຮັດວຽກໃຫຍ່ສີ່ຄັ້ງ/ປີ, ແຕ່ລະຄັ້ງໂຈະການຕັດສິນສຳລັບຜູ້ຮ້ອງຂໍປະມານ 5,000 ຄົນ ແລະ ປ່ຽນເສັ້ນທາງພວກເຂົາໄປສູນຕິດຕໍ່ໃນຕົ້ນທຶນປະມານ £25/ສາຍ:

```
Interest ≈ £180,000 (skills premium)
         + 4 × 5,000 × £25 = £500,000 (redirected-contact cost)
         ≈ £680,000/year
```

ການແກ້ໄຂແບບເຈາະຈົງສຳລັບໂມດູນທີ່ເຮັດວຽກແຍ່ທີ່ສຸດມີຕົ້ນທຶນ £1,200,000 ແລະ ຈຳລອງວ່າຫຼຸດດອກເບ້ຍລົງ 70%:

```
Interest reduction = 0.70 × 680,000 = £476,000/year
Payback ≈ 1,200,000 / 476,000 ≈ 2.5 years
```

ການເຈາະຈົງສຳຄັນ: ການແກ້ໄຂໂຄ້ດທີ່ແທບບໍ່ມີໃຜແຕະຕ້ອງບໍ່ໄດ້ຫຍັງ, ເພາະດອກເບ້ຍກະຈຸກຕົວຢູ່ບ່ອນທີ່ຄວາມຖີ່ຂອງການປ່ຽນແປງ ແລະ ຄວາມໜາແໜ້ນຂອງໜີ້ສູງສຸດທັງສອງຢ່າງ.

## ຄວາມເຊື່ອມໂຍງກັບວິສະວະກຳຊອບແວ

ກອບຄຸນຄ່າສາທາລະນະທີ່ຍົກລະດັບກໍລະນີໜີ້ທາງເທັກນິກຈາກ "ໂຄ້ດເກົ່າ": ສະແດງລະບົບເກົ່າເປັນບັນຊີລາຍການຂອງບ່ອນທີ່ຄວາມສາມາດໃນການສົ່ງມອບທີ່ສູນເສຍກະຈຸກຕົວຢູ່, ແລະ ເຊື່ອມໂຍງມັນຢ່າງຊັດເຈນກັບ[ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ](../ຕົ້ນທຶນການເປັນເຈົ້າຂອງທັງໝົດ-ໃນ-it-ຂອງລັດຖະບານ/), ເພາະດອກເບ້ຍເປັນຕົ້ນທຶນການດຳເນີນງານທີ່ຢູ່ໃນແຖວ TCO ບໍ່ວ່າຝ່າຍການເງິນຈະເຄີຍຖາມຫຼືບໍ່. ລະບົບທີ່ມີໜີ້ຫຼາຍຍັງມີຄວາມສ່ຽງ[ດ້ານຄວາມປອດໄພທາງໄຊເບີ](../ມູນຄ່າຂອງຄວາມປອດໄພທາງໄຊເບີໃນພາກລັດ/) ທີ່ບໍ່ສົມສ່ວນ, ເພາະຈັງຫວະການແພັດຊ໌ ແລະ ຄວາມໜາແໜ້ນຂອງໜີ້ມີສະຫະສຳພັນກັນ — ລະບົບເກົ່າທີ່ແພັດຊ໌ບໍ່ໄດ້ແມ່ນໜີ້ທາງເທັກນິກທີ່ດອກເບ້ຍຖືກຈ່າຍເປັນຄວາມສ່ຽງເຫດການ ແທນທີ່ຈະເປັນເງິນປອນ. ແລະ ທຸກການແລກປ່ຽນລະຫວ່າງການແກ້ໄຂກັບຄຸນສົມບັດໃໝ່ເປັນການຕັດສິນໃຈ[ຕົ້ນທຶນຂອງການຊັກຊ້າ](../ຕົ້ນທຶນຂອງການຊ້າໃນໂຄງການສາທາລະນະ/) ໃນຕົວມັນເອງ: ການຊຳລະໜີ້ເຮັດໃຫ້ການປ່ຽນແປງຕາມກົດໝາຍຄັ້ງຕໍ່ໄປຊັກຊ້າ, ເຊິ່ງມີ CoD ຂອງມັນເອງທີ່ຕ້ອງຊັ່ງນ້ຳໜັກກັບດອກເບ້ຍທີ່ປະຫຍັດໄດ້.

## ຂໍ້ຜິດພາດທີ່ພົບເລື້ອຍ

- **ການລາຍງານສະເພາະເງິນຕົ້ນ**: ປະມານການແກ້ໄຂທີ່ໃຫຍ່ ແລະ ໜ້າຢ້ານ ໂດຍບໍ່ມີຕົວເລກດອກເບ້ຍ ບໍ່ສາມາດໃຫ້ເຫດຜົນຫຍັງຕໍ່ຜູ້ອະນຸມັດການໃຊ້ຈ່າຍ.
- **ຖືຕົວເລກໜີ້ທີ່ເຄື່ອງມືສ້າງຕາມຕົວອັກສອນ**: ເຄື່ອງສະແກນແບບ SQALE ນັບການລະເມີດກົດ; ມັນພາດໜີ້ປະເພດທີ່ແພງ — ການຕັດສິນໃຈດ້ານສະຖາປັດຕະຍະກຳ ແລະ ກົດທຸລະກິດເກົ່າທີ່ບໍ່ມີເອກະສານ — ໃນຂະນະທີ່ຊີ້ເລື່ອງຈຸກຈິກ.
- **"ການຂຽນໃໝ່ຫຼີກລ່ຽງທຸກຢ່າງ"**: ໂຄງການທົດແທນຕ້ອງຜ່ານລະບຽບວິໄນດຽວກັນກັບແຜນທຸລະກິດອື່ນ — ຕົ້ນທຶນຕາມສະຖານະການສົມມຸດ (counterfactual), ຄວາມເປັນໄປໄດ້ຂອງຄວາມສຳເລັດ, ແລະ ການຄິດຫຼຸດ — ບໍ່ແມ່ນການຍົກເວັ້ນ, ດັ່ງທີ່ການເລີ່ມໃໝ່ Universal Credit ປີ 2013 ສະແດງໃຫ້ເຫັນ.
- **ອຸດົມການໜີ້ເປັນສູນ**: ລະດັບໜີ້ທີ່ເໝາະສົມບໍ່ແມ່ນສູນ; ໜີ້ແມ່ນອຳນາດຕໍ່ລອງທີ່ຊື້ການສົ່ງມອບໄວຂຶ້ນ. ຄຳຖາມທີ່ມີຊີວິດສະເໝີແມ່ນອັດຕາດອກເບ້ຍ, ບໍ່ແມ່ນວ່າມີໜີ້ຫຼືບໍ່.
