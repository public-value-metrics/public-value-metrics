# ಸಾರ್ವಜನಿಕ ವಲಯದ ಸೈಬರ್ ಭದ್ರತೆಯ ಮೌಲ್ಯ

ಸಾರ್ವಜನಿಕ ವಲಯದ ಸೈಬರ್ ಭದ್ರತೆಯ ಮೌಲ್ಯ ಎಂದರೆ ಅಪಾಯ ಕಡಿತಕ್ಕೆ ಬೆಲೆ ಕಟ್ಟುವ ಶಿಸ್ತು: ನಾಗರಿಕರ ಡೇಟಾ ಉಲ್ಲಂಘನೆಯ ಸಾಧ್ಯತೆಯನ್ನು ಕಡಿಮೆ ಮಾಡುವುದರ ಮೌಲ್ಯವೇನು? ಭದ್ರತಾ ಖರ್ಚು ಕೆಲಸ ಮಾಡಿದಾಗ ಯಾವುದೇ ಗೋಚರ
ಉತ್ಪನ್ನ ನೀಡುವುದಿಲ್ಲ, ವಿಫಲವಾದಾಗ ಬಹಳ ಗೋಚರ ಉತ್ಪನ್ನ ನೀಡುತ್ತದೆ. ಸೌಲಭ್ಯ ದಾಖಲೆಗಳು, ಆರೋಗ್ಯ ಡೇಟಾ ಅಥವಾ ತೆರಿಗೆ ದಾಖಲೆಗಳನ್ನು ಹೊಂದಿರುವ ಸೇವೆಗೆ, "ಕೆಲಸ ಮಾಡುವಾಗ ಅದೃಶ್ಯ" ಎಂಬ ಈ ಗುಣವೇ
ಅದಕ್ಕೆ ಕೇವಲ ಅನುಸರಣೆ ಟಿಕ್ ಅಲ್ಲ, ಸ್ಪಷ್ಟ ಮೌಲ್ಯದ ವಾದ ಬೇಕಾಗಿರುವುದಕ್ಕೆ ಕಾರಣ.

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಬ್ರಿಟನ್‌ನ National Cyber Security Centre ಯ Cyber Assessment Framework (CAF) ಸಾರ್ವಜನಿಕ ವಲಯದ ಸಂಸ್ಥೆಗಳಿಗೆ ಭದ್ರತೆಯನ್ನು ಪರಿಶೀಲನಾ ಪಟ್ಟಿಯ ಬದಲು ಮೌಲ್ಯಮಾಪನ ಮಾಡಬಹುದಾದ, ಫಲಿತಾಂಶ-ಆಧಾರಿತ ಶಿಸ್ತನ್ನಾಗಿ
ಮಾಡುವ ರಚನಾತ್ಮಕ ವಿಧಾನವನ್ನು ನೀಡುತ್ತದೆ: ಇದು ನಾಲ್ಕು ಉನ್ನತ ಮಟ್ಟದ ಉದ್ದೇಶಗಳನ್ನು ವ್ಯಾಖ್ಯಾನಿಸುತ್ತದೆ (ಭದ್ರತಾ ಅಪಾಯ ನಿರ್ವಹಣೆ, ಸೈಬರ್ ದಾಳಿಯಿಂದ ರಕ್ಷಣೆ, ಸೈಬರ್ ಭದ್ರತಾ ಘಟನೆಗಳ ಪತ್ತೆ, ಮತ್ತು ಘಟನೆಗಳ ಪರಿಣಾಮ ಕನಿಷ್ಠಗೊಳಿಸುವುದು),
ಇವನ್ನು ವ್ಯವಸ್ಥೆಯ ಮಾಲೀಕರನ್ನು ಮೌಲ್ಯಮಾಪನ ಮಾಡಬಹುದಾದ ಕೊಡುಗೆ ನೀಡುವ ಫಲಿತಾಂಶಗಳಾಗಿ ವಿಭಜಿಸಲಾಗಿದೆ; ಇದು [ಡಿಜಿಟಲ್ ಸೇವಾ ಮಾನದಂಡ](../ಡಿಜಿಟಲ್-ಸೇವಾ-ಮಾನದಂಡ/) ದ 9ನೇ ಅಂಶ ("ಬಳಕೆದಾರರ ಗೌಪ್ಯತೆಯನ್ನು ರಕ್ಷಿಸುವ ಸುರಕ್ಷಿತ ಸೇವೆಯನ್ನು ರಚಿಸಿ")
ದ ಅದೇ ಆಶಯದಲ್ಲಿದೆ. CAF ಮೌಲ್ಯಮಾಪನ ರಕ್ಷಿಸುವ ವಿಷಯಕ್ಕೆ ದಾಖಲಿತ ಬೆಲೆಪಟ್ಟಿ ಇದೆ: IBM ನ Cost of a Data Breach Report ವಲಯವಾರು ಸರಾಸರಿ ಉಲ್ಲಂಘನೆ ವೆಚ್ಚವನ್ನು ಹಿಂಬಾಲಿಸುತ್ತದೆ, ಮತ್ತು ಹಣಕಾಸು ಅಥವಾ ಆರೋಗ್ಯಕ್ಕೆ ಹೋಲಿಸಿದರೆ ಸಾರ್ವಜನಿಕ
ವಲಯ ಶ್ರೇಣಿಯ ಕೆಳ ತುದಿಯ ಕಡೆ ಇದೆ ಎಂದು ನಿರಂತರವಾಗಿ ಕಂಡುಕೊಂಡಿದೆ — ಇತ್ತೀಚಿನ ಆವೃತ್ತಿಗಳು ಸಾರ್ವಜನಿಕ ವಲಯದ ಸರಾಸರಿಯನ್ನು ಪ್ರತಿ ಉಲ್ಲಂಘನೆಗೆ ಸುಮಾರು $2.6–2.9 ಮಿಲಿಯನ್ ಎಂದು ನೀಡುತ್ತವೆ — ಆದರೆ
"ಹಣಕಾಸಿಗಿಂತ ಕಡಿಮೆ" ಎಂದರೆ "ಕಡಿಮೆ" ಅಲ್ಲ, ಮತ್ತು ಸರ್ಕಾರಿ ಉಲ್ಲಂಘನೆಗಳು ವರದಿಯ ಅಂಕಿಅಂಶಗಳು ಪೂರ್ಣವಾಗಿ ಹಿಡಿಯದ ವೆಚ್ಚಗಳನ್ನು ಹೊರುತ್ತವೆ: ಡಿಜಿಟಲ್ ಮಾರ್ಗಗಳಲ್ಲಿ ನಾಗರಿಕರ ವಿಶ್ವಾಸದ ನಷ್ಟ, ಇದು
ಮಾರ್ಗ-ಬದಲಾವಣೆ ವ್ಯವಹಾರ ಪ್ರಕರಣಗಳು ಅವಲಂಬಿಸಿರುವ [ಡಿಜಿಟಲ್ ಅಳವಡಿಕೆ](../ಚಾನೆಲ್-ಬದಲಾವಣೆಯ-ಉಳಿತಾಯ/) ಯನ್ನು ಕುಗ್ಗಿಸುತ್ತದೆ, ಮತ್ತು ಮೊದಲಿಗೆ ರಾಜ್ಯ ನಾಗರಿಕರನ್ನು ಒತ್ತಾಯಿಸಿ ಪಡೆದ ಡೇಟಾವನ್ನು ಬಹಿರಂಗಪಡಿಸಿದ ರಾಜಕೀಯ
ಮತ್ತು ಕಾನೂನು ವೆಚ್ಚ.

## ಗಣಿತ

ಭದ್ರತಾ ಹೂಡಿಕೆಗೆ ಮೌಲ್ಯ ಕಟ್ಟುವುದು ಯಾವುದೇ ಅಪಾಯ-ಕಡಿತ ಖರ್ಚಿಗೆ ಮೌಲ್ಯ ಕಟ್ಟುವಂತೆಯೇ: ಶ್ರೇಷ್ಠ ಅಪಾಯ-ನಿರ್ವಹಣಾ ಸಮೀಕರಣ ಬಳಸಿ, ನಿರೀಕ್ಷಿತ-ನಷ್ಟ ಕಡಿತವಾಗಿ.

```
Annualized Loss Expectancy (ALE) = Single Loss Expectancy (SLE)
                                  × Annualized Rate of Occurrence (ARO)

Value of a security control =
  ALE_before_control − ALE_after_control − annual cost of the control

A control is worth funding when:
  (ALE_before − ALE_after) > annual cost of the control

CAF assessment doesn't directly output a probability, but a service's
CAF outcome profile (which contributing outcomes are "achieved",
"partially achieved", or "not achieved") is a reasonable proxy input
to estimate ARO — a system with unmanaged privileged access or no
tested incident response plan has a materially higher realistic ARO
than one with both in place.
```

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

**40,000 ನಿವಾಸಿಗಳ ಸಾಮಾಜಿಕ ಆರೈಕೆ ದಾಖಲೆಗಳನ್ನು ಹೊಂದಿರುವ ಕೌಂಟಿ ಪರಿಷತ್ತಿನ ಪ್ರಕರಣ-ನಿರ್ವಹಣಾ ವ್ಯವಸ್ಥೆ**:

```
Single Loss Expectancy (breach cost), using a public-sector-sector
average from a recent IBM Cost of a Data Breach Report ≈ £2.1m
(converted, order-of-magnitude figure — always re-derive from the
current report edition rather than reusing a fixed number)

Current ARO (unmanaged privileged access, no tested incident
response, per an internal CAF self-assessment showing multiple
"not achieved" outcomes) ≈ estimated 8% per year
  ALE_before = £2.1m × 0.08 = £168,000/year

Proposed control: privileged access management + tested incident
response plan, moving the relevant CAF outcomes to "achieved",
estimated to cut ARO to 3%/year
  ALE_after = £2.1m × 0.03 = £63,000/year

Annual cost of the control (tooling + process + testing) = £45,000

Value of the control = (168,000 − 63,000) − 45,000 = £60,000/year
  net positive — fund it. The arithmetic also shows the control
  would still be worth funding at nearly triple the cost, which is
  the kind of sensitivity check that should accompany any ALE figure
  built on estimated probabilities.
```

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್ ಸಂಪರ್ಕ

ALE ಸಮೀಕರಣದ ಹೆಚ್ಚಿನ ನಿಯಂತ್ರಣ ಸನ್ನೆಕೋಲುಗಳು ಎಂಜಿನಿಯರ್‌ಗಳ ಬಳಿ ಇವೆ: ಪ್ರವೇಶ ನಿಯಂತ್ರಣ ವಿನ್ಯಾಸ, ಅವಲಂಬನೆ ಮತ್ತು ಪ್ಯಾಚ್ ಶುಚಿತ್ವ, ಲಾಗಿಂಗ್ ಮತ್ತು ಪತ್ತೆ ವ್ಯಾಪ್ತಿ, ಮತ್ತು ಘಟನೆ ಪ್ರತಿಕ್ರಿಯೆ ಸಾಧನಗಳು ARO ಪದವನ್ನು
ನೇರವಾಗಿ ಚಲಿಸುತ್ತವೆ; ಆದ್ದರಿಂದಲೇ CAF ಮೌಲ್ಯಮಾಪನ ನೀತಿ ಲೆಕ್ಕಪರಿಶೋಧನೆಯಷ್ಟೇ ತಾಂತ್ರಿಕ ವಾಸ್ತುಶಿಲ್ಪ ಪರಿಶೀಲನೆಯಂತೆ ಓದುತ್ತದೆ. ಇದು [ಸಾರ್ವಜನಿಕ ಮೌಲ್ಯ ಸವೆತವಾಗಿ ತಾಂತ್ರಿಕ ಸಾಲ](../ತಾಂತ್ರಿಕ-ಸಾಲ-ಸಾರ್ವಜನಿಕ-ಮೌಲ್ಯದ-ಸವೆತ/) ದ ಅತ್ಯಂತ ತೀವ್ರ ರೂಪ —
ಪ್ಯಾಚ್ ಮಾಡದ, ಮೇಲ್ವಿಚಾರಣೆಯಿಲ್ಲದ, ಕಳಪೆ ಪ್ರವೇಶ ನಿಯಂತ್ರಣದ ವ್ಯವಸ್ಥೆಗಳು ಸಾಲ, ಅದರ ಬಡ್ಡಿ ಸ್ಥಿರ ಹೊರೆಯಲ್ಲ ಬಾಲದ ಅಪಾಯ — ಮತ್ತು ಭದ್ರತಾ ಖರ್ಚು ವ್ಯವಸ್ಥೆಯ ನಿಜವಾದ ನಿರ್ವಹಣಾ ವೆಚ್ಚದಿಂದ ಪ್ರತ್ಯೇಕವೆಂದು ಪರಿಗಣಿಸದಂತೆ
[ಸರ್ಕಾರಿ IT ಯಲ್ಲಿ ಒಟ್ಟು ಮಾಲೀಕತ್ವ ವೆಚ್ಚ](../ಸರ್ಕಾರಿ-ಐಟಿಯಲ್ಲಿ-ಒಟ್ಟು-ಮಾಲೀಕತ್ವ-ವೆಚ್ಚ/) ದೊಂದಿಗೆ ಹೊಂದಿಸಬೇಕು. ಇದು Green Book ಅಡಿಯ [ಹಣಕ್ಕೆ ತಕ್ಕ ಮೌಲ್ಯ](../ಹಣಕ್ಕೆ-ತಕ್ಕ-ಮೌಲ್ಯ/) ಮೌಲ್ಯಮಾಪನಗಳಿಗೂ ನೇರ ಇನ್‌ಪುಟ್:
ಅಪಾಯ-ಹೊಂದಿಸಿದ ವೆಚ್ಚ ಯಾವುದೇ ಆಯ್ಕೆ ಮೌಲ್ಯಮಾಪನದ "ವೆಚ್ಚ" ಭಾಗದ ಅಂಶ, ಕೊನೆಯಲ್ಲಿ ಜೋಡಿಸುವ ನಂತರದ ಆಲೋಚನೆಯಲ್ಲ.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **CAF ಸ್ವಯಂ-ಮೌಲ್ಯಮಾಪನವನ್ನೇ ಭದ್ರತೆ ಎಂದು ಪರಿಗಣಿಸುವುದು**: ಪೂರ್ಣಗೊಂಡ ಮೌಲ್ಯಮಾಪನ ಭದ್ರತಾ ನಿಲುವನ್ನು ವಿವರಿಸುತ್ತದೆ; ಅದನ್ನು ಸೃಷ್ಟಿಸುವುದಿಲ್ಲ — ಮೌಲ್ಯ ಇರುವುದು ಸಾಧಿಸಿದ ಫಲಿತಾಂಶಗಳಲ್ಲಿ, ದಾಖಲೆಯಲ್ಲಿ ಅಲ್ಲ.
- **ಜಾಗತಿಕ ಸರಾಸರಿ ಉಲ್ಲಂಘನೆ ವೆಚ್ಚಗಳನ್ನು ಹೊಂದಾಣಿಕೆ ಇಲ್ಲದೆ ಸ್ಥಳೀಯ ಅಂದಾಜಾಗಿ ಬಳಸುವುದು**: IBM ನ ಅಂಕಿಅಂಶಗಳು ದೊಡ್ಡ, ವೈವಿಧ್ಯಮಯ ಮಾದರಿಗಳ ಸರಾಸರಿಗಳು; ಸಣ್ಣ ಸ್ಥಳೀಯ ಪ್ರಾಧಿಕಾರದ ವಾಸ್ತವಿಕ ಏಕ ನಷ್ಟ ನಿರೀಕ್ಷೆ
  ರಾಷ್ಟ್ರೀಯ ಸರ್ಕಾರಿ ಇಲಾಖೆಯದ್ದಕ್ಕೆ ವಿರಳವಾಗಿ ಸಮಾನ.
- **ಹೂಡಿಕೆ ನಿರ್ಧಾರಗಳಲ್ಲಿ ಬಾಲದ-ಅಪಾಯದ ಮನೋವಿಜ್ಞಾನವನ್ನು ನಿರ್ಲಕ್ಷಿಸುವುದು**: ಕಡಿಮೆ ವಾರ್ಷಿಕ ಸಂಭವನೀಯತೆ ಭದ್ರತಾ ಖರ್ಚನ್ನು ಅನಿರ್ದಿಷ್ಟವಾಗಿ ಮುಂದೂಡಲು ಸುಲಭಗೊಳಿಸುತ್ತದೆ, ಅದು ಸಂಭವಿಸುವ ವರ್ಷದವರೆಗೆ —
  ಉದಾಹರಣೆಯಲ್ಲಿರುವಂತೆ ALE ಲೆಕ್ಕಾಚಾರವನ್ನು ಹಲವು ARO ಗಳ ವ್ಯಾಪ್ತಿಯ ವಿರುದ್ಧ ಸಂವೇದನಾ-ಪರೀಕ್ಷೆ ಮಾಡುವುದು ಇದನ್ನು ಎದುರಿಸುತ್ತದೆ.
- **IBM-ಶೈಲಿಯ ಉಲ್ಲಂಘನೆ ವೆಚ್ಚವನ್ನು ಮಾತ್ರ ಎಣಿಸಿ, ವಿಶ್ವಾಸದ ವೆಚ್ಚವನ್ನು ಬಿಡುವುದು**: ಡಿಜಿಟಲ್ ಮಾರ್ಗಗಳನ್ನು ಬಳಸುವ ನಾಗರಿಕರ ಇಚ್ಛೆಯನ್ನು ಕುಗ್ಗಿಸುವ ಉಲ್ಲಂಘನೆ, ನಂತರದ ವರ್ಷಗಳ ಕಾಲ
  [ಮಾರ್ಗ-ಬದಲಾವಣೆ ಉಳಿತಾಯ](../ಚಾನೆಲ್-ಬದಲಾವಣೆಯ-ಉಳಿತಾಯ/) ಪ್ರಕರಣವನ್ನು ಸವೆಸುತ್ತದೆ; ಉಲ್ಲಂಘನೆ-ವೆಚ್ಚ ಅಂದಾಜುಗಳಲ್ಲಿ ಇದು ವಿರಳವಾಗಿ ಸೇರಿರುತ್ತದೆ.
