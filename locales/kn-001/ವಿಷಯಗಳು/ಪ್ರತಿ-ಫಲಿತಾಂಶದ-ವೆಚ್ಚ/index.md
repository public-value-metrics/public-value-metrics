# ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚ

ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚ (cost per outcome) ಎಂದರೆ ಕಾರ್ಯಕ್ರಮದ ಒಟ್ಟು ಖರ್ಚನ್ನು ತಮ್ಮ ಪರಿಸ್ಥಿತಿಗಳಲ್ಲಿ ವ್ಯಾಖ್ಯಾನಿತ, ಅರ್ಥಪೂರ್ಣ ಬದಲಾವಣೆ ಸಾಧಿಸಿದ ಜನರ ಸಂಖ್ಯೆಯಿಂದ ಭಾಗಿಸಿದ್ದು — ಕೇವಲ ಸೇವೆ ಪಡೆದವರ ಸಂಖ್ಯೆಯಲ್ಲ. ಹಣಕಾಸುದಾರ ಅಥವಾ ವಿತರಣಾ ತಂಡ ಬಳಸಬಹುದಾದ ಅತ್ಯಂತ ಹರಿತ ದಕ್ಷತೆಯ ಮಾಪನ ಇದು, ಏಕೆಂದರೆ ಹೆಚ್ಚಿನ ದತ್ತಿ ಸಂಸ್ಥೆಗಳು ತಪ್ಪಿಸಿಕೊಳ್ಳುವ ಪೂರ್ವ ಪ್ರಶ್ನೆಯನ್ನು ಇದು ಒತ್ತಾಯಿಸುತ್ತದೆ: ಯಶಸ್ಸು ಎಂದರೆ ನಿಖರವಾಗಿ ಏನು?

## ಇದು ಏಕೆ ಮುಖ್ಯ

ಆಹಾರ ಬ್ಯಾಂಕ್ ಒಂದು ವರ್ಷದ ಲೆಕ್ಕಪತ್ರಗಳಿಂದ ಎರಡು ಬಹಳ ಭಿನ್ನವಾದ ಸಂಖ್ಯೆಗಳನ್ನು ವರದಿ ಮಾಡಬಹುದು. ವಿತರಿಸಿದ ಪ್ರತಿ ಆಹಾರ ಪಾರ್ಸೆಲ್‌ಗೆ ವೆಚ್ಚ £15 ಇರಬಹುದು. ಆಹಾರ ಭದ್ರತೆ ಸಾಧಿಸುವ ಪ್ರತಿ ಮನೆಗೆ ವೆಚ್ಚ — ಇನ್ನು ತುರ್ತು ಆಹಾರ ನೆರವು ಬೇಕಿಲ್ಲ, ಅನುಸರಣಾ ಹಂತದಲ್ಲಿ ಪರಿಶೀಲಿಸಲಾಗಿದೆ — £340 ಇರಬಹುದು. ಎರಡೂ ನಿಜ. ಹಣ ಕೆಲಸ ಮಾಡುತ್ತಿದೆಯೇ ಎಂದು ಹಣಕಾಸುದಾರನಿಗೆ ಹೇಳುವುದು ಒಂದೇ. ಇವುಗಳ ನಡುವಿನ ಅಂತರವೇ ಉತ್ಪಾದನೆ ಮತ್ತು ಫಲಿತಾಂಶದ ನಡುವಿನ ಅಂತರ: ಹಸ್ತಾಂತರಿಸಿದ ಪಾರ್ಸೆಲ್ ಉತ್ಪಾದನೆ; ಇನ್ನು ಬಿಕ್ಕಟ್ಟಿನಲ್ಲಿಲ್ಲದ ಮನೆ ಫಲಿತಾಂಶ. [ಫಲಿತಾಂಶಗಳು ಮತ್ತು ಉತ್ಪಾದನೆಗಳು](../ಫಲಿತಾಂಶ-ಮತ್ತು-ಉತ್ಪನ್ನ/) ನೋಡಿ.

ಯುಕೆ ತೃತೀಯ ವಲಯವು ಈ ವ್ಯತ್ಯಾಸವನ್ನು ಒತ್ತಾಯಿಸುವ ಮೂಲಸೌಕರ್ಯ ನಿರ್ಮಿಸಲು ಎರಡು ದಶಕಗಳನ್ನು ಕಳೆದಿದೆ. New Philanthropy Capital ನ ದತ್ತಿ ಪರಿಣಾಮಕಾರಿತ್ವದ "ನಾಲ್ಕು ಸ್ತಂಭ ವಿಧಾನ" (four pillar approach) ಸಂಸ್ಥೆಗಳು ತಮ್ಮ ಉತ್ಪಾದನೆಗಳಿಗೂ ಮೊದಲು ತಮ್ಮ ಫಲಿತಾಂಶಗಳನ್ನು ಹೇಳಬೇಕೆಂದು ಸ್ಪಷ್ಟವಾಗಿ ಕೇಳುತ್ತದೆ, ಮತ್ತು ಯುಕೆ ಹಣಕಾಸುದಾರ-ಬೆಂಬಲಿತ ಪರಿಣಾಮ-ಮಾಪನ ಸಹಯೋಗವಾದ Inspiring Impact ಅನೇಕ ಅನುದಾನ ಅರ್ಜಿಗಳು ಈಗ ದತ್ತಿ ಸಂಸ್ಥೆಗಳು ಪೂರ್ಣಗೊಳಿಸಬೇಕೆಂದು ಅಗತ್ಯಪಡಿಸುವ Outcomes Matrix ಅನ್ನು ಪ್ರಕಟಿಸುತ್ತದೆ. Heriot-Watt University ಜೊತೆ ನಡೆಸುವ Trussell Trust ನ ವಾರ್ಷಿಕ "State of Hunger" ಸಂಶೋಧನಾ ಕಾರ್ಯಕ್ರಮವು ನಿಖರವಾಗಿ ಇದೇ ಕಾರಣಕ್ಕೆ ಅಸ್ತಿತ್ವದಲ್ಲಿದೆ: ಜನರು ಆಹಾರ ಅಭದ್ರತೆಯಿಂದ ಪಾರಾಗುತ್ತಾರೆಯೇ ಎಂಬುದರ ಬಗ್ಗೆ ಪಾರ್ಸೆಲ್ ಎಣಿಕೆಗಳು ಮಾತ್ರ ಏನನ್ನೂ ಹೇಳುವುದಿಲ್ಲ.

ಪ್ರತಿವಾಸ್ತವಿಕ ಸ್ಥಿತಿಯನ್ನು ನಿಗದಿಪಡಿಸಿದ ನಂತರವೇ ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚಕ್ಕೆ ಅರ್ಥವಿರುತ್ತದೆ: "ಹೇಗಾದರೂ" ಸಾಧಿಸಿದ ಫಲಿತಾಂಶವು ಕಾರ್ಯಕ್ರಮ ಖರೀದಿಸಿದ ಫಲಿತಾಂಶವಲ್ಲ. [ಪ್ರತಿವಾಸ್ತವಿಕ ವಿಶ್ಲೇಷಣೆ](../ಪ್ರತಿವಾಸ್ತವಿಕ-ವಿಶ್ಲೇಷಣೆ/) ಮತ್ತು [ಸ್ಥಳಾಂತರ ಮತ್ತು ಕಾರಣಾರೋಪಣೆ](../ಸ್ಥಳಾಂತರ-ಮತ್ತು-ಕಾರಣ-ನಿರ್ಣಯ/) ನೋಡಿ.

## ಗಣಿತ

```
ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚ = ಕಾರ್ಯಕ್ರಮದ ಒಟ್ಟು ವೆಚ್ಚ / ವ್ಯಾಖ್ಯಾನಿತ ಫಲಿತಾಂಶ ಸಾಧಿಸಿದ ಫಲಾನುಭವಿಗಳ ಸಂಖ್ಯೆ

ಇಲ್ಲಿ:
  ಕಾರ್ಯಕ್ರಮದ ಒಟ್ಟು ವೆಚ್ಚ = ನೇರ ವಿತರಣಾ ವೆಚ್ಚ + ಓವರ್‌ಹೆಡ್‌ನ ನ್ಯಾಯಸಮ್ಮತ ಪಾಲು
  ವ್ಯಾಖ್ಯಾನಿತ ಫಲಿತಾಂಶ   = ಮೊದಲೇ ನಿರ್ದಿಷ್ಟಪಡಿಸಿದ, ಅಳೆಯಬಹುದಾದ ಸ್ಥಿತಿ ಬದಲಾವಣೆ
                            (ಉದಾ. "6-ತಿಂಗಳ ಅನುಸರಣೆಯಲ್ಲಿ ಆಹಾರ ಭದ್ರತೆ",
                            "ಆಹಾರ ಪಾರ್ಸೆಲ್ ಪಡೆದರು" ಅಲ್ಲ)
```

ನಿರ್ದಿಷ್ಟ ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚ ಉತ್ತಮ, ಸರಾಸರಿ ಅಥವಾ ಕಳಪೆಯೇ ಎಂದು ಹೋಲಿಸಬಹುದಾದ ಮಧ್ಯಸ್ಥಿಕೆಗಳಿಗೆ ಹೋಲಿಸಿ ನಿರ್ಣಯಿಸಲು [ಘಟಕ ವೆಚ್ಚ ದತ್ತಾಂಶ ಸಂಗ್ರಹಗಳು](../ಘಟಕ-ವೆಚ್ಚ-ದತ್ತಾಂಶ-ಸಂಗ್ರಹಗಳು/) (ಉದಾ. ವಲಯ-ನಿರ್ದಿಷ್ಟ ಘಟಕ ವೆಚ್ಚ ಮಾನದಂಡಗಳು) ಗೆ ಹೋಲಿಸಿ.

## ಬಿಡಿಸಿದ ಉದಾಹರಣೆ

**ಆಹಾರ ಬ್ಯಾಂಕ್, ಒಂದು ವರ್ಷ**:

- ಕಾರ್ಯಕ್ರಮದ ಒಟ್ಟು ವೆಚ್ಚ: £450,000
- ವಿತರಿಸಿದ ಪಾರ್ಸೆಲ್‌ಗಳು: 30,000
- ಪ್ರತಿ ಪಾರ್ಸೆಲ್ ವೆಚ್ಚ (ಉತ್ಪಾದನಾ ಮಾಪನ): £450,000 / 30,000 = **£15**

ದತ್ತಿ ಸಂಸ್ಥೆಯು ಮನೆಗಳ ಮಾದರಿಯೊಂದಿಗೆ ಆರು-ತಿಂಗಳ ಅನುಸರಣಾ ಸಮೀಕ್ಷೆಯನ್ನೂ ನಡೆಸುತ್ತದೆ; ಮೂರು ಅಥವಾ ಹೆಚ್ಚು ಪಾರ್ಸೆಲ್‌ಗಳನ್ನು ಪಡೆದ ಮನೆಗಳಲ್ಲಿ 35% ಇನ್ನು ತುರ್ತು ಆಹಾರ ನೆರವು ಬೇಕಿಲ್ಲ ಎಂದು ವರದಿ ಮಾಡುತ್ತವೆ ಮತ್ತು ಪ್ರಮಾಣಿತ ಆಹಾರ-ಭದ್ರತೆ ಸಮೀಕ್ಷೆ ಮಾಡ್ಯೂಲ್‌ನಲ್ಲಿ ಆಹಾರ-ಭದ್ರತೆ ಮಿತಿಗಿಂತ ಮೇಲೆ ಅಂಕ ಗಳಿಸುತ್ತವೆ ಎಂದು ಕಂಡುಕೊಳ್ಳುತ್ತದೆ. ಆ ವರ್ಷ ಮೂರು-ಮತ್ತು-ಹೆಚ್ಚು ಪಾರ್ಸೆಲ್ ಪಡೆದ 1,800 ಮನೆಗಳಲ್ಲಿ, 630 ಆ ಫಲಿತಾಂಶ ಸಾಧಿಸುತ್ತವೆ.

```
ಪ್ರತಿ ಫಲಿತಾಂಶದ ವೆಚ್ಚ = £450,000 / 630 = ಆಹಾರ ಭದ್ರತೆ ಸಾಧಿಸಿದ ಪ್ರತಿ ಮನೆಗೆ £714
```

ಈ ದತ್ತಿ ಸಂಸ್ಥೆಯನ್ನು ನಗದು-ವರ್ಗಾವಣೆ ಪೈಲಟ್ ಅಥವಾ ಸಾಲ-ಸಲಹೆ ಸೇವೆಗೆ ಹೋಲಿಸುವ ಹಣಕಾಸುದಾರ ಬಳಸಬೇಕಾದದ್ದು ಈ £714 ಅಂಕಿ — £15 ಅಲ್ಲ. ಅದೇ ಪ್ರದೇಶದ ಹೋಲಿಸಬಹುದಾದ ನಗದು-ವರ್ಗಾವಣೆ ಕಾರ್ಯಕ್ರಮವು ಪ್ರತಿ ಮನೆಗೆ £500 ಕ್ಕೆ ಆಹಾರ ಭದ್ರತೆ ಸಾಧಿಸಿದರೆ, ಪ್ರತಿ-ಪಾರ್ಸೆಲ್ ವೆಚ್ಚ ಅಗ್ಗವಾಗಿ ಕಂಡರೂ ಅದೇ ಫಲಿತಾಂಶಕ್ಕೆ ಆಹಾರ ಬ್ಯಾಂಕ್ ಹೆಚ್ಚು ದಕ್ಷ ಮಾರ್ಗವೆಂದು ಸ್ಪಷ್ಟವಾಗಿ ಹೇಳಲಾಗದು.

## ಸಾಫ್ಟ್‌ವೇರ್ ಎಂಜಿನಿಯರಿಂಗ್ ಸಂಪರ್ಕ

ಹೆಚ್ಚಿನ ಪ್ರಕರಣ-ನಿರ್ವಹಣಾ ವ್ಯವಸ್ಥೆಗಳನ್ನು ಉತ್ಪಾದನೆಗಳನ್ನು ಲಾಗ್ ಮಾಡಲು ನಿರ್ಮಿಸಲಾಗಿದೆ, ಏಕೆಂದರೆ ವ್ಯವಹಾರದೊಳಗೆ ಸಂಭವಿಸುವುದು ಉತ್ಪಾದನೆಗಳು (ಪಾರ್ಸೆಲ್ ಹಸ್ತಾಂತರವಾಗುತ್ತದೆ, ಫಾರ್ಮ್ ಸಲ್ಲಿಕೆಯಾಗುತ್ತದೆ). ಫಲಿತಾಂಶಗಳು ಸಾಮಾನ್ಯವಾಗಿ ನಂತರ, ಆಗಾಗ್ಗೆ ವ್ಯವಸ್ಥೆಯ ಸಾಮಾನ್ಯ ಸೆರೆಹಿಡಿಯುವ ಕಿಟಕಿಯ ಹೊರಗೆ ಸಂಭವಿಸುತ್ತವೆ, ಮತ್ತು ಉದ್ದೇಶಪೂರ್ವಕ ವಿನ್ಯಾಸ ನಿರ್ಧಾರ ಬೇಕು: ಅನುಸರಣಾ ವ್ಯವಸ್ಥೆಯನ್ನು (ಸಮೀಕ್ಷೆ ಪ್ರಚೋದಕ, ಮರು-ಸಂಪರ್ಕ ಕಾರ್ಯಪ್ರವಾಹ, ದತ್ತಾಂಶ-ಸಂಪರ್ಕ ಅಭ್ಯಾಸ) ವಾರ್ಷಿಕ ವರದಿಗಾಗಿ ಅಂಟಿಸಿದ ನಂತರದ ಯೋಚನೆಯಾಗಿ ಅಲ್ಲ, ಪ್ರಥಮ-ದರ್ಜೆ ವೈಶಿಷ್ಟ್ಯವಾಗಿ ನಿರ್ಮಿಸಿ. ವಲಯಕ್ಕಾಗಿ ಅನುದಾನ ನಿರ್ವಹಣೆ ಅಥವಾ ಪ್ರಕರಣ ನಿರ್ವಹಣಾ ವೇದಿಕೆಗಳನ್ನು ನಿರ್ಮಿಸುವ ಎಂಜಿನಿಯರ್‌ಗಳು "ಫಲಿತಾಂಶ ಘಟನೆ ಯಾವುದು, ಮತ್ತು ಅದನ್ನು ಹೇಗೆ ಗಮನಿಸುತ್ತೇವೆ" ಎಂಬುದನ್ನು ದತ್ತಾಂಶ ಮಾದರಿ ನಿಗದಿಯಾಗುವ ಮೊದಲು ಕೇಳುವ ಅಗತ್ಯದ ಪ್ರಶ್ನೆಯಾಗಿ ಪರಿಗಣಿಸಬೇಕು — ಉತ್ಪಾದನಾ ಕೌಂಟರ್‌ಗಿಂತ ಫಲಿತಾಂಶ ಕ್ಷೇತ್ರವನ್ನು ನಂತರ ಸೇರಿಸುವುದು ಬಹಳ ಕಷ್ಟ. ಆ ಅಗತ್ಯಗಳ ಸಂಭಾಷಣೆಯನ್ನು ಹೇಗೆ ರಚಿಸುವುದೆಂದು [ಫಲಿತಾಂಶಗಳು ಮತ್ತು ಉತ್ಪಾದನೆಗಳು](../ಫಲಿತಾಂಶ-ಮತ್ತು-ಉತ್ಪನ್ನ/) ಮತ್ತು [ತರ್ಕ ಮಾದರಿ](../ತಾರ್ಕಿಕ-ಮಾದರಿ/), ಮತ್ತು ಫಲಿತಾಂಶ ಹಿಂಬಾಲಿಕೆ ಇನ್ನೂ ನಿರ್ಮಾಣವಾಗಿಲ್ಲದಿದ್ದಾಗ ತಂಡಗಳು ಹುಡುಕುವ ವೇಗದ, ಒರಟು ಮಾಪನಕ್ಕಾಗಿ [ಪ್ರತಿ ಫಲಾನುಭವಿಯ ವೆಚ್ಚ](../ಪ್ರತಿ-ಫಲಾನುಭವಿಯ-ವೆಚ್ಚ/) ನೋಡಿ.

## ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

- **ಉತ್ಪಾದನೆಗಳನ್ನು ಫಲಿತಾಂಶಗಳ ವೇಷದಲ್ಲಿ ವರದಿ ಮಾಡುವುದು.** "ತಲುಪಿದ ಜನರು" ಎಂದರೆ "ಸಹಾಯ ಪಡೆದ ಜನರು" ಅಲ್ಲ. ಮಾಪನವನ್ನು ಅನುಸರಣಾ ಸಂಪರ್ಕವಿಲ್ಲದೆ ವ್ಯವಸ್ಥೆಯ ಲಾಗ್‌ನಿಂದ ತಯಾರಿಸಬಹುದಾದರೆ, ಅದು ಬಹುತೇಕ ಖಚಿತವಾಗಿ ಉತ್ಪಾದನೆ.
- **ಛೇದ ತಿರುಚುವಿಕೆ.** ಫಲಿತಾಂಶ ಜನಸಂಖ್ಯೆಯನ್ನು "ಕಾರ್ಯಕ್ರಮ ಪೂರ್ಣಗೊಳಿಸಿದವರು" ಎಂದು ಸಂಕುಚಿತಗೊಳಿಸುವುದು ಬಿಟ್ಟುಹೋದವರನ್ನು — ಆಗಾಗ್ಗೆ ಅತ್ಯಂತ ಕಷ್ಟಕರ ಪ್ರಕರಣಗಳು — ಸದ್ದಿಲ್ಲದೆ ಕೈಬಿಟ್ಟು, ತೋರಿಕೆಯ ದರವನ್ನು ಉಬ್ಬಿಸುತ್ತದೆ. ಛೇದವನ್ನು ಮುಗಿಸಿದ ಎಲ್ಲರಲ್ಲ, ಆರಂಭಿಸಿದ ಎಲ್ಲರೆಂದು ಹೇಳಿ.
- **ಪ್ರತಿವಾಸ್ತವಿಕ ಸ್ಥಿತಿ ಇಲ್ಲದಿರುವುದು.** ಹೇಗಾದರೂ ಸಾಧಿಸುತ್ತಿದ್ದವರನ್ನು ಸೇರಿಸಿ ಫಲಿತಾಂಶ ಸಾಧಿಸಿದ ಎಲ್ಲರನ್ನೂ ಎಣಿಸುವುದು ಕಾರ್ಯಕ್ರಮ ಖರೀದಿಸಿದ್ದನ್ನು ಅತಿಯಾಗಿ ಹೇಳುತ್ತದೆ. [ಪ್ರತಿವಾಸ್ತವಿಕ ವಿಶ್ಲೇಷಣೆ](../ಪ್ರತಿವಾಸ್ತವಿಕ-ವಿಶ್ಲೇಷಣೆ/) ನೋಡಿ.
- **ಹೊಂದಿಕೆಯಾಗದ ಫಲಿತಾಂಶ ವ್ಯಾಖ್ಯಾನಗಳಾದ್ಯಂತ ಹೋಲಿಸುವುದು.** ಮಾನ್ಯ ಸಮೀಕ್ಷೆ ಮಾಡ್ಯೂಲ್‌ನಿಂದ ಅಳೆದ "ಆಹಾರ ಭದ್ರತೆ"ಯನ್ನು ತೃಪ್ತಿ ಫಾರ್ಮ್‌ನಲ್ಲಿ ಸ್ವಯಂ-ವರದಿ ಮಾಡಿದ "ಆಹಾರ ಭದ್ರತೆ"ಗೆ ಹೋಲಿಸಲಾಗದು; ಫಲಿತಾಂಶ ವ್ಯಾಖ್ಯಾನಗಳು ಹೊಂದಿಕೆಯಾದಾಗ ಮಾತ್ರ ಪ್ರತಿ-ಫಲಿತಾಂಶ-ವೆಚ್ಚ ಲೀಗ್ ಟೇಬಲ್ ಪ್ರಾಮಾಣಿಕ.
